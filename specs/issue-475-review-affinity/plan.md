# #475 — bounded source repair design

**Identity:** Aether Project `12027989-a08f-41cd-a82c-54ff1bfb6b03`; owning Issue #475. Source bases and inspected lines: `spec.md` and `research.md`. This is a technical design for a source-only correction, not a finalized Objective Contract or permission to touch the installed runtime.

## Shared boundary and decisions

The only new path is at a claimed **review** run of a direct-affinity Supervisor card. Qualify it with the latest matching `review_requested` transition: original assignee is the Supervisor profile, current assignee is a different reviewer, and the claimed run has review provenance. Corroborate a unique Aether opt-in root and exact native Project/portable Project/contract/board identity using the existing FR-737c standard; board name alone is insufficient. The card's normalized direct flow must be the original Supervisor flow. Look up its exact registered original-profile row/session/workspace without creating or changing a row; require the row's workspace to match this card's canonical flow workspace, and respect any live owner/lease or superseded-worker hold. Missing, ambiguous, malformed or contradictory ancestry, event, row, session or workspace is an ordinary diagnosed lifecycle failure, **not** a fresh fallback. The reviewer must be independent per the existing review event and task state. Preserve the original `terminal` value on the durable card.

For a valid case, keep `session_affinity`, skills and model/provider/reasoning fields unchanged **on disk**; launch this reviewer under its own profile in the *same candidate task/worktree* without the original session ID, resume flag, lease token/generation, flow selector, Supervisor-pinned skills or overrides. Do not reserve/create a reviewer-affinity row or use a Supervisor session-workspace override. Existing review-procedure policy may supply the reviewer's own procedure, but must not import Supervisor-phase pins. A fresh reviewer must still be able to read the same card/evidence, issue a verdict in its claimed run and, on `request_changes`, return the card to the Supervisor. The ready lane then uses the untouched Supervisor row/session. A second independent review on the same card must qualify again; approval must respect terminal-bit/dependency semantics.

Local method remains Implementer judgement: reuse/refactor the existing provenance helper or make a small purpose-built read-only validation in the dispatcher; choose internal function names, event parsing, and tests without weakening the above gate. Supervisor decides task split, integration and independent review, not shared identity/fencing semantics. Owner-reserved: permission for runtime activation, framework authority changes, credential work or broad fallback; none is granted here. No new schema, migration or role authority is designed.
