## Observed behavior (not an accepted remedy)

- `request_review:8928-9115` changes the card assignee from Supervisor to distinct reviewer, ends the Supervisor run, and persists `review_requested` with both identities. It preserves `session_affinity` on the card. `_end_run:6392-6460` clears the lease owner/token but retains the exact registered Supervisor session and row for rework.
- The review dispatcher `dispatch_once:12949-13115` claims a review run, then selects `reserve_session_affinity` when the claimed card has direct affinity. Its key is `(board, project_id, flow_id, current assignee)` (`:1512-1629`). With the new reviewer as assignee, the original Supervisor row is not found; `:1548-1564` rejects a missing row after a prior run with the exact reported `session affinity lease is missing or stale`. No elapsed-time check occurs in that branch.
- `_review_flow_session_context:1323-1475` validates opt-in, exact contract/board/native-and-portable Project identity, a unique collaboration root, same-profile ancestor and existing session/workspace; `_reserve_review_flow_session:1478-1509` reserves the *reviewer's* existing session only for an implementation card **without** direct affinity. That path cannot simply be applied to this Supervisor card: its reviewer is a different profile, and `:1342-1345` skips direct-affinity cards. Removing direct affinity from the durable card would also break Supervisor continuation and its terminal bit.
- `_default_spawn:13422-13635` selects `-p` from the claimed reviewer assignee, uses that profile's `HERMES_HOME`, and emits `--resume` plus affinity env/token only when an `AffinityLease` is passed. Its normal no-affinity path can launch a fresh reviewer without transfer or resume. However `dispatch_once:13077-13091` currently suppresses card-pinned skills/model/provider/reasoning only for a **derived same-profile** reviewer; any new cross-profile fresh path must suppress original Supervisor overrides just for that subprocess, while preserving persisted fields for rework. Review procedure selection may follow the existing reviewer policy; it must not load a Supervisor-only pin. Also check inherited affinity/flow routing variables in the subprocess env, not just the `--resume` argument, before claiming isolation.
- `register_session_affinity:1633-1687` fences by profile, project, flow, generation, token and claimed run. A direct lease under the reviewer identity, a new row after loss of the original row, or transfer of the Supervisor's token/session is not equivalent to fresh independent review. `request_changes:9118-9245` restores the original assignee from the durable latest review event and reapplies parent gating. `claim_review_task:7117-7205` checks reviewer independence but does not resolve this affinity conflict.
- Existing tests `test_kanban_session_affinity.py:295-404,407-563,1051-1091,1942-1960` cover same-profile unit review, review/rework and deleted affinity rows in other topologies, not independent review of a directly affinity-bound Supervisor card. `specs/r7-supervision-and-convergence/spec.md:159-171` FR-735a/737c requires the former behavior to remain, including fail-closed Aether identity; FR-737a requires the verdict in a claimed review run.

## Material choice and feasibility limit

**Decided (delegated technical choice):** a narrow fresh *review-run* exception for an affinity-bound Aether Supervisor integration card, only after the existing provenance can be corroborated and the original Supervisor binding is intact. This is a launch choice, not a card migration: no reviewer lease, no rewriting of card affinity/configuration, no generic fallback on `AffinityRegistrationError`. On return, the ordinary ready lane reserves the original Supervisor binding. A reviewer launch must not race a live original-flow owner; preserve existing defer/fencing behavior. `plan.md` states the shared checks and expected evidence, not a mandatory helper layout.

**Feasibility supported, not yet behaviorally proven:** the existing dispatch paths and `_default_spawn` admit a no-affinity subprocess under a distinct profile, and the durable return path retains the original binding. An isolated RED demonstrates the starting defect. No GREEN/re-review or actual independent reviewer verdict was run at this design checkpoint. A fake-spawn test can verify launch parameters, identity and state; it cannot prove agent obedience. Stop if exact source/provenance checks cannot distinguish valid review from genuine row loss or if the only remedy crosses the session/profile fence.

**Rejected:** wait/retry for TTL (no elapsed-time test in the failing branch); wipe `session_affinity` on `request_review` (loses rework continuity/terminal signal); transfer/copy the Supervisor session or create a reviewer lease (violates profile fencing); catch any affinity failure and fall back to fresh (masks damaged Aether identity). The current issue text's “renew/transfer” wording is an unverified hypothesis, not an authority to transfer. No new Spec Kit adaptation is required.
