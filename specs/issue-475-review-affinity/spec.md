# Issue #475 — same-card cross-profile review on an affinity-bound integration card

**Status:** design draft; no Objective Contract finalized or implementation authorized by this file.
**Owner objective:** existing-bug repair program; [issue #475](https://github.com/DarkArty07/Aether-Agents/issues/475).
**Inspected bases:** Aether `6e29204ac575bea014fe84fd0a65d6641e5e1973`; maintained Hermes fork `30b4846a2c8063528d491f48950b3b341b0ce7d7` (remote `aether-main`, verified before drafting). These are design evidence, not installed-runtime claims.
**Related authority:** `DESIGN.md`; `specs/r7-supervision-and-convergence/spec.md` FR-734–737c; `AGENTS.md`. The issue's long-CI hypothesis was narrowed by an isolated immediate RED at the same fork revision: the error arises from a review-time profile switch while `session_affinity` still names the integration card's Supervisor flow, not from a demonstrated lease timeout. The reproducibility record and source analysis remain in the ignored program Objective Plan; this draft does not claim a fixed behavior.

## Outcome and boundary

A Supervisor integration card in an explicitly verified Aether flow retains its own session affinity across normal integration and rework. When that **same card** requests independent review from another profile, the review run starts with a valid fresh reviewer session, preserved candidate and task history, and no Supervisor session/lease/configuration leakage. A successful review or a bounded return reaches the existing Kanban lifecycle instead of a `spawn_failed` caused solely by the assignee switch. The second review after rework must remain possible. This is distinct from Implementer-unit review by Supervisor, whose already accepted same-profile session continuity must remain intact.

The scoped change is a maintained-fork source repair with Aether-side portable source/evidence reconciliation and normal reviewed GitHub closeout. It does **not** activate the new fork in the live runtime, restart the gateway, create an RC/tag, deploy manually, publish a package, edit a native board to cure a failed flow, change review authority, or waive review/CI gates. The historical failed card remains evidence, not a target for mutation.

## Observable requirements

- **475-01 — valid independent review launch.** Given an Aether collaboration root and exact contract/Project/board provenance, a Supervisor integration card with direct flow affinity and an existing registered Supervisor session, and its durable current `review_requested` event assigning a distinct reviewer profile, dispatch of the claimed review run starts that reviewer under *its own* profile in a fresh session against the same candidate worktree/task context. It must not attempt to reserve the Supervisor affinity row under the new assignee, inherit the Supervisor session/token, or silently replace the persisted card's affinity. The independent reviewer must be able to issue a verdict in the claimed review run. A fake-spawn fixture may prove launch parameters/lifecycle but cannot prove agent behavior.
- **475-02 — rework and repeat.** If the reviewer returns actionable changes, the existing same-card return path restores the original Supervisor phase and its exact registered session/affinity without a fresh fallback or a transferred reviewer lease. After that rework, a new independent review launch works on the same card. A successful verdict preserves the flow's original terminal bit and downstream dependency behavior. Tests inspect both cycles, not just the first spawn.
- **475-03 — fail closed on damaged Aether identity.** If the qualifying review event, exact project/contract/board opt-in, original profile/flow ancestry, original affinity row, or its registered Supervisor session is missing, ambiguous or contradictory, dispatch reports the existing lifecycle failure without creating a new lease or session to make a damaged flow appear healthy. A truly lost original affinity row must not be treated as the valid cross-profile case; no transfer of session, token or lease across profiles is permitted.
- **475-04 — preserve existing review classes.** Implementer-unit same-card review by Supervisor in a verified opted-in Aether flow still resumes the existing Supervisor session per FR-735a/737c, with its ephemeral review lease and Implementer-phase card config preserved. Generic Hermes review outside a verified Aether root keeps its prior fresh/bundled behavior. A board name by itself never opts a task in. No new blanket fresh fallback for an affinity error is allowed.
- **475-05 — evidence and source-only closeout.** The original immediate RED, successful scoped GREEN/negative cases, affected fork regression suite, and Aether exact-Hermes integration gates are attributable to their actual source revisions. A portable Aether-side source/evidence artifact reconciles the accepted fork commit; normal protected PR gates and merge state are inspected before any issue closure. An untested or unapplied installed runtime is labeled as such, and closing #475 must not imply live adoption.

## Verification and stop conditions

The repository testing standard is `CONTRIBUTING.md` §§ Test with the locked Hermes baseline / Quality checks: hermetic isolated Kanban state including `HERMES_KANBAN_*`, focused iteration, full exact-Hermes bootstrap before handoff, applicable Python quality gates, and fork tests at the exact reviewed fork revision. Worker design must identify the decisive fake-spawn RED/GREEN, negative row-loss/identity cases, return/re-review and original terminal bit, plus non-regression of unit review and generic Hermes. No browser test, live gateway call, or activation is part of this source-only repair. The test fixture's outer board must be checked unchanged.

Stop for a design decision rather than weakening this draft if the only feasible remedy transfers a Supervisor session/token between profiles, creates a new lease after a genuine original-row loss, relaxes FR-735a/737c, or requires a protected live effect. Reinspect and replan if the fork base or competing PR changes before the contract is finalized; an old test is not proof for a later revision. Local implementation details remain Implementer judgment once the shared identity, error and configuration boundaries are met; Supervisor owns decomposition/integration and independent review.
