## 2. Baseline finding and technical judgement

The unchanged baseline's search behavior is correct for this acceptance: context is
returned when requested, and the projection excluding `context` does not enrich rows.
The test's trace setup was not connected to the current read-path implementation.

Before the read-connection pool, the test's preselection of `db._get_read_conn()` was
sufficient to identify the per-thread read connection. On the maintained baseline,
`_get_read_conn()` now opens a fresh connection, while `_read_ctx()` calls
`_checkout_read_conn()` and can open or borrow a different connection. The test therefore
installed callbacks on the writer and a preselected, unpooled read connection, but the
context query ran on the connection actually returned by `_checkout_read_conn()`. The
returned context was non-empty even though the test observed zero traced context queries.
The preselected connection also did not satisfy the current helper's caller contract and
was not needed for the search.

This is a trace/test connection mismatch, not evidence that the product skipped context
enrichment. The local choice was therefore to repair the test at the existing checkout
seam rather than alter production connection pooling or search behavior. No coverage is
hidden: the same test continues to assert the projected result, the context-bearing
result, the legacy default result, non-empty contexts, and exact enrichment counts of
`0`, `1`, and `2` respectively.

## 3. Candidate change

`tests/test_hermes_state.py:822-866` now wraps the instance's existing
`_checkout_read_conn()` helper for the duration of the test. The wrapper:

1. delegates to the real checkout implementation;
2. attaches the trace callback to the returned read connection, or to the writer
   connection when the read path deliberately falls back;
3. records each actual connection once, so pooled reuse remains observable without
   duplicate callbacks; and
4. restores the original helper and removes callbacks in `finally`.

The production search implementation and the read-pool/lease behavior are unchanged.
