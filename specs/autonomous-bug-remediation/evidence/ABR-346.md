## 3. Findings and Technical Judgement

### Root cause reproduced on the unchanged baseline

The original `pr_impact` path trusted the `files` array returned by
`gh pr view --json ...files` and could analyze a capped or empty array as if it were
complete. It did not expose an authoritative `changedFiles` total for the complete
set. The original triage path had the same pagination gap and did not verify a PR head
SHA across impact analysis. A controlled shortfall probe against the unchanged
`b52afd1` implementation confirmed that a response declaring one changed file with an
empty REST page still invoked Graphify with `files=[]` and produced a zero-impact
result.

### Causal remediation

- `_parse_known_total` accepts only a non-negative integer (or its decimal string
  representation). A malformed or negative declared total raises
  `GITHUB_UNAVAILABLE` instead of silently treating it as unknown.
- `_fetch_pr_files` retains initial paths, then uses fixed read-only REST pages with
  bounded `per_page` and `page` values. When GitHub declares a total, it must collect
  the complete required prefix up to `min(known_total, max_files)` before returning;
  an invalid page, early empty page, short page, no-progress page, or bounded stop
  below that target raises `GITHUB_UNAVAILABLE` before Graphify runs.
- For a declared total, `total_files` is that total and `truncated` is true only when
  it exceeds the operation's analysis cap. Without a declared total, a final short
  REST page proves exhaustion; reaching the cap without that proof remains truncated.
- `execute_pr_impact` propagates pagination failure as top-level
  `GITHUB_UNAVAILABLE`. `execute_triage_prs` preserves its existing per-PR result
  shape, setting `status="unavailable"`, `node_count=None`, and an explanatory error
  rather than rendering `0 nodes affected`.
- Both analysis paths preserve the existing head check and at-most-one retry. A head
  that moves again after retry fails as `GITHUB_UNAVAILABLE`; successful retry output
  is bound to the verified new head SHA.
