## 3. Findings and Technical Judgement

1. **Root Cause Analysis (Baseline RED):**
   - `execute_pr_impact()` requested `gh pr view --json ...files` in a single call, then sliced the returned array to 500. It could not know or analyze files omitted by GitHub CLI's GraphQL response cap (100 files). If a PR touched 150 files, baseline analyzed only 100, set `total_files = 100`, and marked `truncated = False`, presenting incomplete analysis as complete.
   - `execute_triage_prs()` fetched each PR with `gh pr view --json files` and never verified `headRefOid` before or after impact analysis. If the head moved while analyzing a batch of PRs, stale or invalid impact was returned for the old commit SHA.
   - `execute_triage_prs()` lacked pagination for large PRs and lacked moving-head retry.

2. **Causal Remediation (Candidate GREEN):**
   - Implemented `_fetch_pr_files(root, repo, pr_number, max_files, page_size=100, known_total, initial_files)`:
     - Extracts `changedFiles` from PR summary to know the exact total file count upfront.
     - Reuses initial view files if complete; if `known_total > len(file_paths)` or `initial_files` was capped/omitted, paginates via fixed read-only `gh api "repos/{repo}/pulls/{pr_number}/files?per_page={page_size}&page={page}"`.
     - Bounded pagination stops when `len(file_paths) >= max_files` (500 for `pr_impact`, 200 for `triage_prs`) or all pages are consumed.
     - Explicitly records `truncated: bool`, `total_files: int`, and `analyzed_files: int`. Omitted files are never analyzed as a complete set.
   - Moving-head verification in `execute_triage_prs`:
     - Records `head_before` prior to analysis.
     - Runs Graphify impact analysis.
     - Checks `headRefOid` after analysis.
     - If head moved, retries at most once: re-fetches PR view and files, re-runs impact, checks `headRefOid` again.
     - If head moved again, raises `KnowledgeError("GITHUB_UNAVAILABLE", ...)` which sets `status="unavailable"`, preserving zero-impact versus unavailable distinction (`node_count` remains `None`).
     - If retry succeeds, binds `triaged_pr["head_sha"]` to the verified new head SHA.
   - Preserved identical moving-head verification with retry and verified head SHA binding in `execute_pr_impact`.
