## 3. Findings and Technical Judgement

1. **Root Cause Analysis (Baseline RED):**
   - The R0 design baseline validation step in `.github/workflows/policy.yml` traversed markdown files using `root.rglob('*.md')`.
   - On a clean CI checkout, only tracked repository markdown files exist. However, on provisioned developer environments or checkouts with runtime dependencies installed (e.g., `home/.venv-hermes/`, `.venv/`, `.worktrees/`), `rglob('*.md')` recursively traverses through all ignored virtual environments and package directories.
   - External python packages frequently include markdown documentation files (e.g., `Privacy.md`, `README.md`) that contain relative links to unbundled files or non-standard code fence formatting.
   - Clean CI checkouts never reproduced this failure because clean worktrees omit ignored runtime dependencies.
   - When provisioned with runtime dependencies, `root.rglob('*.md')` fails asserting broken links or unbalanced fences on external dependency files that are gitignored.

2. **Causal Remediation (Candidate GREEN):**
   - In `.github/workflows/policy.yml` ("Validate accepted R0 design baseline" step), replaced filesystem-wide `root.rglob('*.md')` with tracked markdown file enumeration via `git ls-files '*.md'`:
     ```python
     md_files = [
         Path(p)
         for p in subprocess.check_output(
             ['git', 'ls-files', '*.md'], text=True
         ).splitlines()
         if p
     ]
     assert md_files, 'tracked markdown manifest must not be empty'
     ```
   - Both the legacy stage path check and the fence/link validation loop now operate strictly on `md_files`.
   - Tracked documentation checks remain 100% complete and fail if any tracked markdown file has broken links or unbalanced code blocks.
   - Ignored runtime dependencies under `home/.venv-hermes/`, `.venv/`, etc., are excluded from traversal, ensuring CI and provisioned local checkouts agree.
