## 3. Findings and Technical Judgement

1. **Demonstrated Credential Shapes vs. Baseline Acceptance (Baseline RED):**
   - On baseline `b52afd1`, `_SECRETS` in `src/aether_agents/knowledge/memory.py` only matched private key headers, OpenAI-style keys, and AWS access key IDs.
   - The three demonstrated credential shapes identified in issue #343 were accepted without rejection:
     1. Password assignments: `password = ...`, `passwd: ...`, `PASSWORD=...`, `"password": ...`
     2. GitHub token prefixes: `ghp_`, `gho_`, `ghu_`, `ghs_`, `ghr_`, and `github_pat_`
     3. Bearer authorization values: Authorization header Bearer values and standalone Bearer tokens
   - Furthermore, `_evidence()` previously scanned only `json.dumps(fields)`. With escaped quotes in JSON serialization, certain quoted assignments could bypass naive single-quote checks.

2. **Causal Remediation:**
   - Extended `_SECRETS` regex pattern with:
     - GitHub token prefixes (`ghp_`, `gho_`, `ghu_`, `ghs_`, `ghr_`, `github_pat_`) requiring token body >= 8 characters, preserving bare prefix documentation in benign text.
     - Password assignments matching assignments with quoted or unquoted values >= 6 characters, handling both raw text and JSON-escaped strings.
     - Authorization header values with Bearer scheme, or standalone Bearer tokens >= 16 characters.
   - In `WorkMemoryStore._evidence()`, updated validation to check both raw field values (`fields.values()`) and `json.dumps(fields)` against `_SECRETS`.
   - Local validation occurs in `_prepare_payload` and `_evidence` before any `GraphifyBackend.run()` call, guaranteeing that suspected secret material is never sent to Graphify or an auxiliary model.

3. **Benign Prose and Documentation Preservation:**
   - Discussions of password policies, hashing algorithms (e.g. argon2id, bcrypt), and reset flows do not use assignment operators immediately following the keyword and remain accepted.
   - Documentation of token prefixes without token bodies (e.g. `GitHub token prefixes (ghp_ / gho_ / ...)`) is preserved because the pattern requires at least 8 alphanumeric/underscore characters following the prefix.
   - Mentions of Bearer authentication standards (e.g. RFC 6750, middleware enforcement) and non-token English phrases (e.g. "bearer bonds", "bearer instrument") are preserved because standard English words do not reach the 16-character token threshold and lack authorization header syntax.
