## 2. Scope, Root Cause, and Round-2 Security Hardening

### Root Cause
In upstream Hermes, `_PROTECTED_INSTRUCTION_BASENAMES` unconditionally matched `soul.md` across all directory trees, while `_protected_instruction_reason` simultaneously exempted the active `real_home` (`~/.hermes`) where live profile `SOUL.md` files actually reside.

This caused two complementary defects:
1. **False Deny / Timeout on Tracked Source:** An ordinary, reversible edit or patch to a tracked repository or package source file (such as `src/aether_agents/resources/profiles/supervisor/SOUL.md` or any worktree file named `SOUL.md`) was falsely categorized as a protected agent-instruction write. When executed in automated, headless, or TUI sessions, this resulted in unanswerable approval timeouts: `BLOCKED: write to protected agent-instruction file(s) (SOUL.md) approval prompt timed out without a user response. Silence is not consent.`
2. **False Bypass on Live Profile SOUL:** A write targeting the active profile's actual instruction file (`<HERMES_HOME>/SOUL.md`) bypassed `_protected_instruction_reason` via `resolved.startswith(real_home + os.sep)`, completely unmonitored by the protected-instruction gate.

### Round-2 Review Finding
Round-1 independent review identified a case-sensitivity security gap:
- `_is_installed_profile_soul` only compared active/default `<...>/SOUL.md` paths with case-sensitive raw string equality.
- The named-profile branch checked `parts[0] == "profiles"` case-sensitively.
- On case-insensitive filesystems (macOS / Windows) or case-variant probes (e.g. direct `root/soul.md` on Linux), a case-variant path addressed the live identity file while returning `None`, re-introducing the false bypass.

### Bounded Repair
1. Defined `_is_same_dir(dir1, dir2)` to check directory identity robustly across case variants and filesystem conventions (`p1 == p2 or p1.lower() == p2.lower()`, with `os.path.samefile` fallback).
2. Defined `_is_installed_profile_soul(resolved, normalized)` to check whether a path corresponds to an installed Hermes profile's `SOUL.md`:
   - Active profile: `<HERMES_HOME>/SOUL.md` (and case variants `soul.md`, `Soul.MD`, etc.) via `_is_same_dir(target_dir, real_home)` and single-component relpath.
   - Default root profile: `<HERMES_ROOT>/SOUL.md` (and case variants) via `_is_same_dir(target_dir, real_root)` and single-component relpath.
   - Named profile: `<HERMES_ROOT>/profiles/<name>/SOUL.md` across directory case variants (`profiles`, `Profiles`, `PROFILES`) and file case variants.
3. Gated installed profile `SOUL.md` writes before the `real_home` exemption, ensuring live profile identity files always require explicit human approval and fail closed when unapproved.
4. Removed `soul.md` from `_PROTECTED_INSTRUCTION_BASENAMES`. Project-local instruction files (`AGENTS.md`, `CLAUDE.md`, `.cursorrules`, and project-local `.hermes/` config directories) remain protected and require approval across all directories. Ordinary tracked package source or project files named `SOUL.md` proceed without false prompts or timeouts.

Preserved without edits: Aether policy hooks, ledgers, live `home/` profiles, credential guards, and repository operating guidance.
