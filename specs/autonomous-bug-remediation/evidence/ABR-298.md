## 3. Findings and Technical Judgement

1. **Root Cause Analysis of Pre-Tool Credential Denial (Baseline RED):**
   - On baseline `b52afd1`, `_contains_secret(args, broad=False)` runs on non-durable tool calls (`write_file`, `patch`).
   - The authorization pattern in `HIGH_CONFIDENCE_SECRET_PATTERNS` was `(?i)\b(?:authorization|proxy-authorization)\s*[:=]\s*(?:bearer|basic)\s+\S+`, which matched any non-whitespace token after the bearer or basic scheme.
   - The sanitization logic only replaced `[REDACTED]`, `<REDACTED>`, `[redacted]`, and `<redacted>` with empty strings. Even though `PLACEHOLDERS` defined values such as `test`, `example`, `dummy`, `changeme`, and `not-set`, those values were only checked when `broad=True` on dictionary keys in durable tools.
   - Consequently, local writes or patches to documentation files (such as `docs/v1.0.0/STAGING_RUNBOOK.md`) containing placeholder staging auth (for example, header lines with `<staging-token>`, `placeholder`, `test`, or `example`) were blocked with `AETHER-IMPLEMENTER-CREDENTIAL: credential material may not be supplied through a tool call`.

2. **Causal Remediation and Technical Judgement:**
   - **Expanded Staging Auth Placeholders:** Updated `PLACEHOLDERS` to explicitly include staging-runbook placeholders consistent with existing convention: `<placeholder>`, `[placeholder]`, `placeholder`, `<token>`, `[token]`, `<staging-token>`, `<staging_token>`, `<auth-token>`, `<api-key>`.
   - **Enhanced Placeholder Matcher:** In `_is_placeholder(value)`, stripped enclosing quotes and punctuation and recognized angle/bracket delimited placeholders where inner tokens reference standard placeholder keywords (`token`, `placeholder`, `secret`, `key`, `password`, `auth`).
   - **Bounded Documentation Path Recognition:** Added `_target_path` to extract the target file from `write_file` arguments (`path`, `file_path`) or unified patch headers (`*** Update/Add File: ...`), and `_is_doc_path` recognizing paths in `docs/`, `specs/`, or documentation extensions (`.md`, `.markdown`, `.rst`, `.txt`).
   - **Selective Placeholder Allowance on Doc Paths:** In `_contains_secret`, when `is_doc=True`, syntax-based secret patterns (`AUTH_HEADER_RE`, `CONN_STRING_RE`, `QUERY_TOKEN_RE`) inspect all matches: if any matched value is not a placeholder, the check fails closed immediately (`return True`). If all matches are valid placeholders, they do not trigger a credential block.
   - **No Broad Exemption / Strict PD-71 Preservation:** High-confidence intrinsic credential patterns (private key blocks, OpenAI keys, GitHub tokens, Google API keys, AWS keys, Slack tokens, Stripe tokens, JWT tokens) are never exempted, even in documentation. Code and test fixtures (`is_doc=False`) do not receive documentation placeholder allowances.
   - **Micro-Authorization Constraint:** Kept `aether_pre_tool_policy.py` at 318 lines, satisfying the `<= 319` (`< 320`) line constraint enforced by `test_policy_has_no_micro_authorization_dependencies`.
