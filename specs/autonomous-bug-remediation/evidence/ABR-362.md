## Bounded change

The fork candidate changes only the review transition/claim path and its focused tests:

- `hermes_cli/kanban_db.py`
  - Initial `request_review` calls without an independent reviewer fail closed before clearing the implementation claim.
  - A reviewer equal to the implementing profile is rejected.
  - Re-review continues to reuse valid reviewer provenance from `changes_requested`.
  - A legacy `review_requested` event with a missing reviewer cannot be claimed into a review run; it remains parked for explicit reassignment. Rows without review provenance retain the existing manual/dashboard behavior.
- `tools/kanban_tools.py`
  - The `kanban_request_review` schema explains that the first request requires a different reviewer and that re-review may reuse durable provenance.
- Fork review tests under `tests/hermes_cli/`
  - Cover database rejection, worker-tool rejection, self-review rejection, legacy unsafe review claim denial, and the explicit reviewer/re-review cycle.
  - Existing lifecycle tests were updated only where the new explicit reviewer contract changed their fixture setup.
- Aether `tests/test_same_card_phase_predicates.py`
  - Adds the project acceptance predicate that a Supervisor-created implementer task keeps its live implementation claim when no reviewer is supplied.

Preserved without edits: Aether policy hooks and ledgers; fork `conversation_loop.py`, `run_agent.py`, `background_review.py`, and maintenance ledgers.
