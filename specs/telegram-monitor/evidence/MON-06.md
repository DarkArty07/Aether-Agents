**Round 1.** (1) Session seeding was incompatible with the provisioned writer: the fixture
called `SessionDB.create_session(..., display_name=…, started_at=…, ended_at=…)`, which the
provisioned `_insert_session_row` does not accept — reproduced through the harness's own
`_lab_fixture` path against the pinned baseline (`fixture-sessions: TypeError`). The fixture
now passes only resolved parameters (`cwd`, `git_repo_root`, `profile_name`) and writes the
title through the shipped `set_session_title`. (2) Synthetic task identity was not the
writer's identity: the manifest precomputed `_task_id()` values and used them for links, the
between-cut transition and every D12 `fixture_ref` (reproduced: `fixture-tasks: ValueError:
unknown task(s)`). The manifest now carries no task identity at all; the fixture reports the
id each writer call returned, the harness binds exactly those ids and links, transition and
case references derive from them. (3) The evidence claimed digests that did not exist; the
gate now really records them. (4) Counts, the probe's header comment and the `compileall`
gate list were corrected. A seventh defect was found while reproducing: `InProcessCronScheduler.name`
is an *instance property*, so reading it on the class put a `property` object into the probe
payload and the whole preflight died with `runtime-probe-failed … Object of type property is
not JSON serializable` on the pinned baseline too; the probe now reports the descriptor
explicitly and a real child-process regression pins it.

**Round 2 — the two defects that made the live lane unstartable.** Both were reproduced with
the harness's own functions against the pinned baseline in a private temp laboratory, and both
are fixed:

1. **The provisioned probe body was invalid Python.** `_lab_destination(interpreter,
   environment=None)` rendered its child body with `json.dumps(...)`, which emits the literal
   `null` for the missing laboratory root, so the child died with
   `NameError: name 'null' is not defined`. Reproduced: `_lab_destination(interpreter,
   environment=None)` → `QualificationError: runtime-probe-failed` with
   `stderr_tail: ["NameError: name 'null' is not defined"]` — the first step of `run_live`,
   on every runtime. The body is now generated by `_native_probe_body`, which renders the
   optional root through `_python_literal` (`None`, never `null`), and both variants are
   executed as real child processes by a regression.
2. **Bootstrap could never succeed: the isolated probe materialized the laboratory root
   before the exclusive creator.** The single preflight ran the isolated probe in the lab
   child context *before* `_lab_create`; importing `cron.scheduler_provider` with
   `HERMES_HOME=<lab>/hermes` materializes `<lab>/hermes/**` and therefore creates `<lab>`
   itself, so `_lab_create` always refused with `lab-root-exists` after the probe.
   Reproduced: root absent → isolated probe → root exists with children `['hermes']` →
   `_lab_create` raised `lab-root-exists | the laboratory root already exists; a lab is
   created exclusively and never reused`.

The fix follows the normative bootstrap order instead of working around it (D13 bootstrap 1
creates the private root before bootstrap 2 and 5 resolve the loaded artifacts and the native
interfaces):

- `_lab_preflight` is now the **read-only phase**: layout, decision-only configuration,
  borrowed access, verified child context, the provisioned route/destination and the native
  scheduler interface. A refused layout returns its problems **before** the provisioned
  runtime or the borrowed access is touched — no root, no credential read, no runtime probe
  (`test_read_only_preflight_refuses_the_layout_without_creating_or_borrowing`, plus the
  offline `lab-bootstrap-preflight` check, which now drives the real helper with a
  nonexistent interpreter and an empty environment).
- `_lab_context_preflight` is the **in-laboratory gate**: it runs inside the created private
  root, resolves the isolated destination and compares it with the provisioned one
  (`destination-drift`), the native scheduler interface and the whole native writer surface
  (interfaces and accepted keywords, loaded module/artifact digests, entry points, effective
  roots), and refuses with the bounded `lab-context-preflight` code before the scope is
  seeded, the job enabled, the scheduler started, a model called or a message sent. The
  laboratory root created for the run is retained and reported as created — it is never
  self-deleted, and the isolation displaced nothing.
- The writer gate now requires every keyword the fixture passes to `create_task`
  (`body`, `assignee`, `created_by`, `workspace_kind`, `workspace_path` in addition to
  `title`, `initial_status`, `session_id`, `board`), so a narrowed provisioned writer is
  refused by the gate rather than failing after the first write.
- The old tests could not see either defect: the preflight regression monkeypatched
  `_lab_destination` (so neither the generated body nor its side effect ran), the lane tests
  drove fakes, and no test generated the `lab_root=None` variant. Those tests are replaced by
  **executed** regressions: `_run_probe_body` runs both generated variants as real child
  processes, and `_CHAIN_DRIVER` runs the real chain — `_lab_preflight` → `_lab_create` →
  `_lab_context_preflight` → `_lab_fixture` → `_lab_transition` — in a child process against
  a functional minimal native tree, with no monkeypatched probe and no fake backend. The same
  driver with the review writer removed proves the gate refuses before any seeding.

session roots it is about to write (`fixture-root-escape`), so an inherited explicit board

## The retirement mapping (the reviewed swap machinery)

The retired lane hid this installation's project registry behind a synthetic one and then
restored it. That is why it needed durable `registry.json.qualification-recovery.json`
records, `registry.json.qualification-held`/`.qualification-outgoing` moves, `renameat2`
`RENAME_NOREPLACE`, staged installs into the operator registry directory, descriptor-proved
deletions and a documented POSIX deletion boundary. **All of it is deleted, not skipped**,
and the refusal it produced (`scope-isolation-unsupported`) is gone with it. The guarantees
it existed to protect are now provided by containment and retention:

| Swap-lane guarantee | Replacement evidence |
| --- | --- |
| Operator projects are never hidden while the run proceeds | No code path addresses the operator registry at all; the laboratory resolves its own registry, boards, sessions, cron store and monitor state inside the private root (`telegram_monitor_lab.child_environment` + `context_problems` + the child's own effective-root check) |
| A concurrent registry write cannot be lost or overwritten | Nothing is captured, moved, replaced, merged or deleted, so there is no race to lose |
| Registry restored byte-identically | Nothing is displaced; `retention.registry_touched` is reported `false` for every run, qualified or refused |
| Synthetic scope cannot leak into production state | Every mutable root is redirected inside the lab root and verified before use; an escape is refused with `lab-context-escape`, and a writer that effectively resolves outside the laboratory is refused with `writer-root-escape:<root>` / `fixture-root-escape` before its first write |
| Cleanup cannot silently fail | There is no operator-state cleanup; the laboratory is retained and its evidence verified (`lab-retention` refuses an incomplete root) |
| No entry of the registry directory is ever unlinked | `test_no_laboratory_code_path_touches_the_operator_project_registry` runs a whole lane under a filesystem-operation interceptor and asserts **no** rename/replace/unlink/rmdir/rmtree ever names the registry directory — with `test_operator_registry_detector_has_a_positive_control` proving the detector fires on a deliberate rename |

## Interpreter and candidate-loading evidence

- The lane resolves the interpreter through the shipped boundary only
  (`aether_agents.monitor.commands.runtime_interpreter()`); `--live` is refused with the
  bounded `runtime-unavailable` error when no provisioned Hermes-capable interpreter
  resolves, and no fallback interpreter, `sys.executable` or invented launcher is used.
- Candidate identity is recorded from the loaded repository (`_candidate_revision()`), and
  **the loaded candidate itself is now measured**: the preflight records, per module the
  laboratory depends on, the resolved file and its SHA-256, the declared plugin entry points
  and the installed distribution versions — read in the laboratory child context, i.e. from
  the interpreter and import path the lane will actually use. A module without a readable
  digest refuses the run (`writer-artifact-missing:<module>`); a source branch name or a
  version string alone is not treated as loading evidence. The authoritative digest map goes
  to the private receipt, and the same evidence reaches the public summary as names,
  versions and digests only (`preflight_writers`), never a module file or laboratory path.
- The native scheduler interface is probed by signature
  (`InProcessCronScheduler.start(stop_event, …)`) and the `name` descriptor is reported
  explicitly rather than serialized; an unavailable or signature-incompatible scheduler
  refuses the run instead of inventing a replacement.
- The destination is resolved **twice** — once in the provisioned context and once in the
  lab child context — and only its SHA-256 digest is retained; a difference refuses with
  `destination-drift`. The digest (not the chat identifier) is what reaches the receipt.
- **Limit, stated honestly:** the digests above were produced by executing the harness's own
  probe against the pinned tree and against the older local checkout in a private temp
  laboratory (no live lane, no model call, no Telegram call) and by the child-process
  regression in the test suite. They are the *inspected candidates'* loading evidence; the
  live lane has still not been run by this unit, so no live qualification, delivery or
  activation is claimed.

## Compatibility conclusion (unit level)

Observed unit-level compatibility: **additive/minor, with one deliberate removal and one
deliberate tightening.**

- Removed: the live lane no longer refuses with `scope-isolation-unsupported` and no longer
  swaps/restores the operator registry; it runs inside its own private laboratory and never
  addresses operator state.
- Tightened: the read-only preflight now also refuses a provisioned runtime that does not
  expose the writer surface the fixture needs (or whose writers would effectively resolve
  outside the laboratory). A runtime without a review-lane writer (observed: `hermes-agent`
  0.19.1) is now a bounded capability gap instead of a mid-lane failure; the selected public
  baseline (`v2026.8.18`) resolves the whole surface with no writer problem. This is a
  fail-closed capability check, not a feature change, and it is the behaviour D13 asks for.
- Unchanged: `--json`/`--live`/`--output`/`--wait-hourly-boundaries 2`, the deterministic
  lane, the shipped monitor implementation (`src/aether_agents/monitor/**`), the D12,
  boundary, receipt and privacy oracles, and the public summary's existing fields.
- Public summary: gains `preflight_writers` (names, digests, entry points, installed
  distribution versions) on top of the laboratory containment/retention fields; the
  restoration fields of the retired lane remain absent.

**Release impact and action are not decided here**: this is unit-level compatibility evidence
only, and prerelease/merge is not a compatibility statement. Aggregate release conclusions
(`release_impact`, `release_action=defer`, `release_channel=none`) belong to MON-INT2.

## Residual risk and limits

- **No live run in this unit.** The laboratory's multi-hour behaviour (real model narration,
  real Telegram delivery, two natural hourly cuts, the idle skip) is implemented and driven
  end to end by injected backends, but never executed here. The fixture, the between-cut
  transition and the read-only probes *were* executed against the pinned baseline in a
  private temp laboratory (no live effect, no credential use), which is what makes the
  writer-interface corrections evidence rather than intent. The first real run happens in
