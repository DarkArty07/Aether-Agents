## HLP-310 — delegated-child identity and Kanban environment snapshot exclusion

- **Reason:** terminal snapshot dumps (`_export_dump_excluding_session_vars` in `tools/environments/base.py`) did not unset `HERMES_DELEGATED_CHILD_CONTEXT` or dispatcher-owned `HERMES_KANBAN_*` environment variables. When a delegated child executed a terminal command, its `HERMES_DELEGATED_CHILD_CONTEXT="1"` persisted into the shared bash session snapshot, leaking child mutation denial markers into subsequent parent commands. Similarly, dispatcher-owned `HERMES_KANBAN_*` variables were persisted as stale state across tasks and sessions.
- **Primary active files:**
  - `tools/environments/base.py`
  - `tests/tools/test_snapshot_session_id_leak.py`
  - `tests/tools/test_delegate_kanban_isolation.py`
- **Local evidence:** fail-first reproduction on unchanged base `6243e40ea6b06e85061bf3fedffaad43eed51dec` showed `HERMES_DELEGATED_CHILD_CONTEXT` and `HERMES_KANBAN_*` persisted into snapshot dumps and observed by later parent commands (4 failed). Candidate with prefix unset `${!HERMES_KANBAN_*}` and explicit `HERMES_DELEGATED_CHILD_CONTEXT` unset in `_export_dump_excluding_session_vars` passes all 14 tests across `test_snapshot_session_id_leak.py`, `test_delegate_kanban_isolation.py`, and `test_snapshot_multiline_session_env_injection.py` with `HERMES_TEST_FILE_RETRIES=0` from a sterile HOME/HERMES_HOME. Zero Windows footguns detected.
- **Upstream:** bug in `NousResearch/hermes-agent` terminal snapshot persistence; no upstream direct fix was found.
- **Rollback:** revert commit `25cabeb25327199a03aa3cf1613ed2f815f646cb` in fork repository `DarkArty07/aether-hermes`.
- **Retirement gate:** verify on target upstream revision that bash snapshot exports exclude `HERMES_DELEGATED_CHILD_CONTEXT` and `HERMES_KANBAN_*`, so delegated children cannot leak identity markers to parent execution and Kanban task identity remains per-command transient.
