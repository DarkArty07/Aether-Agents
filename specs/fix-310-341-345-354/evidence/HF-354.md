## 3. Investigation, Reproduction, and Qualification Findings

### 3.1 Defect Mechanism (Reproduced on Unchanged Baseline `6243e40e`)
In `hermes_cli/kanban_db.py:_ensure_git_worktree()`, when creating a new branch for a linked git worktree, the command was hard-coded to use `"HEAD"`:
```python
cmd = [
    "git", "-C", str(repo_root), "worktree", "add", "-b", branch_name,
    str(target), "HEAD",
]
```
If the primary project checkout was on an incidental branch or divergent commit (e.g. branch `branch-b` at commit `B`), any newly materialized Kanban worktree for that project was rooted at commit `B`, even when board metadata recorded a specific contract base commit `A` in `worktree_base_ref`. Furthermore, invalid `worktree_base_ref` values were ignored, silently falling back to primary `HEAD` rather than failing closed.

### 3.2 Fail-First Test Execution (RED on Unchanged `6243e40e`)
Executing `tests/hermes_cli/test_kanban_worktree_base_ref.py` on baseline `6243e40e` resulted in **14 failed, 2 passed**:
- `test_worktree_base_ref_materializes_at_base_commit`: FAILED. The materialized worktree HEAD matched primary HEAD (`commit_b`), not `commit_a`.
- `test_invalid_worktree_base_ref_fails_closed` (9 parameterized cases: `"not-a-sha"`, `"HEAD"`, `""`, `"6243e40"`, uppercase, trailing space, leading space, 41 chars, 39 chars): ALL FAILED with `Failed: DID NOT RAISE ValueError`.
- `test_worktree_base_ref_occupied_fallback_uses_base_ref`: FAILED. Fallback worktree was rooted at primary HEAD (`commit_b`) instead of `commit_a`.
- `test_write_board_metadata_persists_worktree_base_ref`: FAILED (`TypeError: write_board_metadata() got an unexpected keyword argument 'worktree_base_ref'`).
- `test_ensure_git_worktree_explicit_base_ref`: FAILED (`TypeError: _ensure_git_worktree() got an unexpected keyword argument 'base_ref'`).
- `test_worktree_base_ref_nonexistent_commit_fails_closed`: FAILED (`TypeError: _ensure_git_worktree() got an unexpected keyword argument 'base_ref'`).
- `test_missing_worktree_base_ref_uses_head`: PASSED (control for non-Aether boards).
- `test_linked_worktree_reuse_preserves_existing_checkout`: PASSED (control for worktree reuse).

### 3.3 Causal Repair (GREEN on Candidate `7d3173e1`)
1. Added regex pattern `_WORKTREE_BASE_REF_PATTERN = re.compile(r"^[0-9a-f]{40}$")`.
2. Implemented `_resolve_worktree_base_ref(board=None, base_ref=None) -> str`:
   - If `base_ref` is provided, validates that it matches `^[0-9a-f]{40}$`.
   - If `base_ref` is omitted, reads `board_slug = board if board else get_current_board()`, then inspects `read_board_metadata(board_slug)`.
   - If `"worktree_base_ref"` is absent from metadata, returns `"HEAD"`, preserving standard Hermes behavior for non-Aether boards.
   - If `"worktree_base_ref"` is present in metadata, validates that it is a string matching `^[0-9a-f]{40}$`. If invalid, raises `ValueError` (fails closed).
3. Updated `_ensure_git_worktree(repo_root, target, branch_name, *, board=None, base_ref=None)` to resolve `target_ref = _resolve_worktree_base_ref(board=board, base_ref=base_ref)` and pass `target_ref` instead of hardcoded `"HEAD"`.
4. Updated `_resolve_worktree_workspace(task, *, board=None)` to forward `board=board_slug` into each `_ensure_git_worktree()` call (both initial path and occupied-path fallback).
5. Added optional keyword argument `worktree_base_ref: Optional[str] = None` to `write_board_metadata()`.
