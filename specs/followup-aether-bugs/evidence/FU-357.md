## What changed

### Runner (`scripts/qualify_observation.py`)

- New `QualificationFailure(RuntimeError)` (line 158) carrying a bounded `diagnostic`
  dict; the JSON is appended to the exception message so CI tracebacks retain it.
- Allowlisted schema builder `_qualification_diagnostic` (line 198) with
  `QUALIFICATION_DIAGNOSTIC_SCHEMA_VERSION = 1` (line 128). Retained fields only:
  `schema_version`, `phase`, `failure_kind` (`assertion`/`exception`), `failure_class`,
  `exception_class`, `assertion_class`, optional `test_node` (repository-relative),
  optional `source_commit` (40-hex), optional `runtime` (`python`, `implementation`) and,
  on the fallback path only, `marker_count` (bounded count).
- Bounded phase names: harness phases `registration`, `tool_capture`, `api_capture`,
  `unload`, `persisted_event_privacy`; runner phases `checkout`, `collection`,
  `core_execution`, `qualification_harness`, `harness_result`, `unknown`.
- `_run` (line 368) accepts a call-site `phase` and raises `QualificationFailure` with the
  structured diagnostic alongside the pre-existing content-free `stdout_tail`/
  `stderr_tail`. Existing git redaction and pytest node/hash retention are unchanged.
- `_qualification_failure_diagnostic` (line 302) first parses at most one harness-emitted
  `AETHER_QUALIFICATION_DIAGNOSTIC=` marker and re-validates every field against the
  allowlist; if no marker is usable it falls back to the call-site phase plus an
  identifier-shaped `*Error|*Exception|*Failure` token recovered from the streams.
- `_harness_result_failure` (line 501) classifies harness result mismatches as phase
  `harness_result` with `source_commit` pinned to the runner-verified
  `HERMES_BASELINE.commit`.
- Runner call sites now pass phases: `checkout` (546/553/567/572), `collection` (685),
  `core_execution` (701), `qualification_harness` (728).

### Harness instrumentation (`tests/test_observation_qualification.py`)

- `_mark_qualification_phase` (line 50) and `_emit_qualification_failure` (line 57) emit
  exactly one allowlisted marker line; `_diagnose_qualification_failure` (line 83) wraps
  the real harness test, resets the phase to `registration` and re-raises after emitting.
- The real harness marks the phase at its boundaries (lines 182, 242, 301, 306), so a
  failure names the phase in which it occurred. Phase names and marker prefix/schema
  values are shared with the runner by construction; the end-to-end canary proves they
  agree in practice.
