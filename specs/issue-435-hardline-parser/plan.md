## Behavior and design boundary

The observed user effect is an unconditional malformed-payload denial of two short, legitimate read-only grep inspections. Both are validly quoted; the parser limit is not reached. The material decision is to evaluate shell/grep quote structure on a syntax-preserving representation of the original command, not on deobfuscation output that has stripped backslashes and empty quote pairs. Continue to detect genuinely malformed executable payloads and real protected commands using the existing deobfuscated variants and hardline floor. Masking of genuinely inert grep operands, if needed, must be derived from unambiguous original shell structure and must not hide a real executable command, command substitution, separator or quoted-data boundary. Keep the existing parser limits, approval mode, protected patterns and fail-closed behavior. A simple broad grep allowlist, raising limits, or skipping normalizer/threat variants is unacceptable.

Sanitized **representatives of the two logged byte shapes** (private directory prefixes replaced, examples rather than new universal allowances):

```text
cd /tmp/safe-repo && grep -n "for edge in" -A 3 harness.py | head -20; echo "=== check other spot ==="; grep -n "edges\\", \\[\\]" harness.py
cd /tmp/safe-repo && grep -n "PATTERN\\|regex\\|r\\"" scripts/check_public_artifacts.py | head -30
```

Transfer these to Python tests with explicit literal/escape checks; Markdown escaping is not a fixture. No test executes these shell strings or reads the private original files. A positive fixture must fail with `_MALFORMED_EXEC_DESCRIPTION` at the base and pass on the candidate; a genuinely unclosed quote stays blocked. The rejected alternative is treating a normalized-only imbalance as evidence that the raw shell command is malformed. Local implementation choice: exact lexer/variant helper shape, as long as both syntax and protected effects are preserved across the full guard chain.
