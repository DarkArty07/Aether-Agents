# TS-390 evidence — typed finish-reason histograms survive the observation pipeline

Requirement: `specs/006-tools-memory-stability/spec.md` TS-390 — "Legitimate schema-valid
numeric finish-reason histograms survive capture, reduction, storage and compact
observation", with `stop`, `tool_calls` and `error` persisted and readable at their
original counts, and raw contents, unsafe names/types and forbidden fields elsewhere
still rejected.

Objective Contract `oc_6176d2be6cb7e6fe@v1` (digest
`69765e73e657b7c0854454a4257a43e5f113ed9c4deb9c6559c536b374a5c040`), unit U390 of the
Supervisor breakdown `specs/006-tools-memory-stability/tasks.md@ef69bdc`. Base commit
`3ce47369165dda9c7df3452730c8caf1ee0a6ca0`. Selected design: `plan.md` "TS-390: typed
finish-reason counts".

## Diagnosis (reproduced before the fix)

`observation/privacy.py` treated *every* metadata key as a field name. The summary
histogram's keys are schema-owned data, so a legitimate
`model_context_economics.finish_reasons` entry named `tool_calls` or `error` matched
`FORBIDDEN_KEYS` and the whole summary was rejected — even though the normative summary
schema already accepted it. `ReadModel.record_summary` therefore could not persist a
summary whose trace contained those finish reasons, and compact observation failed with
"observation state is unreadable". `failures: FORBIDDEN_KEY at
$.model_context_economics.finish_reasons.error` (probe output, baseline).

Baseline probe (`specs/006-tools-memory-stability/fixtures/binding_privacy_probe.py`):
5 failed / 9 passed, of which the four TS-390 assertions were RED
(`test_390_schema_valid_numeric_histogram_passes_privacy[tool_calls,error]`,
`test_390_real_event_reducer_and_storage_boundary[tool_calls,error]`).

Normative alignment (`specs/002-aether-contract-observation/spec.md`, read-only here):

response, reasoning, request body, and error text remain forbidden", and section 8.3
forbids "arbitrary unvalidated payload dictionaries". The relaxed path accepts only the
schema-validated histogram (bounded names, strict non-negative integer counts), so the
guard now matches the requirement instead of contradicting it; no canonical revision is
implied.

### Traversal evidence (verification item 2)

`tests/test_observation_brief_tool.py::test_finish_reason_histogram_survives_persistence_reduction_storage_and_compact_observe`
(parametrized `stop`, `tool_calls`, `error`) exercises the real, non-mocked boundary set
with a per-project isolated state home:

1. **Projection/capture** — `EventBuilder.model_request(finish_reason=<reason>)` produces
   the event and `EventFactory.add` schema-validates it.
2. **Persistence** — `JournalWriter.append` accepts the event; the canonical journal line
   on disk contains `"finish_reason":"<reason>"` verbatim.
3. **Reduction** — `query.load_summary` → `ingest_pending` → `reduce_trace` →
   `reduce_events` produces `model_context_economics.finish_reasons == {<reason>: 1}`.
4. **Storage** — the same call performs `ReadModel.record_summary` (validate + guard +
   insert); a rejection would surface as `AETHER-OBSERVE-STATE-UNREADABLE`. The immutable
   summary file is re-read through `query.load_previous_summary` (schema + guard +
   identity re-check) with the count intact.
5. **Compact observation/report** — `brief.observe(action="status")` returns
   `state="ready"` with the same `summary_id`, and `report.render_brief` renders
   `finish reasons: <reason>=1`.

`test_every_finish_reason_count_survives_one_trace` gives one trace four distinct native
requests (`stop`, `tool_calls`, `tool_calls`, `error`) and observes
`{"error": 1, "stop": 1, "tool_calls": 2}` after persist → reduce → storage → re-read,
and `finish reasons: error=1, stop=1, tool_calls=2` in the compact brief.

drift from the schema it mirrors.

## Limits

- Verification item 5 (native `aether_observe` on a real affected contract after
  candidate adoption) was **not** performed here: it requires adoption of this candidate
  into the scoped runtime and reads real project state. It is terminal integration work
  per the card and the owning `quickstart.md`; no authoritative events were rewritten and
  no privacy check was bypassed to obtain a result.
- `uv run --frozen python scripts/run_tests.py` (the bootstrap-managed exact-public-baseline
  qualification) was not run. The full local suite *was* run against a pre-existing local
  checkout of the selected public release (`v2026.8.18`,
  `e624e9fde561e1add9388384012b295fde669ade`) on `PYTHONPATH`, with the base commit
  measured in a detached worktree under the identical invocation (rows 6–7); that is a
  local regression comparison, not exact-baseline qualification.
- Environment-prerequisite skips are pre-existing and independent of this change: three
  `tests/test_knowledge_plugin_cli.py` cases need `hermes_cli`, one needs the Native
  Graphify fixture, `tests/test_observation_brief_tool.py` needs `hermes_cli` for its
  real-`PluginContext` case, and the full run reports 64 such skips on both revisions.
- Four files remain unformatted repo-wide on the base commit; they are outside this
  unit's writable surface and were left untouched.
- The guard is intentionally stricter than the JSON Schema `pattern` keyword in one
  unobservable corner (a trailing newline is accepted by `re.search`-based JSON Schema
  matching and rejected here). The projector's `opaque_ref` boundary cannot produce such a
  name, so no schema-valid summary is rejected; the direction is fail-closed.
- The reducer's existing reconciliation collapses two terminal model requests that share
  one native request identity into one attempt, so a histogram counts distinct native
  requests. That is preserved behavior, not a change made by this unit.
