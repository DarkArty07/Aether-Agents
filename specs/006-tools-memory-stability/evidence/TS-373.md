## Requirement

`spec.md` TS-373: "A valid exact-session explicit binding remains reachable when native cwd
is an ordinary existing non-Git directory, as it is for null/empty cwd", retaining rejection
of conflicts, copied/unregistered worktrees, wrong role/session, unreadable evidence and
malformed Git metadata, with tool-level graph and memory resolution plus a deterministic
matrix (`spec.md:29`, `spec.md:52`).

`plan.md` TS-373 selection: classify native evidence before deciding precedence; absent/empty
metadata and an ordinary existing directory proven to have no Git repository context may fall
through to the exact-session explicit binding; a usable native project and the explicit binding
must agree; missing/unreadable paths, malformed Git metadata, Git failure in an apparent
repository, copied markers, unknown UUIDs, unregistered worktrees and contradictory native
evidence remain errors; ancestors resolve through the existing Git operation rather than being
treated as a new project (`plan.md:17-42`).

## Owned change

`src/aether_agents/knowledge/bindings.py` only; `knowledge/context.py`, `knowledge/common.py`
and the native plugin boundary needed no change.

- `_native_workspace` now classifies the recorded workspace before precedence is decided:
  non-absolute, missing/not-a-directory, and unusable-Git-evidence paths keep raising
  `VIEW_MISMATCH`; unreadable session databases keep raising `PROJECT_UNRESOLVED`; a
  workspace with no usable project evidence returns `None`, which lets the existing
  `context_for_session` precedence read the exact-session explicit binding as it already did
  for absent/empty metadata.
- New local helpers `_apparent_git_metadata` (a `.git` entry in the directory or an ancestor)
  and `_repository_context` (Git's own `rev-parse --git-dir` discovery, run in the shared
  clean environment) decide that classification. Only a directory with neither a `.git` entry
  nor a Git repository found by Git is treated as ordinary; every unclear or failed probe keeps
  the conservative failure path.
- Usable checkouts still resolve through `git rev-parse --show-toplevel`, so an ancestor
  subdirectory resolves the registered root and an attached worktree resolves its own view.

Local choices (reversible, inside the selected behavior): the classifier is private to
`bindings.py`, uses Git's discovery instead of a path-name heuristic, and reuses the existing
`clean_environment()`; no public name, schema or error code was added.
