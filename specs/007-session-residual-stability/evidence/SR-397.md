## 2. Residual gap implemented (Aether-owned, Monitor-disjoint files)

New module `src/aether_agents/lab/isolation.py` (single dependency-free module; the canonical home of the moved `HarnessError`, `preflight_disposable_destinations`, `isolated_hermes_env`, `native_python_for`):

- `resolve_writer_roots(environ=None, *, native=None)` resolves the **effective** home, board root, boards root, database, projects database and workspaces a loaded writer would use; native resolvers (`hermes_constants:get_hermes_home`, `hermes_cli.kanban_db:{kanban_home,boards_root,kanban_db_path,workspaces_root}`, `hermes_cli.projects_db:projects_db_path`) are authoritative in the child; the environment-derived form mirrors the same override precedence (`HERMES_KANBAN_DB` outranks `HERMES_HOME`) for a foreign process.
- `writer_root_problems(roots, *, private_roots)` / `verify_writer_context(...)` compare each resolved root with the declared private roots: absolute, **non-symlink**, resolvable, and **contained** (equal or descendant); any mismatch raises `HarnessError` with bounded codes (`<root>-escape`, `<root>-symlink`, `<root>-not-absolute`, `<root>-unresolved`, `private-root-*`) *before* any writer runs.
- `verify_child_writer_context(private_roots)` is the in-child gate: resolves this process's roots with the loaded writer modules and refuses before the first write.
- `probe_child_writer_roots(python, environ)` runs the self-contained read-only `CHILD_WRITER_ROOTS_PROBE` in the provisioned interpreter; `require_verified_writer_context(...)` consumes it and refuses on mismatch, recording `child_probe: native|unavailable` in a decision-only receipt (root names and counts, never paths).
- `scrub_inherited_identity(environ)` is the single scrub definition (`HERMES_KANBAN_*`, `HERMES_SESSION_*`, `TERMINAL_CWD`, `HERMES_CWD`, `HERMES_DELEGATED_CHILD_CONTEXT`, `HERMES_PROJECT_ID`, `HERMES_TENANT`, `AETHER_PROJECT_ID`) reused by the constructor and the matrix launcher.

### 2.1 Round-1 review corrections (second iteration, same card)

**(a) The environment-derived fallback did not model `get_default_hermes_root()`'s native-home branch.** `isolation.py` anchored every kanban root on `_hermes_root_for_profile()` (profiles-split only), so a `HERMES_HOME` resolving *under the platform-native home* was treated as its own root: `writer_root_problems(...) == []` and a PASS receipt while the loaded revision anchors the kanban roots on that native home — the operator's live root. Reproduced on the round-1 tip with a synthetic HOME under `/tmp` (nothing real touched): derived `kanban_home=<synth>/.hermes/labs/x`, problems `[]`, receipt PASS vs native `kanban_home=<synth>/.hermes`, problems `[boards_root-escape, kanban_db-escape, kanban_home-escape, workspaces_root-escape]`.

Correction: `_platform_default_hermes_home` (`$HOME/.hermes` on POSIX, `%LOCALAPPDATA%\hermes` on native Windows), `_hermes_home_from_env`, `_default_hermes_root_from_env` (native branch order preserved: under-native-home → native home; `<root>/profiles/<name>` → `<root>`; otherwise the home itself; unset `HERMES_HOME` → native home; a resolution failure → `None`) and `_kanban_home_from_env` (its override, else the default root). A `None` model refuses the anchored roots as `<root>-unresolved` instead of guessing; `boards_root`/default-board `kanban_db`/`workspaces_root` now anchor on the effective kanban home, matching `kanban_home()`.

Fidelity matrix (8 mappings — under-native-home, profile-in-native, profile-outside-native, custom-outside, `HERMES_HOME` unset, mapping without `HOME`, `HERMES_KANBAN_HOME` override, standard lab env): the derived form equals the native child probe for all six roots in every case; the new regression test additionally asserts that derived and native problem lists are identical, so the derived refusal matches native behavior instead of being merely stricter.

**(b) `dispatch_until_settled` reached the native `hermes kanban dispatch` writer with no gate when no roots were declared** (round-1 `if run_root is not None:`). It now mirrors `run_persistent_session`: an undeclared context raises `HarnessError` before any dispatch, and the declared context is verified with the provisioned interpreter (`python=native_python_for(hermes)`). This is the call site that previously *always* took the environment-derived fallback; it now takes the native child probe whenever the provisioned interpreter can resolve the modules and falls back only when it cannot. Reproduction pinned as a test: ambient `HERMES_KANBAN_DB`, no declared roots, fake launcher records its own invocation — the marker must stay absent.

**(c) The child probe is never handed to a non-Python runner.** `native_python_for` may legitimately return a shell shebang target (its pinned contract is asserted by `tests/test_lab_formalization.py::test_native_python_resolves_shell_launcher_interpreter`), and `sh -c <python source>` does not fail fast: on this host `import` resolves to ImageMagick and blocks until the probe timeout (measured: the dispatch test took 60.05s = 2×30s timeouts before the guard). `probe_child_writer_roots` now requires a Python-named interpreter (`_is_python_interpreter`), records `child_probe: unavailable` otherwise, and the environment-derived fallback verifies. The launcher-resolution contract itself is unchanged.

## 7. Residual risk

- The gate is a cooperating-process integrity control, not an OS sandbox: it prevents an *unintended* laboratory context from reaching a live board; a process that deliberately fabricates its own environment is out of scope (same boundary as the Monitor laboratory).
- When the child interpreter cannot import the native modules, verification falls back to the environment-derived form and the receipt records `child_probe: unavailable`; containment and pin checks still run, but the native confirmation is absent. In this environment both forms were exercised.
- Fidelity boundary of the fallback: the environment-derived model is pinned to the selected public release's resolution algorithm (`hermes_constants.py` `get_default_hermes_root`/`_hermes_home_from_env`/`_get_platform_default_hermes_home`, `hermes_cli.kanban_db.kanban_home`, revision `e624e9f`), and matches it on all 8 exercised mappings. If a future provisioned revision changes that algorithm, the model can diverge; the child probe is the authority whenever it can run, and the model is the documented, fail-closed substitute only for the unprobed case. A revision bump must re-run the matrix.
- A mapping that omits `HOME` (and the relevant `HERMES_KANBAN_*` pins) is refused as `<root>-unresolved` even where the native child would fall back to the passwd entry: fail-closed by design, since the parent cannot show which native home the child computes.
- The child probe is only spawned under an interpreter whose executable name is Python-named; a launcher that resolves to a shell or other runner (possible under `native_python_for`'s existing contract) is not probed and the faithful fallback verifies instead. This is also a hang guard: `sh -c <python source>` can block (measured with an ambient `import` command) rather than fail fast.
- Non-blocking review observation, recorded rather than fixed: the six verified roots exclude `HERMES_KANBAN_ATTACHMENTS_ROOT`; the scrubbing constructors remove every `HERMES_KANBAN_*` name, so only hand-built environments could carry it, and the six-root scope stands unchanged.
- The fallback anchors `kanban_db`/`workspaces_root` for the `default` board; a non-default active board resolves inside the same verified `kanban_home`, which is the root the gate checks, so containment decisions are unaffected.
- `dispatch_until_settled` now refuses a caller that declares no `run_root` (`HarnessError`, mirroring `run_persistent_session`); every in-tree caller declares one.
- `run_persistent_session` now refuses without a declared disposable context; external callers of the exported alias `persistent_session_run` must pass `env`+`run_root` or `run_root`. This is the intended fail-closed change and is recorded as the unit's compatibility impact (`patch`).
- The lab gate resolves `boards_root`/`workspaces_root` through the runtime's native modules; a future Hermes revision that renames a resolver degrades to the environment-derived form (`child_probe: unavailable`) rather than guessing.
