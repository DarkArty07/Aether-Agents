**Inspected base:** Aether `4ece53bfadfd0facbbea3220565841a74a07e97a`; selected executable maintained Hermes fork `aed6591a69f453a1867b73628603e7b53ba40ffc` (`0.20.1`). ## Baseline and deliberate decisions

- The owner-approved Objective Plan method already exists in `specs/r2-contract-and-handoff/spec.md` §3.1, `src/aether_agents/resources/skills/objective-contract-design/SKILL.md` and Morfeo's `SOUL.md`. The Aether skill named `plan` is the **user-invoked entry** only: project resolution, bounded plan-only writing and reference to the canonical method. It is not a second contract designer or a copy of the private learned skill.
- Hermes's selected `hermes_cli/commands.py` has no built-in `plan`. `agent/skill_commands.py:402-495` registers `name: plan` as `/plan` when it does not collide; its sorted same-name discovery means the local learned skill in a nested category must be explicitly tested against the package-owned root `skills/plan/SKILL.md`. This is a selected-runtime behavior gate, not a promise for all future Hermes versions.
- Source skill: `src/aether_agents/resources/skills/plan/SKILL.md`, with portable frontmatter, a single clear planning-only trigger and no private profile material. Native Aether release bundle installs `skills/plan/SKILL.md` **only in Morfeo**. The nine existing canonical skills remain available to each existing role as before. No new loader, registry, profile or core fork change.
- A plan is project-local, ignored by default, and stable per whole objective. Its anticipated Objective Contracts are revisable route markers, **never a cap**, authority transfer or automatic handoff; individual contracts retain R2/R7 attempt and convergence bounds. No plan generated for an unrequested simple question. A literal `/plan` request ends after planning.

## Profile bundle, identities and compatibility

`src/aether_agents/lifecycle.py` currently has one `_CANONICAL_SKILLS` list reused to write, hash, validate, activate, snapshot and uninstall the **same** set in each role. Existing release bundles (`profile-bundle.json` schema 2) contain per-role `skills` maps and release-lock digests. The new shape is deterministic:

| Release shape | Morfeo skills | Supervisor and Implementer skills |
| --- | --- | --- |
| Historical authenticated releases | Existing common set | Existing common set |
| New package candidate | Existing common set plus `plan` | Existing common set |

Material design requirement: use one coherent role-aware source inventory for candidate generation, wheel/sdist resource closure, deterministic profile-bundle SHA, native materialization and *new* release validation. Historical releases are validated against their authenticated stored inventory and exact historical bytes, with only the two known inventory shapes above accepted (not arbitrary self-declared subsets). Keep strict path, digest, symlink, mode, role and resource-set checks; no disabling a drift guard or rewriting historical manifests. The profile-bundle's per-role map can express the new shape without an invented state machine; change schema only if exact tests demonstrate a necessary incompatibility, and report it for design review before handoff. The existing `release-lock` source identity and wheel fingerprint remain binding.

Transition invariants to implement and exercise:

1. Before changing a home, inspect the union of product-owned skills from the *authenticated previous and target releases*. Prove existing owned bytes against the owning release; an unowned target `skills/plan/SKILL.md` is not automatically owned. On initial adoption or upgrade, back up an exact-path pre-existing learned skill before replacing it and retain the receipt. Keep nested `skills/software-development/plan/SKILL.md` and unrelated operator files untouched.
2. Snapshot previous/target-owned paths before transition. On a failed transition, restore exact bytes and selection. On rollback from a candidate with `plan` to a historical release without it, remove only proven managed `plan` bytes, leaving any separately named learned skill and its directory intact. A drifted/unsafe path blocks rather than being deleted. Validate the target's exact role inventory after each transition; no shadow canonical `plan` survives rollback.
3. Update uninstall and doctor/readback paths to use release ownership rather than assuming the current candidate inventory was always installed. Supervisor/Implementer must never receive a `plan` resource in the bundle or their homes.
4. The executing older manager's `LifecycleManager._wheel_profile_bundle_sha256` currently requires an exact wheel resource set, so it rejects a wheel with an extra canonical `plan` **before** the new manager could take over. The chosen compatible source ancestry is: **first** a reader-capable commit retaining the exact old nine-skill profile-resource inventory and adding strict knowledge of the new role-scoped inventory; **then** a candidate commit adding `plan` only to Morfeo and using that reader. The old manager can be tested against a wheel from the first commit without a resource-set change; that reader can then be tested against the second candidate in disposable roots. A commit is not a qualified release: any future bridge and candidate require their own exact package/release proof and separate activation authority. If either isolated transition fails, stop and report that existing installations cannot update directly; do not change installed profiles by hand or claim an upgrade works because fresh install passes.

Implementer may choose internal helper/function names and equivalent local layout, but the role sets, historical shape acceptance, ownership rules and observable rollback above are shared decisions. Keep changes limited to the actual profile bundle/lifecycle seam, relevant docs, tests and the new skill; do not refactor other release mechanisms or introduce global skill routing.

## Verification strategy and route

Testing standard from this repository: `uv run --frozen` and pytest; CI also runs `scripts/run_tests.py` against the exact **public reference Hermes baseline**, docs/public-artifact checks, lint and wheel/sdist build. Native `/plan` dispatch is a **separate** qualification against Aether's exact selected maintained fork, not a result of that public-baseline suite. [quickstart.md](quickstart.md) owns the runnable checks and expected observations. Add focused negative and old/new/rollback cases to existing profile-bundle/lifecycle and package tests; qualify native slash dispatch in an isolated Hermes home and separate static instructions from one actual planning-only run. Do not operate on the live Morfeo profile, active release or other agents' worktrees. Evidence must name the exact candidate revision and test producer; no invented full-suite PASS.

This objective changes packaging, role isolation and mixed-version transitions; independent Supervisor review of role inventory, migration and integration catches material failures that a direct one-file skill edit would miss. Morfeo supplies the design and one finalized Objective Contract; Supervisor owns unit decomposition, independent review, integration and authorized PR closeout. A later source merge has `release_impact` to classify from the final diff; it does not itself authorize `release_action=publish` or `release_channel=stable`.
