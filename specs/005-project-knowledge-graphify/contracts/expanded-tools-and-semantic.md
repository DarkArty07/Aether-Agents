The initial structural-only implementation remains the compatibility baseline. Applies to every bound project, not only the repository implementing Aether.

## Shared model-tool interface

Maintain `aether.project-knowledge.v1` envelopes and old successful call shapes. Additional action-specific output objects are additive. Canonical action discriminators and surviving field descriptions must agree with runtime validation for all roles and supported schema sanitizers.

| Action | New model arguments | Output addition |
|---|---|---|
| `stats` | none | `stats`: node_count, edge_count, community_count, confidence_counts (EXTRACTED/INFERRED/AMBIGUOUS/UNKNOWN), origin_counts (structural/llm/unknown) |
| `god_nodes` | optional top_n=10 (1..50), exclude_hubs_percentile (0..100), budget_tokens | `nodes`: stable native ranking entries {id,label,degree,community_id}; existing references for returned source-bearing nodes |
| `list_prs` | optional base (1..255 chars), limit=20 (1..50), budget_tokens | `github` context and `prs` summary entries; bounded listing, no extraction or per-PR LLM calls |
| `pr_impact` | required pr_number (positive integer); optional budget_tokens | `github`, `pr`, `impact`: files, matched_files, unmatched_files, communities, node_count |
| `triage_prs` | optional base, limit=20 (1..50), budget_tokens | `github`, `prs` summaries plus per-PR impact and community-overlap pairs for review; no automatic approval or merge |
| `visualize` | optional format=graph (`graph` or `tree`), detail=auto (`auto` or `full`, graph only) | `artifact`: id, format, view, revision, snapshot_id, local_path, bytes, sha256, rendered_nodes, total_nodes, aggregated, external_assets |
| `query` | optional traversal=bfs (`bfs` or `dfs`), depth=2 (1..6), context_filter (up to 20 nonempty strings, each <=80 chars) | content and references reflect the actual native traversal/filter; optional query_options receipt |
| `impact` | optional relations (up to 20 nonempty strings, each <=80 chars) | native reverse traversal and references use the same relation selection |
| `path` | optional undirected=false (boolean) | directed/undirected interpretation explicit in content/receipt, references follow the actual returned path |

`budget_tokens` preserves 128..8000 and the existing content/reference caps. Stats is small and accepts no irrelevant budget. No new model-supplied project/repo/URL/output_path/provider/model/secret arguments. Missing optional fields preserve old behavior. Empty successful PR lists are distinguished from unavailable access. Unknown graph filters return empty explicit filtered results, not an unfiltered fallback. Unclassified community IDs remain null. A selected native `context_filter` is now supported; stale recovery advice and tests forbidding that literal unconditionally must be reconciled to distinguish supported query use from unsupported contexts.

GitHub summary entries contain number, title, head_branch, base_branch, head_sha, base_sha, draft, ci_status, review_state and updated_at. `github` contains repository, observed_at and graph_revision; local worktree paths are not returned. Unmatched files are not counted as zero-risk. PR metadata need not imply the graph is indexed at the PR head. The impact is file-to-node/community coverage, not transitive runtime impact or a merge-safety score.

## Semantic data/control flow

1. Resolve the exact bound project/view/commit as today and capture only supported committed Git text blobs through `_sources`. Reuse its secret/path/binary exclusions and size limits. Include eligible project documentation and code; do not crawl another repository, external URL, user home, private notes or arbitrary untracked files. Existing project prohibitions on external processing remain authoritative.
2. The explicit operator component setting `semantic.enabled` governs configured updates. Portable installations remain opt-in until their owner authorizes processing; this deployment is authorized. Configure `semantic.auxiliary_task` to `web_extract` for the initial activation: inspection found this existing text auxiliary route shared across the three roles and a live probe verified it. This task name is a configuration reference, not a new Hermes auxiliary task or permission to use a primary/vision/goal model. An operator can bind another explicit preconfigured text auxiliary. Missing/auto/ambiguous bindings return unavailable, never credential acquisition or implicit primary/provider fallback.
3. Use Hermes's existing profile-scoped auxiliary resolver/client, preserving its configured protocol (including Responses), request cancellation and existing routing attribution. Only the selected connection is used; no newly introduced fallback chain. Backend modules remain lazy imports so structural use and disabled plugins work without Hermes or LLM packages. Explicit CLI semantic use resolves only the explicitly active profile, never last-used role/profile. The exact public Hermes baseline must pass the adapter tests; no private patch dependency.
4. In the isolated Graphify worker, reuse native `_extraction_system(deep=False)`, `expand_oversized_files`, `_pack_chunks_by_tokens` and `_read_files` to prepare bounded text prompts. In the manager, call the configured auxiliary client with those system/user messages and collect response text, finish reason, observed usage and elapsed time. Send output back to the isolated worker for native `_parse_llm_json`, `validate_semantic_fragment`, evidence binding and native graph construction. No monkeypatch of Graphify/Hermes modules or SDKs; this adapts native primitives around the existing transport, not a second semantic extractor.
5. Preserve native packing/slicing without silent truncation. Attach source-backed AST symbol anchors for referenced code to document chunks within the same budget, preferring explicit relative-path references. Do not invent a cross-project/global retrieval mechanism. Include all such context bytes in chunk identity. Native semantic-to-AST normalization during `build_from_json(..., root=captured_root)` maps document relations onto code symbols; verify that document-to-code paths are actually queryable, not disconnected duplicate semantic symbols.
6. Treat model fragments as untrusted. Validate bounded types, source membership and node/edge endpoints. Model outputs cannot name executable effects. A parse failure, empty/hollow output on nonempty sources, length finish or rejected evidence is not full semantic success. Sources outside the captured scope are rejected; a genuine source with no exact locator may retain an empty locator, never a made-up line. Mark new LLM-derived elements with `origin=llm`; model-declared EXTRACTED confidence is not structural proof: use INFERRED (or AMBIGUOUS when unresolved). Preserve raw reported confidence only as untrusted metadata if useful. Existing AST identities, source sites and extracted relations take precedence on collisions.
7. Merge validated fragments with the structural graph through native normalization/build/clustering. Verify every preexisting structural relation is retained by normalized source/target/relation/site identity. If a native simple-graph collision would overwrite structural evidence, retain the structural relation and report the omitted semantic alternative as uncovered; do not silently change the whole graph representation or claim full coverage. Only publish a validated bounded candidate through the existing atomic snapshot/pointer path.

## Snapshot identity, cache and failure behavior

The current per-commit pointer must no longer imply that structural coverage also satisfies a semantic update. Add a semantic fingerprint to manifest/cache qualification: corpus scope version, native engine/prompt digest, extraction policy, selected transport/model identity and full chunk source/context hashes. Persist only non-secret identity/digests. Endpoint credentials and private deployment configuration are not public receipts. Reuse same-project chunks only when all inputs and policy match; never reuse by file content alone across projects or relative-path changes. Deletions/renames invalidate dependent fragments. Rerun native structural extraction as required by the source revision, not the model.

Keep old structural manifests readable. Introduce an optional manifest `semantic` object with state `disabled|pending|complete|partial|unavailable`, fingerprint, covered_paths, pending_paths, failed_paths, validated_chunk_ids and observed usage. `complete` on the outer manifest still means a valid published artifact, not universal semantic understanding. Result envelopes add semantic state/coverage and warnings; `semantic_pending` becomes false only when no eligible semantic work remains (or semantically disabled and explicitly reported). Coverage documents uses semantic only for complete enabled document coverage, partial when some eligible document content is not covered, otherwise structural_only.

- `update(mode=structural)` remains no-LLM and does not downgrade an already complete same-revision semantic snapshot.
- `update(mode=configured)` (default) performs/resumes semantic work when enabled. Repeating unchanged complete work produces zero model calls. Same-commit structural snapshots are eligible for enrichment without another source commit.
- Publish usable current structural coverage even when an auxiliary is unavailable; any successful partial semantic fragments are explicit. Keep a previously complete same-revision snapshot on failed refresh. Never serve a different revision as current. Cross-view snapshots and private memory are not merged.
- Reuse the stable per-view lock and atomic file primitives; hold one publication owner. Cache completed chunks durably before returning deferred work so later authorized updates resume instead of resending everything. Existing readers can use the prior complete artifact. No detached work falsely implied by `deferred`.
- Operator defaults: max_concurrency=2, request timeout capped by the selected auxiliary timeout and 180 seconds, one transient retry per chunk, invocation deadline 600 seconds; bounded values can be configured without changing model-tool arguments. These are operational bounds, not monetary caps. Successful partial work is retained at deadline. Router exhaustion fails/defer visibly; no endless retries or alternate accounts/providers. Cancellation stops new requests and worker processes, retains already validated cache and never publishes unfinished state.
- Skills instruct agents to perform/resume configured updates at coherent committed checkpoints, including integrated main before closeout, whenever project work changed covered sources. No model call on query/status/greetings, no watcher or mandatory separate human semantic request. One bounded retry is allowed for temporary failures; persistent unavailable/deferred work is reported, not an infinite loop to force completion.

## Optional GitHub boundary

Do not check out, fetch foreign heads, approve, comment or merge from these tools. Ordinary authorized project closeout still uses its existing separate workflow.

CLI `prs --triage`'s extra LLM ranking is not invoked. GitHub unavailable must not disable any local graph action.

## Native visualization boundary

Output path is an intentional local artifact handle, not permission to reveal the snapshot cache path or private source roots in content. No arbitrary filename/URL/HTML override enters tool arguments.

`detail=auto` uses native aggregation above its 5,000-node visualization threshold; `full` explicitly renders all nodes within existing graph size bounds. Report aggregation, rendered/total nodes and external assets. Tree follows the native document/module hierarchy and discloses native child grouping. The HTML identifies project/revision and makes INFERRED vs structural evidence visible where supplied by native styling. Preserve native HTML escaping. Do not inline credentials/private notes. Known native external visualization libraries are disclosed; no source data is uploaded. Do not open a browser or add a server. Give the human a verified file link/path and the short platform-appropriate opening instruction.
