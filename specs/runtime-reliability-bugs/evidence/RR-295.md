## 1. Outcome Summary

Explicit HTTP 503/529 error bodies containing the reported pool exhaustion phrase `"no available Codex accounts"` (matched case-insensitively in bounded error text) are classified as non-retryable `FailoverReason.server_error` with `should_fallback=True` after context overflow handling and before generic overload handling. Guessed or un-evidenced structured error codes (such as `pool_exhausted`) are not treated as exhausted-pool fallback and remain generic overload.

This allows the conversation loop caller to activate an already configured fallback candidate immediately without burning same-route retries against an exhausted pool. When no secondary is configured, or when all configured candidates fail, execution terminates cleanly with a bounded honest failure. Generic 503 overload backoff, context overflow handling, and partial-stream/tool-effect protections (including unrepeated execution of completed tool sentinels) are strictly preserved and verified through executed tests.
