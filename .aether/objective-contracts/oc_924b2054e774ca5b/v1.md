# Objective Contract: Repair routine per-flow Morfeo and Supervisor instance affinity (#211)

## Owner Intent

Christopher wants Aether’s existing work ordered and then Aether dogfooded to improve itself without overengineering. Existing issues may be resolved when current evidence supports them. The accepted flow has one owner-facing persistent Morfeo instance and one Supervisor instance per execution flow; only Implementer is intentionally replicable. Terminal results must return to the originating Morfeo TUI. Any newly discovered bug outside this objective is recorded in GitHub and stops the run for owner/Morfeo design.

## Objective

Resolve GitHub issue #211 for the ordinary no-crash path. A real Morfeo → Supervisor → Implementer(s) → review/integration flow must preserve the originating Morfeo session and one actual Supervisor session/process for that flow, then return terminal board state to the originating Morfeo TUI without spawning routine replacement Morfeo or Supervisor workers.

## Decisions and Assumptions

Decisions: (1) instance identity means the concrete session/process within one flow, not merely a profile name; (2) #212 is closed because the loaded Hermes and upstream now provide a TUI subscription poller that both displays the event and starts an agent turn; (3) use existing native Hermes capabilities before adding Aether machinery; (4) crash/unavailable-instance replacement is not decided here—on loss of the persistent Morfeo or Supervisor instance, stop and preserve durable state rather than silently replace it. Assumption supporting (4): the owner approved routine per-flow affinity but did not choose the recovery exception. Assumption supporting the scope: issue #211’s observed routine duplication remains reproducible from current Supervisor lifecycle instructions, which finish the decomposition card after fan-out.

## In Scope

Inspect current loaded Hermes and current upstream for a native bounded mechanism; reproduce the routine duplication on an isolated board; make the smallest project/runtime, profile-instruction, and canonical-design changes necessary to preserve per-flow Morfeo and Supervisor instance affinity; add regression coverage; and execute one real isolated end-to-end flow through implementation, review/integration, and return to the originating TUI.

## Out of Scope

Crash recovery or replacement-session semantics; A2A; a fourth role or new profile; Telegram as a required return channel; a generic workflow engine/controller; release, packaging, deployment, credentials, provider/model changes, or public upstream publication; unrelated Kanban cleanup, historical graph migration, telemetry work, and issues other than #211 except a newly found blocker recorded under the stop protocol.

## Authority

Supervisor may inspect the verified Aether project and loaded/upstream Hermes sources, decompose this contract, and integrate locally reversible project changes after independent review. Implementers may modify isolated project-linked worktrees and run local tests. Existing provisioned models and credentials may be used for the requested real pipeline exercise. No role may push, publish, deploy, restart owner services, acquire/widen credentials, spend outside existing provisioned routing, change product intent, decide crash recovery, or perform irreversible/destructive effects. Morfeo alone revises this contract and communicates with the owner.

## Deliverables

1. A minimal implementation that preserves routine per-flow Morfeo and Supervisor instance affinity. 2. Canonical design and shipped Supervisor/Morfeo profile instructions reconciled with the implemented mechanism, without duplicating Hermes lifecycle rules. 3. Focused regression tests and an isolated real-board E2E record identifying session/process IDs, cards, transitions, and return event. 4. Updated GitHub issue #211 with exact evidence and disposition. 5. If a generally useful Hermes defect is proven, a local patch record with upstream retirement gate; no remote PR without separate authority.

## Acceptance Criteria

A passing run must prove all of the following: (1) the originating Morfeo TUI creates one contract/root handoff and receives the final/blocked event back in that same session; (2) no ordinary card in the flow dispatches a replacement Morfeo; (3) one concrete Supervisor session/process owns decomposition, later review/convergence, and integration for the full routine flow; (4) one or more Implementers may run in isolated worktrees; (5) a contract defect returns to originating Morfeo without a fresh Morfeo worker; (6) process/session IDs and board events demonstrate the topology, not profile names alone; (7) if the persistent Morfeo or Supervisor disappears, the flow remains durable and stopped rather than silently replacing it; (8) existing unrelated tests do not regress and protected-effect boundaries remain intact.

## Testing Standard

Testing standard: reproduce the current routine duplication first (RED) on an isolated board using the real loaded Hermes executable and real profiles; add focused unit/integration regressions for the chosen mechanism; run the complete directly affected Hermes/Aether test selections and compare failures with a pre-change baseline; then run one controlled real E2E with provisioned live models from the originating Morfeo TUI through one persistent Supervisor, at least one Implementer, review/integration, and return. Record session IDs, PIDs, task/run IDs, Git commits/diffs, commands, exit codes, and durable board handoffs. A fixture-only or profile-name-only proof is insufficient. Stop on the first new bug outside #211, create/update its GitHub issue with reproduction evidence, and return to Morfeo/owner before repairing it.

## Stop Conditions

Stop and block without workaround when: the verified project marker/path/digest conflicts; no current native or bounded project mechanism can preserve one actual Supervisor instance without a generic controller or downstream-only product dependency; the persistent Morfeo or Supervisor instance exits; crash-recovery semantics become necessary; a protected effect or new credential/spend is required; acceptance would require weakening role separation, review, worktree isolation, or protected-effect guards; or the first distinct bug appears. A distinct bug must be recorded in GitHub with evidence, and design returns to Morfeo and the owner.
