# Objective Contract: Opt-in Claude Code executor for Implementer work attempts (#563)

## Owner Intent

The owner wants other agent harnesses to act as Aether's Implementer so Aether can use each harness's quotas, offers and particularities, starting with Claude Code. Hermes stays the infrastructure and the default executor for every role. On 2026-09-30 the owner explicitly authorized implementing this functionality as the bounded exception to the PD-74 feature freeze, approved the DESIGN.md PD-40 amendment, approved delivering the worker-launcher override through an Aether plugin already loaded in the gateway, confirmed that the Kanban board remains the only way work moves between roles, and excluded any release, managed update, installed activation or tag. The owning accepted decisions are specs/external-implementer-harness/spec.md section 1 (OD-1 to OD-10), DESIGN.md PD-40 (owner amendment 2026-09-30) and R6 FR-611b. Issue #563 represents this objective.

## Objective

Deliver one reviewed, verified source increment, integrated through the repository's normal green PR/merge path, in which a contract carrying the optional structured selection implementer_harness=claude-code runs its eligible Implementer work attempts through the official, unmodified Claude Code CLI: with the owner's own Claude configuration and session, without permission prompts, with the PD-71 guard as a blocking fail-closed pre-tool hook, with the Implementer role context and canonical skills, and with a per-attempt worker MCP surface over the native board tools. When Claude cannot work an attempt, that attempt falls back statelessly to Hermes inside the same claim. Without a selection, contract and execution-board bytes stay identical and every attempt still runs the Hermes entry the dispatcher would have resolved, with the argv and environment it built; the only addition is the launcher hop. Material design, shared interfaces and runnable checks are owned by specs/external-implementer-harness/{spec,plan,research,quickstart}.md. The outcome is accepted source plus one isolated real run; it is not installed availability, a release or behavioral qualification.

## Decisions and Assumptions

Decided by the owner (spec.md section 1, OD-1 to OD-10): selection per contract only on the owner's explicit request, with Hermes as the default and no Morfeo proposal or question otherwise; no permission prompts (bypassPermissions enabled and verified per run) while PD-71 stays a blocking pre-tool check; stateless per-attempt fallback with no global state, circuit breaker or failure memory; Aether adds only its minimum requirements and never manages, isolates or curates the user's harness configuration; role skills reach every harness from the single canonical source; goal-mode cards stay on Hermes; minimal verification with real calls permitted; implementation only, with no release or activation; HERMES_BIN delivered in-process by the Morfeo-profile Aether plugin, not by a systemd drop-in (excluded by the A1 #487 reconciliation) nor the credential .env; PD-40 amended. Morfeo's delegated technical decisions (plan.md section 3; research.md section 4): the shared identifiers in plan section 3.1; the optional front-matter key is tolerated by rc17 readers (store.py parser/validation read at 4bbf8ac2), so no new artifact type is introduced; eligibility per plan section 3.5, with every routing uncertainty resolving to Hermes; all review attempts, including an Implementer-assigned independent review, and cards with Hermes model/effort pins stay on Hermes; fallback by execv within the same claim, PID and remaining deadline, at most once per attempt; A2A stays unused (R6 FR-606 reconsidered). Assumed, to be verified during construction on the exact Claude version, with stop conditions if false: the readiness sequence (stream-json input gating plus a SessionStart nonce) can withhold the work prompt until MCP, bypass and hook are proven active; the PD-71 hook and worker MCP coexist with the user's own configuration; the flags checked on Claude Code 2.1.284/2.1.285 remain valid. Locally delegated (plan section 5): module and file names other than the section 3.1 identifiers, internal structure, readiness mechanics within its invariant, heartbeat rate, receipt layout and equivalence-table wording. Supervisor owns decomposition, sequencing, review and integration; Implementer owns equivalent local reversible choices without changing shared boundaries. Compatibility conclusions: release_impact=minor; release_action=defer; release_channel=none.

A missing prerequisite or an unrelated CI/infrastructure failure is an explicit blocker, not a fabricated PASS or permission to weaken gates. Follow canonical Supervisor review convergence: at most two ordinary returns per logical unit, with no reset by new cards or versions; a recurring common-cause failure or an exhausted budget requires a bounded repair or an explicit Morfeo design/recovery decision, never automatic acceptance. Once all supported outcomes and normal closeout are verified, finish; no ceremonial successor, release or extra harness is required.
