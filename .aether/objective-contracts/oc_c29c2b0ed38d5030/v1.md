# Objective Contract: Canonical project-local /plan skill for Morfeo (#504)

## Owner Intent

The owner uses literal `/plan` with Morfeo to give a complete objective a beginning, scope, history and defensible end, not to fragment it into endless iterations. The Objective Plan belongs to the selected project under `.aether/plans/` and complements, rather than replaces, Objective Contracts: each contract delegates an authorized portion; the count of contracts is not capped, but every continuation must be justified against the remaining owner objective. The generic Hermes plan skill is not the desired Aether behavior. Ship an Aether-owned canonical `plan` skill to Morfeo in the source/package, update user-facing and canonical documentation, and integrate through the normal green main-line path while leaving other agents' sessions, worktrees and active profiles untouched. Publication, local release selection and activation are separate future decisions.

## Objective

Implement and independently verify issue #504 as one product objective at the explicitly bound Aether Project. Deliver a portable, package-owned, native slash skill named `plan` for Morfeo only; in the selected maintained Hermes fork it must resolve `/plan`, remain planning-only, and create/update one stable Objective Plan per owner objective within the exact selected project's `.aether/plans/`. Preserve the existing `objective-contract-design` method and all other roles' skill inventories. Extend release/profile resource handling only as needed for strict role-aware and historical inventory verification, adoption, compensation, rollback and safe future upgrade qualification. Reconcile R2, the Objective Plan guide, capability references and affected tests with observed implementation; integrate reviewed source to main by normal PR/check gates. Acceptance is the verified source result and explicit compatibility limits, not a release, installation or a claim that every future model turn will behave perfectly.

## Decisions and Assumptions

Material decisions are owned in `specs/plan-skill-productization/{spec,plan,research,quickstart}.md` and R2-FR-204f. The skill frontmatter name is `plan` (literal `/plan` in selected fork), a focused entry that defers deeper method to `objective-contract-design`. A project-local plan is reused by exact identity; contract numbers are a revisable forecast, not a quota. Keep the nine existing common canonical skills for every role and add `plan` only to Morfeo through a strict per-role, per-authenticated-release inventory; the schema-2 profile bundle already has per-role skill maps. Preserve old exact shapes and hashes, avoid accepting arbitrary manifest entries, and prove ownership before modifying managed bytes. The selected executable Hermes fork is pinned to `aed6591a69f453a1867b73628603e7b53ba40ffc` (`0.20.1`), where `/plan` is dynamic; public newer documentation about built-in `/plan` is not target-runtime proof. Direct old-manager wheel readback has an exact-resource-set incompatibility: source ancestry must first provide a reader-compatible, old-shape commit, then a new-shape candidate, qualified in disposable roots; no bridge release/activation follows automatically. Aether Project identity must be explicit; absent/ambiguous identity means no write or auto-init. Internal helper names and equivalent local implementation remain Implementer judgement.
