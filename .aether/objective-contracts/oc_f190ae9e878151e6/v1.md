# Objective Contract: Qualify active-manager bootstrap and finish local rc4 activation

## Owner Intent

Restore the blocked local Aether activation path without weakening active-manager authority, moving immutable tags, patching the live runtime or losing state. Qualify a safe one-time bridge from the current rc3 manager to the already reviewed rc4 manager, then finish the launcher/Graphify objective and leave a truthful permanent-defect record for #485.

## Objective

Independently review and prove in disposable roots a two-hop promotion using only existing guarded lifecycle commands: active rc3 prepares/activates a local-only metadata-stable bridge manager built from the exact merged rc4 code, then that bridge manager prepares/activates the immutable final rc4 candidate with release-owned TUI and branded projections. Only after the proof passes, execute the same sequence from a durable transient user unit, verify final rc4 and resume the terminal canaries/closeout of `oc_ff82ba151cdf3861@v2`.

## Decisions and Assumptions

Delegated decisions and assumptions:

- Route through Supervisor/Implementer because this is a release-authority/bootstrap design with live cutover consequences; the prior bounded recovery is closed and no third ad-hoc variant is allowed.
- The bridge identity is local package `1.0.0a4`, display `1.0.0-a.4`, annotated local tag `v1.0.0-a.4`. It is one VERSION-only commit based on merged rc4 commit `5a897746afe422f3c07f2290f9115d60204ef4d2`; independent review proves no other byte differs. PEP 440 preserves `1.0.0a4` literally in wheel metadata.
- The failed experimental bridge refs were removed. The pipeline recreates fresh reviewed bridge refs; no prior scratch commit/tag is authority.
- The disposable proof and live transition invoke the current manager from its resolved immutable release path, never through the `runtime/current` symlink. Private-path refusal remains firm.
- The bridge is never a user candidate: no doctor acceptance, launcher canary, public claim or ordinary workload occurs there. It exists only long enough for its authenticated manager to prepare final rc4.
- Final rc4 remains package `1.0.0rc4`, tag `v1.0.0-rc.4`, exact merged commit `5a897746…`, maintained fork `aed6591…`. Its source/tag bytes are immutable and are not rebuilt by moving the tag.
- The local-only bridge branch/tag/release are retained as audit evidence after success; they are never pushed or published. #485 remains open for a permanent single-hop candidate-manager protocol unless the implementation adds and independently qualifies that source fix without delaying the activation objective.
- Release conclusions: bridge `none/defer/none`; final rc4 retains `patch/prepare/prerelease`. No stable/public release or WSL2 qualification follows.
- Assumption: rc4 `ReleaseRecord.from_json` intentionally accepts missing TUI fields from an rc3-created bridge, while active-manager authority excludes runtime/TUI health, so the bridge manager can authorize the second hop. This must be proven, not inferred.

## In Scope

In scope:

1. Reproduce #485 against exact rc3/merged-rc4 identities and verify the active-manager dispatch premise.
2. Create and independently review the VERSION-only local bridge commit/tag.
3. Build a disposable two-hop fixture using isolated XDG data/state/config/cache/home, confined projections and disabled service effects; use the resolved immutable rc3 manager path.
4. Prove rc3→bridge and bridge→final-rc4 preparation, registration, authority checks, selector transitions, TUI asset/provenance and final doctor state.
5. Record pre-live state and run the same two hops in one durable transient user unit with bounded phase receipts and supported lifecycle commands only.
6. Verify final rc4 and resume the existing LG-CLOSE acceptance: launchers, source immutability, Graphify configured-update canary, state preservation, issue reconciliation and cleanup.
7. Preserve issue #485 evidence and document whether the bridge is only a one-time recovery or a supported repeatable procedure.

## Out of Scope

Out of scope:

- Patching live rc3 files, deleting or editing active/release records, bypassing manager authority/private-path checks, changing `runtime/current` manually, replaying `.patch` evidence, or invoking a candidate manager as if already active.
- Moving/deleting/recreating `v1.0.0-rc.4`, mutating merged rc4 source, or treating the bridge as accepted rc4.
- Public bridge/rc4 tag push, GitHub Release, PyPI/OIDC, stable 1.0.0, manual deployment, another installation or WSL2/native-Windows qualification.
- Uninstall/purge, state rollback, cleanup of prior rc1/rc2/rc3 releases, credential/provider/model changes, or unrelated lifecycle refactoring.
- A generalized permanent bootstrap protocol unless required by evidence to make the bounded bridge safe; #485 owns that later source objective.

AC-3 — First hop: rc3 manager prepares/registers/activates the bridge with exact candidate evidence. The bridge release may lack rc4 TUI/projections and may have unavailable doctor, but its manager identity/active-record authority validates. No normal workload or canary runs in the bridge.

Final release contains hash-bound TUI/provenance and branded projections; selector, active record, manager/runtime wheel identity, fork digest and tag agree. One durable transient unit executes both reviewed hops with phase receipts outside the repository. Aether-owned interruptions are bounded; projects, boards, sessions, credentials, knowledge, observations and profiles remain present. On first-hop failure no final hop runs; on second-hop failure retain the bridge manager/evidence and use only supported retry/rollback disposition.

AC-6 — Final user outcome: installed `aether`, `Aether` and `Continue Aether` reach exact project-bound Morfeo; real TUI start/exit creates no `node_modules`/symlinks/build debris in locked `hermes-source` and source digest/doctor remain stable. One configured Project Knowledge update returns a terminal receipt inside its operation/host bounds with no hidden continuation; route/fallback limits are reported honestly.

AC-7 — Closure: #480/#481/#482 close only on final live evidence. #485 records whether the bridge is a qualified one-time path and remains open for permanent single-hop repair unless that repair was separately implemented/reviewed. No public bridge/rc4 release effect exists; reviewed rc4 and prior tags/releases remain immutable.

## Stop Conditions

Stop on any project/contract/repository/tag ambiguity; bridge diff beyond the authorized VERSION byte; version normalization mismatch; dirty or wrong-origin checkout; another tag at either candidate commit; failure to resolve the immutable rc3 manager path; any disposable proof access to live XDG/service paths; rc3 inability to register the bridge; bridge inability to authenticate its rc3-created record; final rc4 release-id collision/incomplete TUI/projection; red focused/review/required check; need to edit records/selectors or bypass private-path/authority checks; unexpected service/state loss; hidden/pending transition; public tag/branch/release effect; or need for another ad-hoc recovery variant. Do not start live mutation until the disposable proof and independent review pass. If a live first hop fails, preserve rc3 and stop; if the second hop fails, preserve the bridge and use only the contract's supported recovery disposition.
