# Objective Contract: Qualify active-manager bootstrap and finish local rc4 activation

## Owner Intent

Restore the blocked local Aether activation path without weakening active-manager authority, moving immutable tags, suppressing integrity checks or losing state. First restore the contaminated active rc3 Hermes source exactly to its authenticated release-lock bytes through a reviewed atomic quarantine/swap with rollback; then use the already qualified one-time bridge to reach final rc4, finish launcher/Graphify acceptance and retain truthful evidence for #481/#485.

## Objective

Independently review and prove that the active rc3 source differs from exact fork `aed6591…` only by runtime-created npm/TUI extras, materialize and harden a clean archive with the exact release-lock digest, and atomically swap it into the active release while quarantining the contaminated tree and retaining immediate rollback. Then execute the already reviewed two-hop promotion using guarded lifecycle commands: restored rc3 prepares/activates the local-only bridge manager, the bridge prepares/activates immutable final rc4 with release-owned TUI/projections, and final launcher/Graphify canaries close the original objective.

## Decisions and Assumptions

Delegated decisions and assumptions:

- Route through Supervisor/Implementer because this is a release-authority/bootstrap/restoration design with live cutover consequences. The previous live refusal is preserved as correct evidence; no retry occurs under v1.
- Exact source restoration is rollback to authenticated release bytes, not an integrity exception: materialize `git archive` of maintained-fork `aed6591…`, require `_tree_sha256 == cc1ebf94…`, compare every expected relative file/type/hash, and proceed only when expected files have zero missing/changed entries and every live extra is confined to `node_modules/**`, `ui-tui/node_modules/**` or `ui-tui/dist/entry.js`.
- The clean tree is built as a sibling on the same filesystem, hardened with the lifecycle's private-tree procedure, and swapped atomically only after Aether-owned gateway/TUI processes are quiesced by the durable unit. The contaminated tree is atomically quarantined outside the release and never deleted in this objective. Any failed post-swap validation immediately restores it.
- rc3 `validate_release`, source digest and doctor must become ready before hop 1; restoration that merely suppresses the error is refused. Runtime/current, active/record JSON, manager/runtime environments, wheel artifacts, profiles and mutable state are not edited.
- The bridge identity remains local package `1.0.0a4`, display `1.0.0-a.4`, annotated local tag `v1.0.0-a.4`, one VERSION-only commit based on merged rc4 `5a897746…`. Prior failed scratch refs remain non-authoritative; consume the independently reviewed bridge evidence.

- Final rc4 remains package `1.0.0rc4`, immutable tag `v1.0.0-rc.4`, merged commit `5a897746…`, fork `aed6591…`. The tag is never moved.
- Local bridge branch/tag/release and quarantined rc3 contamination are retained as audit evidence after success and never pushed/published. #485 stays open for a permanent single-hop protocol; #481 may close only after final rc4 proves normal TUI use no longer recreates contamination.
- Release conclusions: restoration and bridge `none/defer/none`; final rc4 `patch/prepare/prerelease`. No stable/public release or WSL2 qualification follows.
- Assumption to prove: rc4 `ReleaseRecord.from_json` accepts missing TUI fields from the rc3-created bridge while active-manager authority excludes runtime/TUI health, enabling hop 2 after restored rc3 makes hop 1 legal.
