# Objective Contract: Reconcile active local Hermes patches for release preflight

## Owner Intent

Dogfood the real Aether Morfeo → Supervisor → Implementer system on useful Aether maintenance. Advance preparation for the eventual final-release objective without performing a release. Use the flow itself to detect autonomy, routing, Project/worktree, review, and evidence defects. A material new Aether defect must be surfaced to Morfeo, recorded as a GitHub issue before repair, and explained to the owner by Telegram; work then follows bounded recovery when the defect blocks this objective.

## Objective

Produce a verified, reproducible release-preflight reconciliation of every Hermes patch entry currently marked ACTIVE_LOCAL in HERMES_LOCAL_PATCHES.md against the latest inspected public upstream state, and integrate the resulting maintenance evidence into Aether. The result must state which hunks remain required, which have qualified upstream equivalents, what blocks retirement, and whether each portable patch artifact is internally consistent. The effective Hermes checkout must remain unchanged.

## Decisions and Assumptions

Delegated decision: use patch reconciliation as the maintenance objective rather than implementing the final release. Assumption: the owner wants useful release preparation that remains fully reversible and exercises independent parallel investigation. Delegated decision: upstream equivalence is behavioral and test-backed, never inferred from a merged PR number or similar source text. Assumption: HERMES_LOCAL_PATCHES.md retirement gates are canonical unless contradicted by the owner's current instruction. Delegated decision: retain ACTIVE_LOCAL whenever evidence is missing or partial; uncertainty must not retire a guarantee. Assumption: no target immutable Hermes baseline has yet been owner-selected, so this objective may recommend candidates but may not select or activate one.

## In Scope

1. Enumerate every current ACTIVE_LOCAL, ACTIVE_LOCAL_E2E_QUALIFIED, candidate, partial, verified, open, or missing upstream disposition in HERMES_LOCAL_PATCHES.md without silently omitting combined entries. 2. Inspect the current public upstream repository plus every linked issue, PR, and commit needed to establish present state. 3. Compare required Aether behavior and retirement gates to upstream behavior by hunk and executable evidence. 4. Validate each versioned patches/hermes artifact referenced by the ledger for parse/apply/reconstruction integrity when its documented base and reconstruction inputs exist. 5. Produce a bounded, versioned, secret-safe machine-readable reconciliation artifact and a human-readable summary under the existing productization evidence surface. 6. Update HERMES_LOCAL_PATCHES.md only for evidence-backed status, target, hash, artifact, or retirement-gate corrections. 7. Update #261 with a concise link to integrated evidence after merge. 8. Exercise the real Aether pipeline and record proportionality evidence relevant to #251: time/event ordering to first child, Project binding, goal_mode use, child size, and absence/presence of residual cards after stop/recovery.

## Out of Scope

No tag, GitHub Release, package-index publication, OIDC configuration, deployment, production activation, service restart, credential/authentication change, or protected environment mutation. No update, checkout switch, port, rebase, patch application, or edit of the effective Hermes runtime. No implementation of the placeholder init/start/stop/restart/status/reconcile commands. No selection of the final upstream/fork runtime strategy. No release-ready or production-ready claim. No unrelated cleanup, issue backlog work, or retirement of a patch without its full behavioral gate.

## Authority

The owner authorizes local reversible repository work, public read-only upstream inspection, tests, branches, commits, a pull request, protected CI, and merge after independent review and required checks pass. The owner also authorizes creation of a GitHub issue for every material new defect discovered. Morfeo alone handles Aether/Hermes recovery when the pipeline mechanism itself blocks the objective and sends the owner a Telegram explanation. No worker may widen credentials, authenticate a new account, publish artifacts, deploy, activate a service, modify the effective Hermes checkout, or decide the final release/runtime strategy. Owner authority remains required for every excluded external or release effect.

## Deliverables

1. Versioned machine-readable reconciliation with one record per ledger entry, upstream identity inspected, required behavior, current disposition, evidence references, artifact verification result, retirement recommendation, uncertainty/blocker, and timestamp/source provenance without machine-local secrets. 2. Human-readable release-preflight summary explaining remaining runtime blockers and safe next decisions for #261. 3. Evidence-backed ledger corrections, if any. 4. Automated validation preventing omitted entries, duplicate IDs, invalid dispositions, unverified retirement, stale artifact hashes, or schema drift. 5. Pull request with independent review and protected CI evidence. 6. Durable dogfood report describing the actual Aether flow and any system defects separately from product findings. 7. GitHub issues for any material new defects, created before their repair.

## Acceptance Criteria

A. Every ledger entry requiring local behavior appears exactly once in the machine-readable reconciliation and maps back to the canonical ledger. B. Every status/recommendation is supported by current upstream identity plus executable or source-level evidence appropriate to its retirement gate; merged/open labels alone never prove equivalence. C. Missing or partial evidence preserves the local requirement and is reported as a blocker/unknown, not guessed. D. Every referenced versioned patch artifact that can be reconstructed passes checksum and byte/apply validation; unavailable reconstruction inputs are explicit, not silently passed. E. The report and validator are deterministic modulo an explicit observation timestamp and upstream revision, secret-safe, portable, and build/package safe. F. The effective Hermes source/runtime bytes, active gateway/service identity, credentials, profiles/configuration, memories, existing unrelated sessions, unrelated board records, and user/project data are unchanged by the objective. The new Kanban tasks, worker sessions, observation records, Git worktrees, branches, commits, PR/CI records, and evidence created specifically to execute this authorized objective are expected mutations and are excluded from that immutability assertion. G. Existing affected tests, the full repository suite, CI-equivalent static/build/public-artifact checks, and independent review pass. H. A protected PR merges to main without bypassing checks. I. #261 receives the integrated preflight result but stays open; no release claim is made. J. The dogfood flow uses the exact Aether Project, creates a useful child graph before context compression, preserves Project/worktree isolation, avoids unnecessary goal_mode, and leaves no unintended runnable/residual cards other than explicitly superseded administrative history. K. If a material Aether runtime defect is observed, an Aether GitHub issue exists before repair and the owner has received a Telegram explanation.

## Testing Standard

Testing standard explicitly selected for this maintenance objective: use RED→GREEN behavioral tests for any new parser, schema, validator, or status rule; run focused tests for every touched component; run deterministic checksum/apply/reconstruction controls over all referenced patch artifacts; run the complete locked Aether test suite; run compileall, Ruff check, Ruff format check, git diff check, package build, and public/private artifact-boundary validation; execute the final preflight against a clean Aether checkout and an explicitly provided read-only copy or identity of the effective Hermes checkout; obtain independent code/evidence review; require all protected CI checks green before merge. Live-model output is not acceptance evidence for patch equivalence. No live provider evaluation beyond the authorized Aether worker flow is required. A test may skip only for a documented platform-inapplicable condition, never because evidence is absent.

## Stop Conditions

Stop and return to Morfeo if the Project identity/path is ambiguous, the effective Hermes checkout would need mutation, an upstream or artifact source cannot be inspected without new credentials, a protected/release effect is required, or evidence would expose secrets/private state. A material Aether/Hermes routing, affinity, worktree, review, notification, lifecycle, or observation defect stops normal expansion and emits durable recovery context; Morfeo creates the issue and applies bounded recovery only when it blocks this objective. Stop rather than inventing evidence if upstream equivalence cannot be demonstrated. Stop release work at the verified preflight result; do not tag, publish, deploy, restart, activate, or select the final runtime strategy.
