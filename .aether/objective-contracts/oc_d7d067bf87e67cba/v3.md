# Objective Contract: Reconcile active local Hermes patches for release preflight

## Owner Intent

Dogfood the real Aether Morfeo → Supervisor → Implementer system on useful Aether maintenance. Advance preparation for the eventual final-release objective without performing a release. Use the flow itself to detect autonomy, routing, Project/worktree, review, and evidence defects. A material new Aether defect must be surfaced to Morfeo, recorded as a GitHub issue before repair, and explained to the owner by Telegram; work then follows bounded recovery when the defect blocks this objective.

## Objective

Produce a verified, reproducible release-preflight reconciliation of every Hermes patch entry currently marked ACTIVE_LOCAL in HERMES_LOCAL_PATCHES.md against the latest inspected public upstream state, and integrate the resulting maintenance evidence into Aether. The result must state which hunks remain required, which have qualified upstream equivalents, what blocks retirement, and whether each portable patch artifact is internally consistent. Normal reconciliation work must not mutate the effective Hermes checkout or service. Separately authorized, issue-first Morfeo recovery effects already required to keep this dogfood flow operable are excluded from that no-mutation claim only when their issue, pre/post identity, portable patch, tests, owner notification, and final loaded state are explicitly retained as evidence.

## Decisions and Assumptions

Delegated decision: use patch reconciliation as the maintenance objective rather than implementing the final release. Assumption: the owner wants useful release preparation that remains fully reversible and exercises independent parallel investigation. Delegated decision: upstream equivalence is behavioral and test-backed, never inferred from a merged PR number or similar source text. Assumption: HERMES_LOCAL_PATCHES.md retirement gates are canonical unless contradicted by the owner's current instruction. Delegated decision: retain ACTIVE_LOCAL whenever evidence is missing or partial; uncertainty must not retire a guarantee. Assumption: no target immutable Hermes baseline has yet been owner-selected, so this objective may recommend candidates but may not select or activate one. Delegated recovery decision: v3 reuses the accepted v2 implementation/rework evidence and existing integration candidate; it creates no duplicate normal Implementer graph. The new Supervisor flow may create only the minimal terminal review/integration handoff needed to finish against v3.

## Out of Scope

No tag, GitHub Release, package-index publication, OIDC configuration, deployment, production activation, credential/authentication change, protected environment mutation, or final runtime-strategy selection. Normal objective work may not update, switch, port, rebase, apply patches to, edit, restart, or activate the effective Hermes runtime. The already completed issue-first bounded recoveries #262/HLP-262 and #226/HLP-226b are historical recovery inputs to v3, not authority for further runtime mutation. No implementation of placeholder init/start/stop/restart/status/reconcile commands. No release-ready or production-ready claim. No unrelated cleanup, issue backlog work, or retirement of a patch without its full behavioral gate.

## Authority

The owner authorizes local reversible repository work, public read-only upstream inspection, tests, branches, commits, a pull request, protected CI, and merge after independent review and required checks pass. The owner also authorizes creation of a GitHub issue for every material new defect discovered. Morfeo alone handles Aether/Hermes recovery when the pipeline mechanism itself blocks the objective and sends the owner a Telegram explanation. No worker may widen credentials, authenticate a new account, publish artifacts, deploy, activate a service, modify the effective Hermes checkout, or decide the final release/runtime strategy. Owner authority remains required for every excluded external or release effect.

Authorized objective-created Kanban/session/observation/worktree/branch/commit/PR/CI/evidence records are expected mutations. ## Testing Standard

Testing standard explicitly selected for this maintenance objective: use RED→GREEN behavioral tests for any new parser, schema, validator, or status rule; run focused tests for every touched component; run deterministic checksum/apply/reconstruction controls over all referenced patch artifacts; run the complete locked Aether test suite; run compileall, Ruff check, Ruff format check, git diff check, package build, and public/private artifact-boundary validation; execute the final preflight against a clean Aether checkout and an explicitly provided read-only copy or identity of the effective Hermes checkout; obtain independent code/evidence review; require all protected CI checks green before merge. Live-model output is not acceptance evidence for patch equivalence. No live provider evaluation beyond the authorized Aether worker flow is required. A test may skip only for a documented platform-inapplicable condition, never because evidence is absent.

## Stop Conditions

Stop and return to Morfeo if the Project identity/path is ambiguous, a new effective-runtime mutation would be required, an upstream or artifact source cannot be inspected without new credentials, a protected/release effect is required, or evidence would expose secrets/private state. The historical #262/#226 recovery mutations are accepted inputs only when fully evidenced under acceptance F; they do not authorize another repair. A material new Aether/Hermes routing, affinity, worktree, review, notification, lifecycle, or observation defect stops normal expansion and emits durable recovery context; Morfeo creates the issue and applies bounded recovery only when it blocks this objective. Stop rather than inventing evidence if upstream equivalence cannot be demonstrated. Stop release work at the verified preflight result; do not tag, publish, deploy, restart, activate, or select the final runtime strategy.
