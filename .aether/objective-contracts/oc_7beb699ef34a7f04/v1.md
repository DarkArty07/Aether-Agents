# Objective Contract: Repair Graphify knowledge-tool contract defects #324-#327

## Owner Intent

The owner authorizes Aether to autonomously resolve GitHub issues #324, #325, #326 and #327 as one coherent Graphify knowledge-tool integration repair. The objective includes contract-aligned implementation, regression tests, current documentation and canonical skill updates, independent review, Git/GitHub integration, and reconciliation of the four issues. It does not authorize modifying or forking Graphify or Hermes, activating profiles, spending through model providers, publishing a release, deploying, acquiring credentials, or widening protected effects.

## Objective

Repair the Aether boundary around the pinned Graphify 0.9.54 component so every project_knowledge/work_memory call advertises its valid argument language, reports cumulative truncation honestly, returns revision-bound structured provenance for source-bearing graph results, and provides a supported query-to-explain-to-community discovery path. Preserve the existing project/session/worktree isolation, bounded output, optional-component behavior and ordinary file-inspection fallback. The completed result must be merged into main with the four reported symptoms independently reproducible on the base commit and absent on the integrated commit.

## Decisions and Assumptions

Decisions: (1) Graphify 0.9.54 and the selected Hermes baseline remain unmodified external dependencies; all repair code belongs in Aether's adapter, envelope, schema, tests and derived guidance. (2) `truncated` is cumulative: native omission, Aether content bounding or reference-cap omission makes it true; a complete native answer that merely exceeds its requested estimate remains false with an explicit warning. (3) Boundary guidance may preserve native content but must replace upstream-only `context_filter`, `get_node`, graph-path and CLI instructions with supported Aether guidance: narrow the question, raise `budget_tokens` within the existing limit, or call `explain` on a returned node. (4) Source-bearing `query`, `explain`, `neighbors`, `community`, `path` and `impact` results return project-relative, revision-bound, deduplicated references for visible node definitions and relation sites in stable order. The existing 50-reference cap remains; an omission at that cap sets `truncated=true` and adds a warning. (5) `explain` adds `resolved_node={id, community_id, community_name}`; `community` adds `community={id,name,node_count}`. Null community fields are allowed for unclassified nodes. IDs remain snapshot-local. No new tool or action is added. (6) Registered schemas retain top-level properties for Hermes coercion and add action-discriminated branches matching the handler's accepted language. Every field description also names applicable actions because Hermes deliberately strips top-level combinators for strict provider schemas; runtime validation remains authoritative. (7) Release conclusions are `release_impact=patch`, `release_action=defer`, `release_channel=none`: valid existing calls remain valid, runtime-invalid combinations merely fail earlier or are described accurately, and additive response metadata is compatible. Assumptions: the live symptoms and source evidence recorded in #324-#327 represent current main; the pinned Graphify functions and graph metadata inspected at 0.9.54 remain the qualification target. Local implementation freedom: Implementer may choose the smallest exact-version adapter technique for extracting native truncation, visible references and path nodes, but may not patch upstream, parse untrusted text as proof of functional success, weaken path/snapshot checks, or change the public decisions above.

## In Scope

In scope: the `aether_agents.knowledge` worker/adapter, snapshot response construction, project_knowledge and work_memory schema construction/validation, native Hermes plugin registration, focused and integration tests, stage-005 contract/validation/implementation evidence, current project-knowledge guide, packaged canonical project-knowledge/work-memory skills when their examples or procedures are affected, documentation registry/generated reference when required by repository checks, and GitHub linkage/closeout for #324-#327. Include exact-version upstream inspection evidence and preserve existing project-relative privacy filters, result limits, locks and revision binding.

## Out of Scope

Out of scope: changing, vendoring or forking Graphify or Hermes; enabling semantic extraction, provider-backed features or model calls; adding model tools/actions, MCP transport, watchers, databases or cross-project graph merging; changing project identity/session binding rules; altering snapshot publication, work-memory semantics or update behavior beyond schema parity; increasing current output/reference limits; activating live profiles or hot-reloading this conversation; changing dependency versions or lockfiles unless a directly blocking same-class defect makes that unavoidable and is reported; releases, tags, packages, deployment and credential changes; unrelated cleanup of the repository's pre-existing worktrees or stashes.

## Deliverables

Deliverables: (1) one coherent Aether implementation that satisfies D29-D32 and closes the observable behaviors in #324-#327; (2) regression tests covering native Graphify 0.9.54 execution, envelope propagation/reference caps, community discovery and both raw/sanitized schema behavior; (3) updated stage-005 implementation evidence plus current guide, packaged canonical skill examples/procedure and documentation registry/generated reference wherever behavior changed; (4) recorded exact commands/results, base and integrated revisions, compatibility/release conclusions and remaining limitations; (5) independently reviewed, CI-green pull request merged to `main`, with #324-#327 reconciled only after integrated verification; (6) project graph refreshed from the final committed `main` revision if the component remains available, with the receipt reported as navigation coverage rather than implementation certification.

## Acceptance Criteria

Acceptance criteria: AC1—A native query that omits nodes/lines at its budget returns `ok=true`, preserves safe useful content, reports `truncated=true`, and contains no recommendation for `context_filter`, `get_node`, direct graph paths or unsupported CLI/MCP calls; a separate complete-over-budget control remains `truncated=false` with an explicit warning. AC2—For query, explain, neighbors, community, path and impact, every visible source-bearing node definition and relation site has a deduplicated project-relative `{path,location,revision}` reference in stable order, subject only to the existing 50-item cap; hitting that cap sets `truncated=true` and a warning, and no snapshot/private absolute path escapes. AC3—Starting only from a query result, an agent can call explain, receive exact `resolved_node.id`, snapshot-local `community_id` and display name, then call community without guessing; the community response repeats the requested ID, name and node count, and unclassified nodes return explicit null community fields. AC4—The canonical parameter schema for each tool uses action-discriminated branches with exact required/allowed fields while retaining root properties; representative valid/invalid instances have identical outcomes under Draft 2020-12 validation and `validate_arguments`. Hermes schema sanitization preserves usable action/field descriptions and runtime dispatch continues to reject invalid or identity-injection payloads without registration/call regressions. AC5—No existing valid call, project/worktree/role isolation, snapshot integrity, output byte limit, component version pin, timeout/process cleanup, dirty-source warning, update semantics or work-memory behavior regresses. AC6—The guide and packaged canonical skills show only supported calls, explain truncation/reference/community semantics, and all examples validate against the registered schemas; documentation/generated references are current. AC7—New regressions demonstrably fail against the base behavior and pass on the candidate; full repository gates and CI pass without skipped/removed/weakened tests or lower coverage thresholds. AC8—The final integrated main commit is verified clean, the four Issues contain linked evidence and are closed/reconciled only after the merge. Release is reported as patch/defer/none; no release artifact is created.
