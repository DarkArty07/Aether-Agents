# Objective Contract: Restore trustworthy and bounded semantic project knowledge (#416, #418, #419, #420, #423, #424)

## Owner Intent

The owner directs Aether to work autonomously through its normal Morfeo → Supervisor → Implementer pipeline until issues #416, #418, #419, #420, #423 and #424 are either closed from verified integrated evidence or left open with one concrete external blocker. The result must make configured semantic project knowledge trustworthy, bounded, resumable and honestly observable rather than merely suppressing failures. Aether is expected to implement, test, independently review, integrate and perform routine authorized GitHub closeout without repeated confirmation gates. Current owner authority does not permit changing credentials, providers, models, Router configuration, Graphify version, public release state or unrelated product behavior.

## Objective

Deliver a single coherent remediation of the semantic-maintenance transaction. A valid configured update must preserve the complete structural knowledge projection, add only provenance-bearing semantic overlay data, stay within the host-visible execution bound, stop cooperatively on cancellation, attribute usage to the originating session, reject unqualified effective routes, distinguish terminal response states from malformed content, and describe snapshot/configuration/operation state accurately. Existing structural queries must remain available throughout failure and recovery. The six issues close only after the exact integrated revision passes deterministic, component, exact-Hermes and bounded live acceptance; a terminal board or green transport alone is insufficient.

## Decisions and Assumptions

Decided:
1. The committed structural graph is the immutable base. Semantic data is composed as an additive overlay; the semantic boundary MUST NOT run Graphify global `build_merge`/label deduplication over the existing structural graph. Graphify 0.9.54 remains the isolated query, validation, clustering and export engine.
2. Before publication, compare a canonical structural projection covering node identity, source/provenance attributes, edge endpoints/relation/site and graph direction. Derived community identifiers and an equivalent explicit `origin=ast` alias may be normalized for comparison; any structural identity, relation, source or provenance loss aborts publication.
3. Prepare the semantic plan once per compatible revision/policy into private bounded staging, validate/cache fragments individually, then compose all accepted work through one indexed in-memory overlay load/cluster/export transaction. Hyperedges are included. Existing partial compatible work resumes without rebuilding or reapplying already published fragments.
4. One configured update has a 300-second total monotonic budget from entry through pointer publication, concurrency remains at most two, and finalization time is reserved before another model call starts. Natural budget exhaustion returns a valid partial receipt. Host/user cancellation stops scheduling, propagates to in-flight auxiliary calls where supported, retains validated cache and never publishes the cancelled candidate. No daemon, watcher or hidden continuation is introduced.
5. Initial route policy is primary-only fail-closed. A response whose effective non-secret provider/model/protocol identity is unresolved or differs from the fingerprinted route is neither cached nor applied and remains explicitly pending/rejected. Multi-route semantic snapshots are not introduced.
6. The maintained Hermes adapter must preserve Responses phase, top-level and item status, incomplete reason, output-text fallback and tool calls; it must never turn incomplete/cancelled output into `stop`. Aether consumes only one unambiguous final-answer text payload or exactly one expected structured fragment call, then uses the existing strict Graphify validator. As a bounded contingency, generic `tool_choice` passthrough plus one forced `submit_graph_fragment` call is authorized only if deterministic support is proven and the corrected text path still yields complete-but-invalid JSON in the first live probe. No Router contract widening is authorized.
7. Each semantic worker receives its own copied Python context so Hermes session accounting and request attribution remain isolated. A shared cancellation event is separate from ContextVar propagation.
8. Semantic snapshot/plan/cache policy versions and a structural-base reference are persisted. Legacy semantic snapshots lacking the new integrity version are not served as trusted semantic results; matching validated cache fragments may be revalidated and reused without new model calls. Old artifacts remain retained evidence.
9. Any Hermes change is delivered as an Aether-owned portable patch against verified clean source, with focused fork/upstream comparison, reconciliation ledger entry, rollback and retirement gate. The dirty live editable checkout is never a source candidate.
10. Existing issue records are canonical; no umbrella issue is created. Release conclusions are `release_impact=patch`, `release_action=defer`, `release_channel=none` unless integrated compatibility evidence proves an additive public control is unavoidable.

Assumptions supporting these delegated choices: the existing auxiliary route and credentials remain provisioned; its current request contract accepts ordinary Responses text and tools/tool_choice but not new output-format fields; the owner prefers the smallest fail-closed repair over mixed-model provenance; and a four-call live qualification ceiling is proportional to the previously authorized larger probe. If any assumption is false, execution stops at the relevant condition rather than changing provider, model, credentials or Router policy.

## Acceptance Criteria

AC-01 Structural preservation (#419): for repeated same-file headings, cross-file equal labels, exact/fuzzy AST–LLM collisions and the retained real-sized fixture, semantic composition preserves every baseline structural node ID and source/provenance attribute and every structural edge endpoint/relation/site. No structural node acquires unscoped LLM rationale/author/source attributes. A mismatch blocks pointer publication.

AC-02 Additive semantics (#419): accepted LLM nodes, edges and hyperedges remain explicitly `origin=llm` with non-structural confidence, bind only to captured sources/anchors, survive serialization and are queryable with revision-bound references. Ambiguous/colliding additions are omitted with a bounded reason instead of overwriting structural evidence.

AC-03 Bounded composition (#418/#419): semantic application loads the candidate graph once and performs at most one cluster/export publication transaction per update. The current per-fragment `build_merge` path is absent from semantic application. A deterministic full-cache fixture completes within the existing Graphify subprocess bound and demonstrates one load/compose/cluster/export sequence; no fragile millisecond CI threshold is required.

AC-04 One-pass preparation/resume (#418): one compatible revision/policy produces or reuses one bounded private plan rather than repacking the full corpus for every page. Plan records are size/path bounded and content never enters receipts/logs. A compatible partial retry reuses plan, structural base and validated cache and makes zero repeat model calls for already accepted chunks.

AC-05 Deadline and cancellation (#418): the 300-second total budget includes prepare, model, validation, composition and publication. Natural exhaustion returns a partial/pending receipt before the host's 420-second default bound. A deterministic host-timeout/manual-cancel E2E proves no late pointer change, lock release, no newly scheduled calls, in-flight cancellation where the existing transport supports it, retained validated cache and no orphan worker.

AC-06 Atomic recovery (#418/#419): content-free operation metadata identifies phase, revision/input identity and terminal outcome. Candidate manifest/hash/integrity validation precedes one atomic pointer change. Crash/cancel simulations at prepare, validate, compose, manifest and pointer boundaries leave either the previous valid snapshot or the fully validated new one; status never treats an operation journal alone as published evidence.

AC-07 Response fidelity (#420): synthetic complete, incomplete/max-output, content-filter, cancelled, commentary-plus-final, output-text fallback, tool-call, empty and malformed Responses fixtures preserve their real terminal/phase shape. Incomplete/cancelled output can never become `finish_reason=stop` or enter parsing/cache/overlay. Only one unambiguous final text or one expected structured call is eligible for strict validation.

AC-08 Honest validation and bounded live yield (#420): receipts separately count empty response, incomplete, malformed JSON, schema, source/evidence, route, cache, apply and deadline outcomes plus bounded input/output/reasoning/total usage; no raw model/source content is persisted. A complete-but-invalid response remains rejected. The bounded live canary obtains at least one source-verified semantic relation through the unchanged configured primary route with no opaque failure category; if corrected text mode fails within its first two calls, the pre-authorized forced structured-call contingency may use at most two additional calls. Total new live calls never exceed four.

AC-09 Effective route (#424): unresolved or mismatched effective route is neither cached nor inserted into the candidate and is reported pending/rejected. Deterministic tests inspect graph bytes/projection, not only cache absence. Cached fragments are read only when policy/version/content and stored route identity match the expected primary route.

AC-10 Session accounting (#423): each successful auxiliary response with usage is attributed exactly once to the originating Hermes session/task; two concurrent sessions remain isolated; retries follow existing attempt semantics; cache hits/deferred chunks add no calls. SessionDB totals for the canary reconcile with the operation receipt, with documented handling for responses whose provider supplies no usage.

AC-11 Accurate state language (#416): status/query distinguish current configuration enablement, immutable snapshot state and active operation state. `disabled`, `pending`, `partial`, `unavailable`, `complete`, contradiction and unknown cases have deterministic messages; a pending snapshot never says extraction is disabled.

AC-12 Migration and structural recovery (#419): legacy semantic snapshots without the new pipeline/integrity version are not served as trusted semantic results. Matching old cache fragments are revalidated and reused without model calls. Structural mode or integrity recovery can select/rebuild a pure structural base through a supported operation; retained historical evidence is not deleted.

AC-13 Degradation and compatibility: structural query/status remain functional when semantic preparation, auxiliary transport, validation, accounting or composition fails. Existing two-tool/fourteen-project-action/five-memory-action schemas and successful v1 envelope fields remain compatible; new receipt fields are additive. No query/status call invokes a model.

AC-14 Integrated qualification: focused RED/GREEN tests, isolated Graphify-native tests, exact maintained-Hermes patch tests, full exact-Hermes Aether bootstrap, Ruff, format, mypy, documentation validation, public-artifact/policy checks, branch coverage at the unchanged configured floor and package build all pass on the exact candidate, or any pre-existing unrelated failure is reproduced identically on the clean base and remains an explicit blocker rather than waived.

AC-15 GitHub and post-merge closeout: required PR checks pass on the exact merged tree; post-merge smoke repeats the structural invariant, no-model query and bounded semantic canary/cache reuse as authorized. The managed primary is synchronized without overwriting unrelated state. Each named issue is closed only with direct evidence for its criterion. No tag, package release, deployment, provider/model/Router change, force operation or destructive cleanup occurs.

## Stop Conditions

Stop and return the owning decision/blocker without weakening acceptance when any of the following occurs:
- portable Aether Project, contract, execution board or base identity is missing, ambiguous, archived or conflicts with the exact repository marker;
- a correction requires changing Graphify version/core, Aether Router contract/configuration, provider/model/fallback/credentials, or another project/repository outside the portable-patch mechanism;
- the additive overlay cannot preserve the canonical structural projection, or a legacy artifact cannot be distinguished/recovered without deleting evidence;
- host cancellation cannot prevent late publication, or the operation can only meet the bound by hiding detached work;
- the selected primary route remains unable to produce one valid source-bound result after the four-call live ceiling, or more model spend is required;
- a required external field such as unsupported output formatting must be added to Router, or a fallback/mixed-route policy becomes necessary;
- an unrelated failing gate cannot be reproduced on the clean base and therefore may be a regression in the candidate;
- a protected-edge denial, credential problem, publication/deployment request, destructive cleanup, force/history rewrite or check bypass would be required;
- repeated implementation review exposes a contradiction in the shared transaction, provenance model, public compatibility or authority rather than a bounded code defect.

Ordinary implementation failures, test failures, review rework, merge conflicts and bounded integration glue remain within Supervisor/Implementer convergence and are not owner questions. Do not close an issue from a partial board summary or exhaust retries to manufacture completion. If Aether/Hermes pipeline infrastructure itself regresses and prevents handoff/execution, invoke the separate rollback-first runtime-recovery boundary rather than changing this contract or asking its workers to repair their dispatcher.
