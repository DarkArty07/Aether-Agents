# Objective Contract: Deliver the installed Aether launcher and bounded Graphify semantic updates

## Owner Intent

Autonomously resolve the installed Aether launcher failures tracked by #480 and #481 and the Graphify semantic-compose deadline/cancellation regression tracked by #482. The owner must be able to open and use project-bound Morfeo comfortably from WSL/Windows without reproducing shell environment incantations, while configured Project Knowledge updates remain bounded, cancellable, and honest. Deliver reviewed, integrated source plus a verified usable local candidate through provisioned access; do not return for routine implementation choices, tests, review, GitHub closeout, or reversible local activation.

## Objective

Deliver one coherent repair candidate that (1) implements the documented installed `aether [--project PATH] [--json]` Morfeo launch surface from packaged manager code, (2) creates branded project-bound one-click launch actions for this WSL installation, (3) launches only a release-bound prebuilt Hermes TUI and leaves locked `hermes-source` unchanged, and (4) propagates the remaining semantic budget and shared cancellation into `semantic_compose` so configured Project Knowledge updates return an honest terminal receipt before Hermes' 420-second tool boundary. Integrate through normal review/PR/green merge, prepare and activate a local-only `1.0.0rc4` candidate from the exact merged Aether commit and accepted maintained-fork commit, verify the two live user paths, and reconcile #480/#481/#482 without publishing a public release.

## Decisions and Assumptions

Delegated decisions and assumptions:

- Route: pipeline, because this spans public CLI behavior, lifecycle projections and candidate preparation, WSL host integration, immutable release assets, semantic execution/cancellation, release qualification and independent review.
- Launcher ownership: the manager package owns validation and environment construction and then `exec`s the managed Hermes executable; manager code must not import Hermes. The checkout-relative `scripts/aether_tui.py` ceases to be an installed dependency and may remain only as a source/development shim if still useful.
- Project selection is exact, never by display name or recency: explicit `--project` first; an explicit verified `AETHER_PROJECT_ID` binding second; a current repository marker or sole registered project only when registry and marker agree; otherwise fail visibly. One-click entries carry an explicit local project binding.
- This installation uses existing Windows Terminal for WSL and installs no Konsole/package. Provide two branded local actions for the exact Aether Agents project: `Aether` starts fresh and `Continue Aether` uses Hermes' documented workspace-scoped `--resume latest` with exact `--in`. Linux-native projection remains terminal-based. Host shortcuts are WSL entry adapters, not a Windows-native support claim.
- Adapt Hermes' inspected prebuilt/Docker contract rather than inventing a second TUI: Aether candidate preparation builds `ui-tui/dist/entry.js` once from maintained-fork commit `aed6591a69f453a1867b73628603e7b53ba40ffc` in a disposable workspace, stores it outside locked `hermes-source` under the release, hash-binds it in candidate/release/bundle evidence, and sets the active launcher/service `HERMES_TUI_DIR` to that release asset. Runtime launch never runs npm/build, never trusts an ambient TUI path, and never weakens source-tree integrity. Refreshed upstream `8a92051f20e6b371c4ff1a46a5bcec7138cc4e8c` and the accepted fork expose the prebuilt path but ship no tracked `tui_dist`; therefore this objective keeps the fork commit unchanged and Aether owns the build/staging adaptation.
- Launcher environment removes conflicting Python, profile, TUI, session/task/cron/Kanban launch residue while preserving ordinary credentials/config, then sets exact `HERMES_HOME`, `AETHER_PROJECT_ID`, cwd and release-owned TUI binding. Reserved binding flags cannot be overridden by passthrough arguments.
- Semantic compose receives the remaining monotonic deadline and shared cancel event. Host cancellation re-raises `OPERATION_CANCELLED`; natural compose timeout is classified as deadline exhaustion and returns pending/partial without publication; other compose failures remain bounded apply failures. Valid cache and structural snapshot are preserved and no model/provider/router/fallback changes occur.
- Local recovery never edits or normalizes contaminated rc3 in place. Prepare package `1.0.0rc4` / display `1.0.0-rc.4` with one local annotated `v1.0.0-rc.4` tag on the reviewed merge, then activate through `aether update --local`. Rc1/rc2/rc3 history and evidence remain immutable.
- Release conclusions: `release_impact=patch` (documented behavior/reliability repairs), `release_action=prepare`, `release_channel=prerelease`. No public tag, GitHub Release, PyPI publication or stable claim.

For Graphify, stop on ambiguous deadline ownership, structural-data loss, cache/provenance loss, cross-project publication, a process surviving cancellation, a configured call reaching the 420-second host boundary, missing configured auxiliary access after one bounded confirmation, or need for fallback/new credentials.
