# Objective Contract: Eliminate silent affinity-flow stalls and wake the exact origin (#280)

## Owner Intent

Christopher authorizes Aether to autonomously correct issue #280 end to end. The owner-visible result is that an affinity pipeline cannot remain silently non-terminal with no executable work while appearing active: a repairable blocker is handled internally by the existing Supervisor controller, while an unrepairable or non-progressing flow emits exactly one typed signal that wakes Morfeo in the exact originating TUI session without another owner message. The objective includes implementation, independent review, normal GitHub integration, reversible local runtime activation and live qualification. The unrelated intermittent TUI/process-persistence incident tracked by #305 is explicitly separate and must not expand or block this objective.

## Objective

Implement and qualify the final HLP-280 repair variant that preserves ordinary parent gating and silent internal recovery while guaranteeing a bounded exit from every zero-executable-frontier affinity state. Preserve the accepted v1/v2 architecture, but close the complete bootstrap boundary: require exact present session and non-terminal affinity identity, scope direct-origin deduplication to the active source run so new recovery cycles can signal again, and treat an exact scheduled terminal controller as materialized controller-first work. Integrate the portable patch and evidence into Aether, activate only merged bytes in the Aether-managed local Hermes runtime, and close #280 only after the active no-watcher canary passes.

## Decisions and Assumptions

1. Flow membership is separate from execution session affinity. Every affinity-controlled task, including a fresh non-affinity Implementer, receives immutable Project, flow, origin-session, controller-task and role identity from trusted kernel inheritance. Missing, malformed or conflicting identity fails closed and never becomes a wildcard.
2. Pending controller attention is normalized durable control state with database constraints. Events remain audit/notification projections and are not reparsed as the authoritative obligation set. The database permits only one unresolved attention per exact controller/blocker pair.
3. Blocking or terminal failure, attention creation/recovery, controller promotion and projected events form one atomic writer transaction. Failure commits neither a partial blocked state nor a pending attention with a todo controller. Terminal/origin deduplication is transaction-local and database-backed.
4. Runtime classification distinguishes exactly three states: a genuinely non-flow task uses legacy behavior; malformed, missing, conflicting or ambiguous flow identity/topology rolls back fail-closed; and a valid non-terminal bootstrap root uses direct exact-origin escalation only when all of the following hold simultaneously: immutable role=root membership, `controller_task_id=task.id`, no parents, non-empty `tasks.project_id`, non-empty `tasks.session_id` exactly equal to membership `origin_session_id`, present parseable `session_affinity` with `terminal=false` and exact membership `flow_id`, non-empty current active `source_run_id`, and no exact terminal controller child materialized in any supported non-terminal status.
5. `session_id=NULL`, `session_affinity=NULL`, malformed affinity, missing/closed current run, or any mismatch is invalid, never bootstrap or legacy. The source transition rolls back and no signal/attention is emitted.
6. For a valid bootstrap cycle, explicit block or exhausted automatic failure atomically persists the source transition and exactly one direct origin signal. Dedupe is keyed by the source task and source run cycle, not globally by outcome: repeated/concurrent handlers for one run emit once; public unblock plus a new claim creates a new run and may emit one new signal. Capture/validate the source run before the transaction clears `current_run_id`, and include it in the projected audit payload.
7. Preserve explicit `input|revision|recovery`; map `needs_input` without signal to `input`; map capability, transient, block-loop, protocol_violation, gave_up, spawn failure, crash, timeout and clean exit without handoff to `recovery`. No attention is fabricated without a controller.
8. An exact terminal controller child in `todo`, `ready`, `running`, `blocked`, `scheduled`, or review-executable state is materialized topology, so the source is not bootstrap. A `scheduled` exact controller is atomically promoted to `ready` and receives normalized attention. A deliberately `blocked` controller is not silently auto-promoted unless the existing explicit recovery/requeue contract authorizes it; zero-frontier handling must still produce a typed recovery rather than direct bootstrap misclassification.
9. Only the exact same-Project/same-flow/same-origin-session terminal controller may bypass ordinary parent gating. Invalid raw obligations, malformed topology, ambiguity or mixed valid+invalid state fail closed as a whole.
10. Repairable blockers route controller-first and remain silent to the origin when a controller exists. The controller may resolve and resume, return to dependency after a valid repair, emit input|revision|recovery, or terminate the flow. It cannot persist a non-dependency block without a typed origin signal.
11. Semantic liveness uses the existing dispatcher, not cron, external watcher or a new role. An unresolved attention with no durable semantic progress expires after a configurable default of 300 seconds; heartbeat alone is not progress. Expiry emits exactly one recovery signal.
12. The affinity notifier filter remains restricted to typed origin signals and flow terminal events. The repair changes event production and lifecycle, not broad notification policy.
13. Existing active Hermes local patches are compositional preimage. Development starts from captured active bytes in isolation, preserves unrelated hunks and produces one independently removable HLP-280 patch.
