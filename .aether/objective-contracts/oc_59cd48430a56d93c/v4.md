# Objective Contract: Eliminate silent affinity-flow stalls and wake the exact origin (#280)

## Owner Intent

Christopher explicitly approves redesigning the narrow HLP-280 flow-routing state machine, requires exhaustive durable documentation, authorizes autonomous execution through verified implementation, review, integration, reversible activation and live qualification, and requests a Telegram update whenever a meaningful objective milestone changes. The owner does not authorize weakening acceptance, treating heartbeats as progress, hiding another counterexample behind a narrower test, or expanding into issue #305 or #267 implementation. Telegram updates are objective-scoped operational reporting and must stop when #280 completes or reaches a durable owner-directed stop.

## Objective

Replace the implicit, distributed HLP-280 blocker/failure routing heuristics with one total typed flow-routing state machine and one atomic transition executor. The result must make every reachable flow condition explicit, preserve legacy non-flow behavior, and prove that no committed transition can leave an open affinity flow with zero executable frontier, no valid controller recovery path, no pending exact-origin signal and no terminal event. Document the complete state vocabulary, transition table, data authority, transaction boundary, invariants, migration, rollback, observability and property-test model before behavior implementation. Telegram milestone reporting is operational visibility only and is never part of the correctness path.

## Decisions and Assumptions

1. Scope. Replace HLP-280 routing with one total typed machine limited to flow identity, blockers/failures/controller lifecycle, durable effects, exact-origin delivery and TUI receipt. Owner-approved native TUI wake supersedes stale R6 text and requires R6/PD-77 update; PD-75 unchanged; #267/#305 separate.
2. Authority. `kanban_flows` owns flow/root/Project/origin, nullable controller, lifecycle `open|terminal|quarantined`, `state_version`, immutable `deadline_seconds`, route identity/revision, terminal fields and quarantine fields. Root/flow unique. Terminal never reopens. Memberships/attentions/effects reference it; affinity is lease only.
3. Tables. Use `kanban_flow_memberships` (one root, ≤1 controller); `kanban_flow_attentions` (`open|resolved`, exact source run); `kanban_flow_effects` (cycle/action/input hash/event/route); `kanban_flow_quarantine` (raw identifiable or unbound evidence); `kanban_flow_delivery_claims`; and state.db `session_wake_receipts`.
4. Route. Registry owns route_id plus platform, chat/session/thread, user IDs, chat type, notifier profile, delivery mode, scope and revision. Sole active root notify-sub is projection linked by route_id/revision, deferred FK/unique index, triggers and transaction validation. Router never derives authority from projection. API update/delete while open is REJECT_OPERATION; already missing/stale/conflicting flow projection is FLOW_CORRUPT. Subs without route_id are legacy and never influence flow routing.
5. Root creation. Under one BEGIN IMMEDIATE create root task, registry, root membership and exact projection; validate all, commit all/none. Disabled/unattached/missing/ambiguous route rejects affinity creation. Non-flow creation remains legacy compatible.
6. Snapshot. Operation is `explicit_block|automatic_failure|dispatcher_reconcile|controller_action`. Snapshot includes full raw registry/membership/affinity/route/projection/task/run/liveness/controller/attention/effect/receipt state and requested outcome. Invalid rows are retained as INVALID, never filtered.
7. Run/liveness map. Exact `current_active` means supplied run equals tasks.current_run_id, owns task, status running, no end, generation/claim exact. Explicit+LIVE valid; explicit+DEAD FLOW_CORRUPT; explicit+UNKNOWN rejects while fresh source remains. Automatic+DEAD valid; automatic+LIVE rejects; automatic+UNKNOWN DEFER_LIVENESS until lease/stale expiry. Supplied alternate/ended/missing run with another exact current-active run rejects stale. Multiple active, current pointer absent/dangling/ended while task says running, ownership mismatch or no exact active run where source transition is required is FLOW_CORRUPT. Structural corruption precedes operation rejection.
8. Attention map. Validate every raw row including resolved history. Invalid/mixed row, duplicate same cycle/pair, bad FK/event or open attention without exact controller is FLOW_CORRUPT. One valid open same-cycle attention is reused. Multiple valid open attentions for different blockers are allowed. Resolved row is closed only with exact state/event. Empty open set with controller creates attention; empty set without controller may bootstrap only after all exact checks.
9. Cycle/effect identity. Keys are `(flow,'source_exit',task,run)`, `(flow,'attention_transition',attention,transition)`, `(flow,'attention_expiry',attention,deadline_at)`, `(flow,'terminal',controller,controller_run)`, `(flow,'quarantine',pre_state_version)`, or unbound `(board,'unbound_quarantine',source_task,supplied_run_or_none,reason_code)`. Effect/ledger rows store canonical input hash, action, event and route revision. Exact key+hash returns same row; same key with different hash/action/route is conflict and never creates a second row/effect. Registry stores quarantine key/event after increment so later quarantined operations replay it.
10. Total precedence. (a) Parse operation and candidate keys; read full state. (b) Before legacy, query unbound quarantine by its key: exact hash returns QUARANTINE_FLOW unbound replay with no mutation; hash conflict returns typed UNBOUND_CONFLICT, preserves first ledger row and never delegates legacy. (c) Consistent terminal validates and returns the exact stored terminal effect/event as FLOW_TERMINAL replay/no-op; missing/mismatched terminal effect or active state invokes TERMINAL_RECONCILE. (d) Quarantined returns QUARANTINE_FLOW stored rejection/cleanup. (e) No registry, membership, affinity, attention, effect, quarantine or flow reference anywhere => LEGACY_NON_FLOW/DELEGATE_LEGACY, touching no flow table. Partial/conflicting reference => FLOW_CORRUPT. (f) Validate open registry and route projection; corruption quarantines before bound replay. (g) Exact bound effect => REPLAY_EFFECT before now-closed-run validation; conflict quarantines. (h) Validate operation/run/liveness; REJECT_OPERATION or DEFER_LIVENESS per Decision 7. (i) Validate full controller/attention sets. (j) Exact no-controller bootstrap => BOOTSTRAP_TO_ORIGIN. (k) Otherwise controller map. No default/None. Operation invalid plus structural corruption follows corruption.
11. Controller map. absent is bootstrap only with open exact registry whose controller field/membership absent, exact LIVE current root, exact nonterminal affinity/route and empty valid open attention set; otherwise corrupt. scheduled/todo=>ROUTE_CONTROLLER and ready. ready/review=>route without duplicate claim. running=>CONTROLLER_BUSY with attention/no duplicate worker. blocked/triage=>CONTROLLER_BLOCKED plus one recovery effect. ambiguous/invalid/done/archived while open=>FLOW_CORRUPT.
12. Controller actions. dependency resolves oldest valid attention, reopens source, closes controller run as dependency, then controller ready if more open attentions else parent-gated todo. Nondependency closes controller run/task blocked and writes typed effect; flow stays open. Success requires all parents done, no open attention and zero other active flow runs; then controller run/task done, flow terminal-success and one flow_terminal effect. Other active run rejects success. Exhausted failure atomically fences/closes every active flow run, sets affected tasks blocked/triage, closes controller failure, terminalizes failure and writes one effect.
13. Terminal reconcile. Consistent terminal requires terminal fields/effect/event, no active flow runs/executable flow tasks; success controller done, failure controller blocked/triage. Operations return exact stored terminal effect/no-op. Inconsistent terminal stays terminal; executor fences/closes runs, triages/demotes tasks, records one terminal_reconciled diagnostic keyed state version, never reopens or creates second terminal effect.
14. Quarantine. FLOW_CORRUPT writes typed event/ledger using pre-mutation state_version, stores key/event on registry, increments once, fences/closes identifiable active flow runs, triages identifiable nonterminal tasks, sets quarantined and prevents claim. Exact route also gets one recovery effect keyed quarantine event. Without trustworthy flow, automatic/dead closes/fences identifiable causal run if present, triages source and writes unbound unique ledger row; explicit/live with no trustworthy flow rejects/preserves source and writes only unbound diagnostic. Quarantined operations replay stored rejection and clean late run/task; no auto-unquarantine.
15. Executor. One BEGIN IMMEDIATE rereads snapshot/version, classifies, writes task/run/controller/attention/effect/event/quarantine, evaluates oracle and commits. Event uses unique dedupe; effect references event in same transaction. Fault/conflict rolls back. Late workers generation-fenced.
16. Delivery order. task_events.id is total order per board. Each route has at most one `leased` claim. It selects smallest relevant id > cursor; filter is immutable for open flow and intervening irrelevant ids are explicitly skipped. Claim does not advance cursor. Claim persists as `leased` until exactly one of: destination receipt completed causes atomic `acked`+cursor advance, or lease expires and the same event is reclaimed. There is no delete/implicit released state. No later relevant event claims while earlier unacked. Crash after ack sees cursor; ack loss reclaims same event and receipt dedupes.
17. TUI receipt. Envelope includes board/root/flow/event/route revision/session and stable turn_id hash. `session_wake_receipts` unique `(session,board,event)` and turn_id unique. One state.db write persists absent receipt+internal prompt as prompted. Live claim defers; expired no-prompt claim reclaims; prompted resumes/observes exact turn; completed returns receipt without another turn. Assistant persistence and receipt completion share one transaction, so turn-without-receipt impossible; if detected, receipt corruption leaves Kanban unacked and quarantines/diagnoses. Notifier acks only completed.
18. Delivery failure. state.db transient/TUI restart leaves claim unacked and cursor unchanged. Invalid/conflicting receipt records failure and quarantines open flow without fallback. Controlled cuts test protocol; spontaneous #305 cause out. Async gateways preserve semantics, receive event identity where supported, no physical exactly-once claim.
19. Deadline. Flow stores immutable deadline_seconds: default 300, 120–3600 and ≥2 dispatcher intervals; invalid config rejects, never clamps; later config affects new flows. Each attention stores last_progress_at and deadline_at=UTC integer now+deadline at create/semantic progress. Heartbeats do not update. Reconciler expires open attention when deadline_at<=now under BEGIN IMMEDIATE using attention-expiry key; no source run. It writes one recovery effect/marks emitted. Expiry while controller LIVE is semantic-stall escalation, not AutomaticFailure. Terminal/quarantined never expire.
20. Migration. Exclusive transaction creates staging/schema/ledger, snapshots HLP-211b task/affinity/DAG/sub/event data, derives unique identities, copies valid rows, stores ambiguous raw identity/hash/reason unbound, rebuilds constrained tables, runs FK/integrity/reopen, then bumps version. v1–v3 tables never activated. DB open emits no user event.
21. Oracle. Valid open postcommit is executable source; exact executable controller+valid attention; current-cycle exact-route effect; or terminal. Structural invalid is quarantined/not-working. Legacy delegates without flow mutation. No state claims working with zero escape.
22. Governance. Design/SQL/matrix/model reviewed before behavior. One implementation correction maximum; new behavior outside matrix returns revision, no automatic v5. Telegram passive/removed at close or stop. Release patch/defer/none.
