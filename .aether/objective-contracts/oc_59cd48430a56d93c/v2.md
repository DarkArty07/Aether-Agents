# Objective Contract: Eliminate silent affinity-flow stalls and wake the exact origin (#280)

## Owner Intent

Christopher authorizes Aether to autonomously correct issue #280 end to end. The owner-visible result is that an affinity pipeline cannot remain silently non-terminal with no executable work while appearing active: a repairable blocker is handled internally by the existing Supervisor controller, while an unrepairable or non-progressing flow emits exactly one typed signal that wakes Morfeo in the exact originating TUI session without another owner message. The objective includes implementation, independent review, normal GitHub integration, reversible local runtime activation and live qualification. The unrelated intermittent TUI/process-persistence incident tracked by #305 is explicitly separate and must not expand or block this objective.

## Objective

Implement and qualify a coherent HLP-280 repair that preserves ordinary parent gating and silent internal recovery while guaranteeing a bounded exit from every zero-executable-frontier affinity state. The repair must make flow membership explicit for non-affinity workers, make pending controller attention durable and exactly-once, perform blocker/attention/controller routing atomically, route all terminal failure paths through the same liveness invariant, add native semantic-expiry escalation, and prove delivery to the exact origin TUI. During the valid bootstrap window before a terminal controller child exists, the non-terminal root must atomically persist exactly one direct typed origin signal instead of being treated as legacy or failing silently. Integrate the portable patch and evidence into Aether, activate only merged bytes in the Aether-managed local Hermes runtime, and close #280 only after the active no-watcher canary passes.

## Decisions and Assumptions

1. Flow membership is separate from execution session affinity. Every affinity-controlled task, including a fresh non-affinity Implementer, receives immutable Project, flow, origin-session, controller-task and role identity from trusted kernel inheritance. Missing, malformed or conflicting identity fails closed and never becomes a wildcard.
2. Pending controller attention is normalized durable control state with database constraints. Events remain audit/notification projections and are not reparsed as the authoritative obligation set. The database permits only one unresolved attention per exact controller/blocker pair.
3. Blocking or terminal failure, attention creation/recovery, controller promotion and projected events form one atomic writer transaction. Failure commits neither a partial blocked state nor a pending attention with a todo controller. Terminal/origin deduplication is transaction-local and database-backed.
4. Runtime classification distinguishes exactly three states: a genuinely non-flow task uses legacy behavior; malformed, conflicting or ambiguous flow identity/topology rolls back fail-closed; and a valid non-terminal bootstrap root whose `flow_role=root`, `controller_task_id=task.id`, exact Project/flow/origin identity is valid, but whose terminal controller child is not yet materialized, uses direct exact-origin escalation. The bootstrap root is never downgraded to legacy and is not treated as corrupt solely because the controller child does not yet exist.
5. For that valid pre-controller bootstrap state, explicit block or exhausted automatic failure atomically persists the source task transition and exactly one direct origin signal on the subscribed root. An explicitly requested `input|revision|recovery` is preserved; `needs_input` without a signal maps to `input`; capability, transient, block-loop, protocol_violation, gave_up, spawn failure, crash, timeout or clean exit without handoff maps to `recovery`. No attention is fabricated without a controller. Once the exact terminal controller exists, all subsequent repairable failures use controller-first routing.
6. Only the exact same-Project/same-flow/same-origin-session terminal controller may bypass ordinary parent gating. Invalid raw obligations, malformed topology, ambiguity or mixed valid+invalid state fail closed as a whole.
7. Repairable blockers route controller-first and remain silent to the origin when a controller exists. The controller may resolve and resume, return to dependency after a valid repair, emit input|revision|recovery, or terminate the flow. It cannot persist a non-dependency block without a typed origin signal.
8. Semantic liveness uses the existing dispatcher, not a cron, external watcher or new role. An unresolved attention with no durable semantic progress expires after a configurable default of 300 seconds; heartbeat alone is not progress. Expiry emits exactly one recovery signal.
9. The affinity notifier filter remains restricted to typed origin signals and flow terminal events. The repair changes event production and lifecycle, not broad notification policy.
10. Existing active Hermes local patches are compositional preimage. Development starts from captured active bytes in isolation, preserves unrelated hunks and produces one independently removable HLP-280 patch.
11. Version 2 consumes the verified candidate history without rewriting it: base candidate `be6855108b34dfc9b3370bd9dc2e6fc04005617c` and actual rework commit `8bd547ce14711ba1b0fd645becd5b07e66ae55b7`. The nonexistent SHA recorded in prior handoff metadata is evidence error and must be corrected, never used as a source ref.
12. Two checkpoints remain required: implementation PR first; after merge, backup/activation/reload/live qualification; then an evidence-only PR with no behavior changes.
13. release_impact=patch, release_action=defer, release_channel=none. No package/tag/release/deployment is implied.
Assumptions: the owner’s autonomous authorization delegates this objective-local bootstrap behavior. The persistent TUI used by the canary is healthy at test start; #305 behavior is not attributed to or repaired by this objective.

## Acceptance Criteria

AC1. Every task in an affinity-controlled DAG has one explicit immutable membership whose Project, flow, origin-session, controller-task and role match the canonical root/controller; non-affinity Implementers remain fresh. Missing, malformed, conflicting or ambiguous identity is rejected without controller adoption. A valid root self-membership before terminal-child materialization is recognized as a distinct bootstrap state rather than legacy or corruption.
AC2. At least two independent SQLite writers routing the same blocker produce exactly one unresolved attention and one logical terminal/origin projection; sequential retries are idempotent.
AC3. For needs_input without signal, capability, transient, block-loop, protocol_violation, gave_up, spawn failure, crash, timeout and clean exit without handoff, the committed state contains exactly one of: blocked unit + pending attention + claimable controller; valid bootstrap root source transition + one typed exact-origin signal; one typed origin signal from the terminal controller; or one flow terminal. No committed zero-frontier silent state exists.
AC4. Fault injection after every route write boundary proves all-or-nothing behavior. Failure after attention insertion cannot leave the controller todo; failure during bootstrap source/signal projection leaves neither partial source transition nor consumed subscription/cursor; projection failure cannot consume or partially resolve an obligation.
AC5. Rediscovery/requeue, external unblock, claim parent-gating bypass and dependency resolution validate the entire raw unresolved set. Valid+stale, valid+malformed, malformed sibling/ancestor/controller, empty, cross-boundary and missing-identity controls fail closed without partial parent resume or invalid resolution.
AC6. Ordinary parent-gated and genuinely non-flow cards preserve legacy behavior. Dependency waits and repairable controller work remain origin-silent. A terminal controller cannot commit a non-dependency block without input|revision|recovery.
AC7. A valid non-terminal root with `controller_task_id=task.id` and no exact terminal child cannot commit a silent block or exhausted automatic failure. Explicit typed signals are preserved; needs_input without signal emits exactly one input; capability, transient, block-loop and automatic failure outcomes emit exactly one recovery; no pending attention is fabricated. Once the terminal child exists, controller-first routing applies. The two Supervisor REDs for capability and protocol_violation pass on the corrected candidate and fail on commit `8bd547ce14711ba1b0fd645becd5b07e66ae55b7`.
AC8. An unresolved attention with no durable semantic progress emits exactly one recovery signal after the configured 300-second default through the native dispatcher. Heartbeat alone does not reset the deadline. Fake-clock exact-boundary tests and a live disposable lower-deadline control pass.
AC9. The exact origin subscription exists or is recovered, selects only typed origin signals and flow-terminal events for affinity tasks, advances its cursor only after successful wake, retries failed delivery and never creates duplicate owner turns.
AC10. One persistent healthy-TUI canary uses exactly one owner prompt and proves pre-controller bootstrap escalation, blocker creation, controller-first repair without owner wake in the repairable case, typed escalation in the unrepairable/deadline case, and a later non-empty Morfeo turn in the same durable session without watcher or synthetic owner input.
