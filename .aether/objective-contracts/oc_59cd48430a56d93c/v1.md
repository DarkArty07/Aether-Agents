# Objective Contract: Eliminate silent affinity-flow stalls and wake the exact origin (#280)

## Owner Intent

Christopher authorizes Aether to autonomously correct issue #280 end to end. The owner-visible result is that an affinity pipeline cannot remain silently non-terminal with no executable work while appearing active: a repairable blocker is handled internally by the existing Supervisor controller, while an unrepairable or non-progressing flow emits exactly one typed signal that wakes Morfeo in the exact originating TUI session without another owner message. The objective includes implementation, independent review, normal GitHub integration, reversible local runtime activation and live qualification. The unrelated intermittent TUI/process-persistence incident tracked by #305 is explicitly separate and must not expand or block this objective.

## Objective

Implement and qualify a coherent HLP-280 repair that preserves ordinary parent gating and silent internal recovery while guaranteeing a bounded exit from every zero-executable-frontier affinity state. The repair must make flow membership explicit for non-affinity workers, make pending controller attention durable and exactly-once, perform blocker/attention/controller routing atomically, route all terminal failure paths through the same controller-first invariant, add native semantic-expiry escalation, and prove delivery to the exact origin TUI. Integrate the portable patch and evidence into Aether, activate only merged bytes in the Aether-managed local Hermes runtime, and close #280 only after the active no-watcher canary passes.

## Decisions and Assumptions

1. Flow membership is separate from execution session affinity. Every affinity-controlled task, including a fresh non-affinity Implementer, receives immutable Project, flow, origin-session, controller-task and role identity from trusted kernel inheritance. Missing, malformed or conflicting identity fails closed and never becomes a wildcard.
2. Pending controller attention is normalized durable control state with database constraints. Events remain audit/notification projections and are not reparsed as the authoritative obligation set. The database permits only one unresolved attention per exact controller/blocker pair.
3. Blocking or terminal failure, attention creation/recovery, controller promotion and projected events form one atomic writer transaction. Failure commits neither a partial blocked state nor a pending attention with a todo controller. Terminal/origin deduplication is transaction-local and database-backed.
4. Only the exact same-Project/same-flow/same-origin-session terminal controller may bypass ordinary parent gating. Invalid raw obligations, malformed topology, ambiguity or mixed valid+invalid state fail closed as a whole.
5. Repairable blockers route controller-first and remain silent to the origin. The controller may resolve and resume, return to dependency after a valid repair, emit input|revision|recovery, or terminate the flow. It cannot persist a non-dependency block without a typed origin signal.
6. Semantic liveness uses the existing dispatcher, not a cron, external watcher or new role. An unresolved attention with no durable semantic progress expires after a configurable default of 300 seconds; heartbeat alone is not progress. Expiry emits exactly one recovery signal.
7. The affinity notifier filter remains restricted to typed origin signals and flow terminal events. The repair changes event production and lifecycle, not broad notification policy.
8. Existing active Hermes local patches are compositional preimage. Development starts from captured active bytes in isolation, preserves unrelated hunks and produces one independently removable HLP-280 patch.
9. Two checkpoints are required: implementation PR first; after merge, backup/activation/reload/live qualification; then an evidence-only PR with no behavior changes.
10. release_impact=patch, release_action=defer, release_channel=none. No package/tag/release/deployment is implied.
Assumptions: the owner's autonomous authorization delegates objective-local implementation choices, including the initial 300-second default. The persistent TUI used by the canary is healthy at test start; #305 behavior is not attributed to or repaired by this objective.

## Acceptance Criteria

Every task in an affinity-controlled DAG has one explicit immutable membership whose Project, flow, origin-session, controller-task and role match the canonical root/controller; non-affinity Implementers remain fresh. Missing, malformed, conflicting or ambiguous identity is rejected without controller adoption.

AC3. No committed zero-frontier blocked+pending+todo state exists.
AC4. Fault injection after every route write boundary proves all-or-nothing behavior. Failure after attention insertion cannot leave the controller todo, and projection failure cannot consume or partially resolve the obligation.

Valid+stale, valid+malformed, malformed sibling/ancestor/controller, empty, cross-boundary and missing-identity controls fail closed without partial parent resume or invalid resolution.
AC6. Ordinary parent-gated cards remain todo. Dependency waits and repairable controller work remain origin-silent. A terminal controller cannot commit a non-dependency block without input|revision|recovery.
AC7. An unresolved attention with no durable semantic progress emits exactly one recovery signal after the configured 300-second default through the native dispatcher. Heartbeat alone does not reset the deadline. Fake-clock exact-boundary tests and a live disposable lower-deadline control pass.

## Testing Standard

Testing is test-first for every behavior change: preserve or add the exact RED before implementation, then GREEN, then refactor without altering the accepted behavior. Every run prints the imported module path, exact base/preimage hashes and isolated database/project/workspace roots so results cannot silently exercise a stale checkout.

Tiers:
1. Deterministic unit/property tests for membership, normalized attention, unique constraints, full-set validity, parent gating, typed controller behavior and fake-clock 300-second expiry boundaries.
2. Two-connection/process concurrency tests and statement-boundary fault injection proving exactly-once and atomic rollback.
3. Fresh and legacy schema migration, reopen, backup, rollback and forward-reapply tests with byte/data preservation assertions.
4. Complete failure-path matrix: explicit blocker kinds, external unblock, block loop, protocol violation, gave_up, spawn failure, crash, timeout and clean exit without handoff.
5. Full affected Hermes suites for Kanban DB/CLI/tools, affinity, sticky blocks, dispatcher, subscriptions, gateway notifier/wake scope and TUI poller; compile, syntax, lint/diff and Aether repository-policy checks.
6. Independent reviewer cold-read plus reviewer-owned malformed, cross-boundary, concurrency and failure-injection counterexamples; submitted tests are not sufficient.
7. Disposable process/SQLite/Project probes against the exact candidate and, after merge, the exact merged patch reconstruction. Never mutate a historical/production board for RED/GREEN.
8. Persistent TUI qualification through the native gateway protocol with one owner submit, same durable origin session, concurrent dispatcher, no watcher, no synthetic continuation, event/cursor/session-DB observation and later non-empty Morfeo turn. Run repairable-silent and unrepairable/deadline-escalation cases, plus duplicate-delivery and failed-send retry controls.
9. After implementation PR merge: recheck active hashes, backup, apply merged bytes, reload gateway, verify module identity/service/PID/readback, execute the no-watcher canary and rollback control, then record facts in a behavior-inert evidence PR.

A test passes only when its asserted behavior was executed. Code reading, green unrelated suites, event rows, cursor movement, process presence or a terminal notification to another session are not substitutes. If a healthy TUI cannot be established because #305 recurs, the canary is blocked and #280 is not declared operationally qualified; #305 itself is not repaired under this contract.

- Stop before implementation if exact Aether Project/board/repository identity, imported Hermes source, base commit, active preimage or overlapping local-patch ownership cannot be resolved without path/time/recency heuristics.
- Abort activation on any preimage hash drift, unclassified target-file hunk, mismatch between merged patch and candidate, missing backup, failed reverse/apply check or migration that cannot preserve/restore existing data.
- Any malformed/missing identity, ambiguous controller, mixed invalid obligation or cross-Project/flow/session adoption must fail closed; do not weaken fences to preserve liveness. If exact origin escalation cannot be produced safely, return contract revision rather than guessing.
- The behavior budget is one primary candidate and one focused rework for reviewer-found defects already inside these invariants. A second new behavior defect, another schema redesign, or any need to widen acceptance returns `revision` to Morfeo; do not silently add a third variant.
- A test that passes only by filtering invalid input, raising timeouts, polling externally, adding a watcher/daemon, delivering all blocked events, manufacturing owner input or using a stale/non-active checkout is invalid and stops that route.
- Do not activate before implementation PR merge or record future activation facts in it. The evidence PR must stop if it changes source behavior, patch bytes or functional tests.
- If #305 prevents establishing a healthy persistent TUI after one clean retry in isolated state, emit `recovery`, preserve all #280 work/evidence and stop operational qualification; do not absorb #305 into this objective.
- Stop on genuine protected-edge denial, credential/provider/model/spend requirement, upstream publication, package release/deployment need, force/bypass/history rewrite, destructive operation or unrelated cleanup.
- Required-check or reviewer failure caused by the objective receives one smallest in-scope correction and rerun. Unrelated infrastructure failure is recorded and retried only when clearly transient; gates are never weakened.
- #280 remains open if source is merely local, PR unmerged, runtime not activated, live same-session wake unobserved, duplicate writers remain possible, or any acceptance criterion lacks evidence.
