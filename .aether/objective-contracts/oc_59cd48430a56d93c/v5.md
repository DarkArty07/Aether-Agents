# Objective Contract: Eliminate silent affinity-flow stalls and wake the exact origin (#280)

## Owner Intent

Christopher explicitly selects option A and authorizes autonomous execution of version 5 solely to rebuild and independently approve the HLP-280 executable pre-behavior design gate. Every decision, schema, migration, state, transition, oracle, coverage result and review finding must be documented durably. Version 5 must not implement or activate production behavior. After a verified design approval, Morfeo may autonomously prepare the later implementation contract for the already-approved #280 objective; implementation still requires that new finalized contract and fresh isolated board.

## Objective

Rebuild the HLP-280 pre-behavior design package from the exact active Kanban and SessionDB schemas, then obtain independent approval that it is a total, executable, non-circular specification for a later implementation. The package must contain authoritative data definitions, complete typed state/transition semantics, exact SQL apply/rollback plans, a generated reachable-state model, an independent oracle, complete coverage evidence, real predecessor RED execution, concurrency/fault models, route/delivery/receipt protocol and isolation controls. The terminal result is DESIGN_APPROVED or DESIGN_REJECTED; no production behavior is written or activated.

## Decisions and Assumptions

1. Design-only boundary: v5 may edit specifications, executable SQL/migration plans, schemas, generators, oracle code and tests for those artifacts. It may not edit or package production Hermes behavior.
2. Behavioral authority: v4 Decisions 1-22 and AC1-AC28 remain the required semantics. v5 may make them executable and remove ambiguity but may not narrow owner wake, quarantine, terminal, replay, deadline, route or receipt guarantees.
3. Exact preimages: derive Kanban and SessionDB schemas from the actually imported Hermes source and disposable DBs created by that source. Record module path, commit, file hashes, sqlite_master DDL, PRAGMA table/index/foreign_key/user_version results and current upstream revision. Hand-written lookalike schemas are forbidden.
4. Separate migration artifacts: Kanban apply/rollback/reapply and SessionDB apply/rollback/reapply are distinct executable scripts/orchestrations. The whole-file apply must not run rollback. Each uses explicit transaction boundaries and final version bump; rollback restores byte-equivalent schema/data in disposable copies.
5. Generated model: one closed typed domain and explicit reachability predicates generate all reachable state vectors. No behavior may depend on case_id, category, label, red_mapping or expected output. Every generated input vector is unique and receives one typed decision/action/postcondition.
6. Independent oracle: classification is computed only from input state and v4 precedence. The oracle cannot import production helpers, matrix expected outputs or generator result logic. Mutation tests must prove wrong decisions, mutations, postconditions, keys, hidden axes and precedence fail.
7. Coverage: 100% generated reachable-vector coverage and 100% pairwise coverage across every declared orthogonal axis pair after documented pruning. Ordered histories cover all v1-v4/reviewer REDs, each key replay/conflict family, controller/terminal/quarantine paths, claim/receipt crash cuts, deadline races, concurrent writers and every planned statement/commit fault.
8. SQL authority: DDL and triggers must enforce every invariant that SQLite can enforce; remaining cross-table checks are listed as BEGIN IMMEDIATE validation obligations. Reviewer probes must cover illegal INSERT/UPDATE/DELETE in both directions. Ambiguous migration rows go to immutable raw quarantine; no provenance is guessed.
9. Interface manifest: exact enums, dataclasses/records, request/snapshot/result/envelope fields, function signatures, errors, transaction ownership, table ownership and kernel↔wake payloads are fixed before implementation units can be decomposed.
10. Isolation: all tests clear every outer task/run/board/DB/attachment/claim/branch/affinity/flow/session/tenant/Project marker, fail on access outside a temporary root, and guard the real board read-only with a before/after digest. No synthetic operational task or worker is allowed.
11. Review model: one Implementer authors the rebuilt package; an independent Supervisor cold-reviews exact artifacts and adds reviewer-owned probes. One artifact-only correction is permitted. Any remaining deterministic blocker yields DESIGN_REJECTED and origin_signal=revision; no second correction or automatic v6.
12. Terminal output: DESIGN_APPROVED includes exact commit graph, artifacts, schema/domain/vector/pair/history/RED/SQL/fault counts, commands/results, real-board digest, residual risk and explicit confirmation of zero production/runtime mutation. DESIGN_REJECTED includes reproducible blockers.
13. Telegram reporter remains temporary, change-only and outside correctness; it reports v5 milestones and is paused/removed at v5 terminal state.
14. Release conclusions for v5 are release_impact=none, release_action=defer, release_channel=none. A later implementation remains expected patch impact but is not authorized here.
15. Approved design does not itself authorize implementation. Morfeo may autonomously materialize a new finalized implementation contract from the approved package under the owner's standing #280 authorization.

## Acceptance Criteria

AC1. Captured Kanban and SessionDB schema snapshots are generated from the actual imported source and disposable databases; hashes, DDL, PRAGMA tables/indexes/FKs/user_version and upstream identity are reproducible. Reviewer byte-compares them to independent captures.
AC2. Kanban and SessionDB migrations are separate executable apply/rollback/reapply paths with explicit transaction boundaries and final version bump. Exact-preimage apply, reopen, integrity/FK checks, rollback and reapply all pass; apply never self-rolls back or creates SessionDB tables in Kanban.
AC3. Ambiguous/corrupt legacy rows are preserved byte-for-byte in immutable staging/quarantine evidence and never assigned guessed flow, root, controller, route or session identity. Migration emits no owner signal merely by opening a DB.
AC4. The JSON Schema closes every input/output enum and requires all behavior-relevant axes. Unknown/missing/extra axes, duplicate case IDs, duplicate state vectors, behavioral null/default, incompatible dimensions and invalid expected structures fail validation.
AC5. Generator enumerates the documented finite domain and applies explicit reviewable reachability predicates. Every reachable vector appears exactly once, every generated vector is reachable, generator output is deterministic and uncovered reachable vectors equal zero.
AC6. Pairwise report covers 100% of every declared orthogonal observed-domain axis pair after pruning; each excluded pair cites a reachability predicate. Ordered histories cover higher-order sequences pairwise cannot prove.
AC7. Oracle imports neither production helpers nor matrix/generator expected-output logic and never reads case_id/category/labels/red_mapping/expected values. It returns complete typed decision, action, mutations, postconditions, key/envelope and error from input state only.
AC8. Mutation tests prove that renamed IDs, wrong decisions/actions/mutations/postconditions/keys/routes, reordered precedence, hidden axes, unknown enums, duplicate vectors and a matrix whose expected outputs are all corrupted fail.
AC9. The model maps every v4 Decision 1-22 and AC1-AC28; machine-readable coverage has no missing decision, AC, axis, vector, history, SQL invariant, historical RED or fault point.
AC10. Exact interfaces contain no ellipses: enums, records/dataclasses, fields, function signatures, transaction ownership, tables, errors and kernel↔wake envelopes are sufficient for later non-overlapping workers to implement compatibly.
AC11. State model contains raw-validity sentinels and complete registry, membership, affinity, route authority/projection, task/run/liveness, controller, attention history, effect/quarantine, deadline, delivery claim, receipt and terminal state. Partial flow evidence never delegates legacy.
AC12. Run/liveness mapping covers current, alternate, multiple, ended, missing, dangling; LIVE/DEAD/UNKNOWN; explicit and every automatic exit. The exact pre-operation current run is required; UNKNOWN defers to expiry; faults roll back rather than inventing committed quarantine.
AC13. Attention/controller/terminal mapping covers empty, valid, resolved, duplicate, mixed, bad-FK and corrupt histories; all controller statuses/actions; bootstrap; scheduled promotion; success/failure all-run terminalization; terminal replay/reconcile and no reopen.
AC14. Every canonical key family—source exit, attention transition, expiry, terminal, bound quarantine and unbound quarantine—has exact replay plus hash/action/route conflicts and ordered repeat-after-new-run histories.
AC15. Route model includes full authority fields and route_id/revision projection. SQL/procedural probes reject open-flow route mutation/deletion, stale/extra/conflicting projections, root/controller retargeting, task-in-two-flows, state-version decrease, terminal/quarantine mutation, invalid FK/event/effect links and duplicate acked claim.
AC16. Delivery/receipt model covers immutable relevant-event filter, irrelevant skip, one-at-a-time task_events.id order, no-release claim, expiry/reclaim, ack loss, receipt absent/leased/prompted/completed/corrupt, stable turn ID, every crash cut and contiguous cursor.
AC17. Deadline model covers 300-second default, 120–3600 bounds, minimum two ticks, UTC integer clock, immutable per-flow value, persisted deadline_at, semantic progress, heartbeat exclusion, terminal/quarantine exclusion and expiry/controller-live race.
AC18. Historical test runner executes every attached/reported v1-v4/reviewer RED on its exact predecessor commit/patch and observes the expected RED, then executes the corresponding rebuilt-model expectation as GREEN.
AC19. Real SQLite multi-connection/process tests and deterministic triggers/barriers exercise each planned statement/commit failure and two-writer interleaving. Oracle verifies rollback or exactly one durable effect according to the design.
AC20. Isolation clears every inherited identity marker, pins fresh temp roots and fails any path escape. A read-only digest wraps the entire v5 test session; operational board tasks/runs/events/subscriptions are identical and no synthetic worker starts.
AC21. Independent Supervisor reproduces all commands, independently captures schemas, adds adversarial vectors/histories/SQL probes and verifies all counts. Worker summary is not evidence.
AC22. One artifact correction may address settled omissions. After rerun, any deterministic blocker, uncovered vector/pair/history, exact-schema failure, circular oracle or isolation mutation yields DESIGN_REJECTED and origin_signal=revision; no automatic second correction.

## Testing Standard

Testing is design-first and test-first. No production behavior source or portable runtime patch may be written in v5. The design package itself is executable and receives RED/GREEN review.

Environment: print imported module paths, exact source/upstream commits, file hashes and disposable DB roots. Clear all inherited Hermes/Kanban/session/flow/Project markers. Use one fresh temporary home/DB/workspace per case or process; deny access outside it. The real board is read-only only for a session-wide before/after digest.

Schema/migration: independently capture exact active Kanban and SessionDB schemas. Run each apply, reopen, PRAGMA foreign_key_check, integrity_check, illegal mutation probe, rollback and reapply on disposable exact copies. Inject failure after every planned write and before/after commit. Verify schema version changes only on full success and rollback restores expected bytes/schema/data.

Model: validate JSON Schema; generate the complete finite reachable domain; verify unique vectors, deterministic output, explicit pruning and zero uncovered reachable states. Require 100% pairwise coverage for every declared orthogonal pair and ordered histories for multi-step properties. Run an independent pure oracle and compare complete structured outputs.

Adversarial: mutate IDs, axes, enums, decision/action/mutation/postcondition/key/route results and precedence. Every mutation expected to invalidate the artifact must fail. Independently add vectors for partial flow evidence, all run/liveness combinations, controller/attention/terminal/quarantine states, six replay/conflict families, deadline races, delivery/receipt crash cuts and concurrent writers.

Historical: check out/reconstruct exact predecessor objects for v1-v4 and run each attached/reported counterexample as actual RED. Then prove the rebuilt model returns the contract-correct GREEN for the same semantic state. Labels or prose do not count.

Repository gates: focused design/oracle/migration tests; `git diff --check`; Ruff/static/schema checks; objective-contract, patch-reconciliation, lab-isolation and full Aether suites. Record exact counts and failures. No live model/provider is needed for deterministic design qualification.

Review: a different Supervisor cold-reads artifacts, reruns all commands on fresh copies, independently captures the active schemas, adds reviewer-owned probes and audits coverage reports. It may authorize one settled artifact-only correction and rerun once. Only an explicit DESIGN_APPROVED verdict satisfies v5.
