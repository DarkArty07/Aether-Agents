# Objective Contract: Corrigir arranque MCP da TUI y abrir Morfeo en nuevos proyectos tras git init explícito (#492)

## Owner Intent

The owner wants exactly four user actions for a new empty folder: enter it, explicitly run `git init`, run `aether init`, then run `aether` to converse with Morfeo. The owner must retain control over creating Git, but must not be asked to choose native Projects, boards, workers or initial-commit mechanics. Morfeo must first learn the project's intent, principles and testing standard through conversation, then autonomously carry out warranted preparation and choose direct work or the Supervisor/Implementer pipeline. Separately, permanently correct the observed rc8 TUI agent-initialization deadlock with MCP configured; removing Context7 from the local profile was only an operational workaround. The owner authorized this combined objective to proceed autonomously through Aether, not automatic release publication, installation cutover or credential changes.

## Objective

Deliver two observable product outcomes in one project-bound change: (1) installed Aether can initialize a manually created, commit-free Git root by binding only portable/native Project identity, then open project-bound Morfeo for as many intake conversations as necessary without a fabricated constitution or `AGENTS.md`; execution remains gated until owner-informed project governance and an actual objective exist; (2) observer-enabled Hermes starts with MCP configured without the plugin-lock/module-import cycle, retains native category/coverage semantics and processes an early first turn exactly once. Preserve existing brownfield initialization, exact project selection, release/runtime integrity, and unrelated local state. Source-only design and a disabled-MCP startup are not acceptance.

## Decisions and Assumptions

Decided by owner: human performs `git init`; init does not commit, choose a forge, invent governance or create a board; Morfeo owns subsequent technical coordination after learning intent. Decided in DESIGN.md PD-52 and A1 FR-043/046-052/100: init accepts an unborn exact Git root, uses the selected managed Morfeo profile's native Hermes Project at that exact primary path (create if absent, reuse one, refuse ambiguous/conflicting); only a finalized contract handoff provisions an execution board. An initialized, exactly registered Project without `AGENTS.md` can open/continue intake; arbitrary unregistered cwd cannot fall back to a sole other Project. Technical decision in A1 plan §4.6: manager remains Hermes-independent and uses the selected runtime's supported native CLI plus readback rather than SQL/native imports; partial failure is retry-safe, not destructive. OBS-D-032 selects Hermes's lightweight `tools.registry` accessor plus shared-metrics taxonomy instead of importing discovery-bearing `model_tools` during observer registration; missing native capability remains a coverage gap. Assumptions: the selected maintained runtime exposes that native create/lookup and registry interface (inspected in installed rc8 fork); verify against the exact candidate before release. Supervisor may assign independent units and decide equivalent local implementation details, but cannot change shared identity, authority, or observability semantics.

AC5 — Focused and full project gates pass against the exact candidate; source/docs/package no private runtime data; user-facing docs state installed behavior only when qualified.
