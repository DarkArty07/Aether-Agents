# Objective Contract: Adopt Hermes-owned gateway service and finish Aether rc5

## Owner Intent

Apply the owner-selected option B for #487: Hermes owns the complete Morfeo gateway service definition and native refresh behavior; Aether owns the release-bound TUI asset and every TUI-launch surface. Remove the false service/TUI coupling, restore doctor readiness, preserve the now-working one-command `aether` launcher and finish the outstanding launcher/Graphify closeout autonomously.

## Objective

Produce, independently review, merge and locally activate `1.0.0rc5` as a compatible corrective candidate. Aether must stop generating or byte-owning `hermes-gateway-morfeo.service`; after selecting a release it must ask that exact runtime's supported Hermes CLI to install/refresh the main user service through the stable selector, then validate only Aether-dependent service invariants. TUI launchers must continue to export the hash-bound release TUI, repeated Hermes service refreshes must leave doctor ready, and the final live closeout must account for #480, #481, #482, #485 and #487.

## Decisions and Assumptions

Decided by the owner: option B. The gateway is not a TUI consumer; `HERMES_TUI_DIR` is therefore a launcher invariant, not a service invariant. Hermes owns the full main unit and may rewrite it through `systemd_unit_is_current` / `refresh_systemd_unit_if_needed`. Aether owns `~/.local/bin/aether`, Desktop/WSL launch actions, the release TUI bytes/digest/provenance and exact project/profile binding.

Material design:
- Candidate identity is package `1.0.0rc5`, display/tag `1.0.0-rc.5` / local annotated `v1.0.0-rc.5`; maintained fork remains exact `aed6591a69f453a1867b73628603e7b53ba40ffc` unless implementation proves a fork change unavoidable and returns for design revision.
- `release_impact=patch`, `release_action=prepare`, `release_channel=prerelease`. No public tag/release/package is implied.
- For rc5-and-newer release projection, Aether does not write the main unit or include its exact bytes in Aether projection digests. It may snapshot the prior opaque unit solely for transactional rollback on a failed transition; that is recovery, not content ownership.
- After the selector points to the target release, Aether invokes the stable selector's exact Hermes command noninteractively for the Morfeo profile, equivalent to `hermes --profile morfeo gateway install --force --no-start-now --start-on-login`, using isolated Python/uv/pip environment and exact `HERMES_HOME`. Hermes creates/refreshes its own main unit. Aether then daemon-reloads/restarts only that unit through its existing controller. An equivalent supported Hermes command shape is local implementation freedom if it preserves these semantics and is directly tested.
- Doctor validates the service exists as a regular user unit and semantically selects `runtime/current`, Morfeo, the exact Morfeo home/working directory and active virtualenv, with no conflicting duplicate selector lines; it checks service availability/health separately. It neither requires nor rejects `HERMES_TUI_DIR` in the gateway unit and does not compare Hermes-owned incidental Description/PATH/cleanup/watchdog bytes.
- Fresh setup must create the service through Hermes ownership. Update and explicit rollback must refresh it for the selected release. Normal Aether uninstall must request removal through the selected Hermes CLI rather than unlinking the file itself. Transition failure restores the previous selector, Aether-owned projections and opaque prior unit before returning failure.
- Rollback qualification targets restored coherent rc3, not known-defective rc4, then forward-reactivates rc5. Mutable state always moves forward.
- No drop-in is created; no maintained-fork patch is planned; no runtime-only edit is accepted.

Assumptions supported by current evidence: the stable rc4 launcher already exports the release TUI and works; the running TUI has exact project/profile/TUI bindings; Hermes' native user-unit generator already selects stable `runtime/current`; the active mismatch is only ownership/oracle drift. Supervisor may choose private helper/function structure and test fixtures but may not change these ownership or release decisions.
