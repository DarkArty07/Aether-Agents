# Objective Contract: Limpieza verificada de código muerto y consolidación de deuda de implementación

## Owner Intent

El owner solicita limpiar únicamente el código muerto o duplicado ya verificado, tratar las demás observaciones confirmadas de los auditores sin completar todavía las capacidades inconclusas, y dejar un informe durable que permita decidir después cuáles implementaciones pendientes siguen siendo necesarias y cómo terminarlas. Ningún archivo o capacidad debe retirarse por mera ausencia de callers cuando sea scaffolding, capability wall, compatibilidad o trabajo congelado por fase.

## Objective

Entregar un repositorio coherente y verificable en el que: (1) se retire sólo el código muerto/duplicado de alta confianza; (2) se corrijan observaciones verificadas que sean defectos o residuos de migración y no requieran redefinir producto; (3) se conserven intactas las implementaciones incompletas, capability walls y scaffolding hasta decisión posterior del owner; y (4) quede un informe canónico que clasifique cada capacidad inconclusa, su función actual, la frontera faltante, dependencias, riesgos y decisiones pendientes.

## Decisions and Assumptions

Owner decisions accepted on 2026-08-29: (1) remove only the four high-confidence dead/duplicate implementations: `observation.reduce.review.apply_since` plus private helpers used only by it, `lab.validation.validate_scenario`, `lab.resources.schema_resource`, and `_Observer._run_id`; (2) repair now the E2E-15 false-PASS/rolling-score defect, stale CI tracked-file manifest, divergent `project.schema.json` validation, the laboratory `projects/projects` registry-root defect, and mutation before `update/rollback --dry-run`; (3) leave prerelease selection, `doctor --project`, setup/service/export and all other unfinished capabilities documented but unimplemented; (4) create tracked root report `INCOMPLETE_IMPLEMENTATIONS.md`; (5) preserve and track the owner-authored `INTEGRATIONS.md` in the same change and reconcile it into CI inventory; (6) require focused tests, the complete non-live Python suite, CI-manifest validation, `git diff --check`, and independent final-diff review. Route remains Supervisor→Implementer because shared cleanup, qualification, lifecycle and documentation changes require decomposition and integration review.

## Testing Standard

Testing is mandatory and follows RED→GREEN for each behavioral defect. Focused tests must cover observation diff/export cleanup, laboratory validation/resources, observer hook cleanup, E2E-15 qualification and rolling-score exclusion, lifecycle dry-run non-mutation, Project marker schema parity/registry path, public artifacts and policy inventory. After focused tests, run `uv run pytest -q` as the complete Python suite without any `--live`, provider/model-spend acknowledgement, service activation or external-effect lane; existing environment-gated skips must be reported, not hidden. Execute the CI tracked-file-manifest check against `git ls-files`, public-artifact/privacy tests for both root reports, and `git diff --check`. An independent reviewer must inspect the final diff and test evidence for compatibility, privacy, authority and qualification regressions before integration is accepted.

## Stop Conditions

Stop and return to the owner without expanding scope if: a candidate removal has any unresolved production, plugin, dynamic-entrypoint, compatibility or public-API consumer; a selected defect cannot be repaired without completing/redefining an unfinished capability; E2E-15 requires choosing a new wake policy; Project validation requires changing `project.schema.json`; CI inventory would require removing intentional compatibility links; `INTEGRATIONS.md` would need content changes; tests require live models, credentials, network publication, service restart or modification of `home/`/the live Hermes checkout; an edge guard denies a genuine protected effect; unrelated dirty tracked changes appear; or focused/full verification cannot complete honestly. Preserve evidence and report the blocker rather than substituting a weaker test or broader cleanup.
