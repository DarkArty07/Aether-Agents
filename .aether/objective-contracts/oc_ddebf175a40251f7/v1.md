# Objective Contract: Autonomous Aether bug remediation queue: reliability, safety and runtime correctness

## Owner Intent

Christopher authorized Morfeo to autonomously remediate the currently open Aether Agents bug backlog, beginning with the highest-impact bugs and continuing through several repair waves without requiring repeated owner messages. The autonomous run must make pragmatic decisions consistent with Aether's constitution and current design, provide truthful milestone progress through the owner's already configured Telegram destination, and stop only for a genuine contract defect, protected boundary, missing authority or unresolved material ambiguity. Telegram progress is an operational delivery concern; no private destination identifier belongs in this public contract.

The objective is maintenance of the existing Aether product, not a redesign. The owner expects real fixes or honest evidence-backed dispositions, not plans, stubs, retry-only green results or claims based on worker heartbeats.

## Objective

At intake, remediate these 18 open bug issues in DarkArty07/Aether-Agents, in pragmatic risk order:

P0 — safety, authority and autonomous-flow integrity: #364, #343, #362.
P1 — protected-workflow continuity and reproducibility: #315, #298, #323, #284.
P2 — trustworthy project analysis and user-facing runtime compatibility: #346, #306, #293, #296, #303, #275.
P3 — CI and baseline reliability after causal reproduction: #360, #357, #352, #349, #329.

The complete objective is one autonomous queue. Supervisor may run sufficiently independent units in parallel and may reorder within a priority wave when evidence or file ownership requires it, but may not turn the queue into unrelated direct changes or skip a higher-risk blocker without recording the reason. Each issue receives an explicit result: reproduced and fixed, already working with integrated evidence, or an honest unresolved/not-reproduced disposition when the issue and evidence support that outcome. A failed or unexecuted check is never reported as success.

The queue is anchored by the intake tracking issue #366 and the individual issues above. Newly created bugs after contract finalization are outside this contract and need a later objective. The objective spans only the Aether-Agents repository and, where the defect is in the already selected maintained Hermes runtime, its already provisioned DarkArty07/aether-hermes repository; source and branch identity must be resolved at execution time.

## Decisions and Assumptions

1. The complete owner objective is routed through Supervisor because it spans multiple repositories/responsibilities, needs independent review and convergence, and benefits from bounded parallel implementation. Morfeo authors this single contract and no implementation units.
2. Priority is risk-based: safety/authority/evidence integrity before continuity/reproducibility, then user-facing integrations, then CI flakiness. Supervisor may reorder only with a durable rationale.
3. Preserve the existing three-role Aether topology and native Hermes Projects/boards/worktrees/review/lifecycle. Do not add a queue, state machine, orchestration framework, new provider, new protocol or permanent role responsibility.
4. Look upstream first for Hermes defects and resolve the actual source loaded at investigation time. The selected public Hermes baseline is the repository's accepted v2026.8.18 / 0.20.4 baseline; the maintained fork is evidence and implementation target only where the defect belongs there. Do not upgrade a moving dependency merely because it changed upstream.
5. Use the current project checkout's verified integrated head as the Aether base; intake observed clean HEAD e9379c4712509c01f133745faaf810857b9a33a8 on branch docs/runtime-reliability-six-bugs. Supervisor must re-check the actual Project/worktree base before decomposition and block on a material mismatch rather than assuming origin/main or a homonymous checkout.
6. Existing repository guidance and R0 constitution remain authoritative. No Project Canonical Skills directory was present at intake. project_knowledge/work_memory could not bind in the native Morfeo session (VIEW_MISMATCH: workspace was not a reachable Git checkout); source inspection is the recorded fallback, not a fabricated graph or memory result.
7. Fix the demonstrated root cause with the smallest compatible change. Tests-only evidence is valid for already-working qualification; not-reproduced evidence is valid only where the issue's stated disposition allows it. Do not hide failures with retries, broaden a match from evidence-free guesses, or repair unrelated defects merely because they appear nearby.
8. Progress messages must be concise Spanish milestone updates based only on durable board/test/PR evidence, without secrets, private paths, invented percentages or heartbeat-only claims. Internal execution continues if Telegram delivery is temporarily unavailable; the failure is recorded.
9. Aggregate release conclusions remain independent: release_impact=patch only when compatibility evidence supports it (otherwise none), release_action=defer, release_channel=none. No activation or publication follows from a fix.

## Testing Standard

The testing standard for this autonomous queue is evidence-first and project-compatible:

- Before each repair, record the exact Aether/fork source path actually imported, commit/base, Python/runtime version and clean-enough tree. Run the same new regression/control tests against unchanged baseline and candidate with identical already-provisioned dependencies. Never use a pass-on-retry as deterministic proof.
- Aether tests use the canonical `uv run --frozen python scripts/run_tests.py` wrapper; affected tests first, then the full required suite and existing documentation/policy/static/build gates. Run `git diff --check` and the documented Ruff checks on touched Python. Do not call an alternative test runner merely to avoid repository behavior.
- Maintained-fork tests use its documented `scripts/run_tests.sh` runner with file retries disabled for RED/GREEN attribution; affected tests first, then the affected agent/run-agent suites and required local gates. Inherited fork Actions remain disabled/not-run if that is the standing repository state.
- Boundary-sensitive tests use isolated temporary state and real imports/processes/SQLite/loopback HTTP where applicable. Use sterile outer environments for laboratory probes; no live board, profile, model, provider, credential, production database or external messaging endpoint is a test fixture. Deterministic synthetic credentials and HTTP replies must be visibly fixtures.
- For policy/credential/authority fixes, test both the safe positive and the fail-closed negative. For provider/runtime fixes, test actual request/response shape, destination and attribution/auth separation. For concurrency/flaky CI issues, use controlled events/barriers rather than sleep-based ordering and distinguish product cause from baseline/environment cause.
- Required GitHub checks, review, merge and post-merge state are part of closeout. A local pass, open PR, heartbeat or green rerun is not sufficient.

## Stop Conditions

Stop or escalate the affected issue/unit when:

- the actual source, Project, repository, branch or base cannot be verified, the contract digest/project binding mismatches, or a worktree would mix unrelated/pre-existing changes;
- reproduction reveals a different material cause, a missing product/design decision, a new public API/protocol, a new provider/routing mechanism, or a required edit to live home/ state rather than a permitted tracked source;
- a test or design requires real credentials, paid/live model traffic, production/live board/database access, settings changes, deployment, activation, publication, destructive cleanup or a protected external effect;
- a cross-destination request cannot safely separate attribution from authentication, a shared-file collision changes unit design, or an upstream change is needed beyond a narrow demonstrated compatibility repair;
- a genuine protected-edge denial occurs. An unexpected denial of ordinary local/reversible work is recorded as an Aether runtime regression and is not bypassed;
- a required check fails for an unrelated/pre-existing reason: preserve the failure and continue independent units only when safe, but do not close the affected issue or declare aggregate success;
- a scoped bug cannot be reproduced on the verified baseline and its issue does not allow a not-reproduced outcome. Leave it open with evidence and return the material decision instead of inventing a fix.

Do not cancel a live worker because it is slow; distinguish liveness from durable progress. Telegram delivery failure does not stop source work, but it must be recorded and must not be replaced with invented progress. Stop the whole queue only for a contract/project/authority defect affecting all remaining units or an explicit owner change.
