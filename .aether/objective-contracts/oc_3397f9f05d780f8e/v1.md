# Objective Contract: Aether 1.0.0-rc.1: coherent local update, immutable maintained-fork runtime and GitHub prerelease (#261)

## Owner Intent

The owner authorizes Aether to complete the release/runtime objective tracked by GitHub issue #261, make the separated installation a supported `aether update` lifecycle, promote Aether and its maintained Hermes fork without patching the live tree in place, activate the resulting runtime locally even though activation interrupts current Aether agent instances, and publish a prerelease near 1.0.0. The owner will reopen interrupted instances and does not require drain/wait semantics. The executable Hermes source is `DarkArty07/aether-hermes` branch `aether-main`; portable `patches/hermes/*.patch` remain evidence/reconstruction rather than the live deployment input. Local promotion from clean commits is required. Morfeo selects `v1.0.0-rc.1` (`1.0.0rc1`) because the current release workflow supports RC syntax and the owner states the product is close to 1.0.0. This objective is autonomous through implementation, independent review, integration, GitHub prerelease publication, local activation, verification, rollback proof, and objective-owned cleanup within provisioned access.

## Objective

Deliver and prove one coherent Aether `1.0.0rc1` release candidate that replaces today's manually copied/dirty runtime with a versioned, immutable, reproducible runtime built from exact clean Aether and maintained-fork commits. Reconcile the product lifecycle and release-lock model with the accepted maintained-fork policy and the post-separation XDG layout; make `aether update` the sole supported promotion/activation boundary for both local candidates and locked release artifacts; preserve external mutable state across update and rollback; close objective-caused release blockers; publish the exact accepted Aether artifacts as GitHub prerelease `v1.0.0-rc.1`; activate those same accepted bytes locally; and prove TUI, gateway, plugins, Graphify, Projects, doctor, update and rollback resolve one release identity. This RC is a qualified pre-stable milestone, not acceptance of stable 1.0.0 or all final-release gates in #261.

## Decisions and Assumptions

DECIDED — Release identity: Aether package version `1.0.0rc1`, annotated tag/GitHub prerelease `v1.0.0-rc.1`; `release_impact=major`, `release_action=publish`, `release_channel=prerelease`. The existing workflow's RC mapping and the owner's near-1.0 intent support this choice. DECIDED — Maintained fork: `DarkArty07/aether-hermes:aether-main` is executable Hermes source. Hermes retains its own distribution/version identity (`hermes-agent` 0.20.1 unless an independently required packaging correction is accepted); Aether binds it by repository, exact commit, source-tree digest, artifacts and provenance. `.patch` files and HLP records are audit/reconstruction evidence and may never be blindly replayed onto `runtime/current`. DECIDED — Layout: immutable releases/components stay under the Aether XDG data root; the current operational Hermes homes and all mutable sessions, boards, credentials, memories, observations, monitor and knowledge state remain under the established Aether XDG state root. The lifecycle must reconcile to this installed layout rather than move/copy the live state again. DECIDED — Authority selector: one authenticated active release record is authoritative; `runtime/current`, launcher, Desktop and service projections must agree with it after one transition. DECIDED — Local updates: a supported `aether update --local` mode prepares from explicit, verified clean Aether and maintained-fork commits. Exact option details for a non-guessing private checkout binding are locally delegable, but cwd/recency, dirty trees and mutable branch tips are not accepted identities. DECIDED — Activation interruption: activation may stop/restart Aether-owned TUI, gateway and workers immediately; it does not wait for drain. The durable state must remain recoverable when the owner reopens instances. It must not stop unrelated Hermes/services. DECIDED — Publication: GitHub prerelease plus exact wheel/sdist/runtime-source-or-equivalent artifacts, release lock, provenance and checksums using existing credentials. No PyPI/OIDC setup, new GitHub Environment, stable tag, arbitrary settings mutation or new credential is inferred. DECIDED — Service: future starts use the stable active selector; update verifies restart and effective release. DECIDED — Update and rollback change code/runtime only, never roll user state backward. ASSUMED — current local Aether dirty launcher changes are valuable migration evidence and must be preserved/reconciled, not discarded; current maintained-fork local commits are candidate source but receive normal review/remote integration. ASSUMED — Linux native is the available RC platform; WSL2 remains a named unverified stable-release gate. LOCAL FREEDOM — internal staging names, private metadata representation and helper decomposition are implementation choices if atomicity, exact identity, preservation and public CLI behavior remain satisfied.
