# Objective Contract: Expose bounded curated Contract Observation to Morfeo (#195)

## Owner Intent

Christopher quiere terminar la observación sin entregar a Morfeo logs, eventos, salidas, diffs, prompts ni datos crudos que llenen contexto. La telemetría existente debe producir información curada mediante una sola herramienta con vistas status, changes y diagnose. Debe quedar activa en runtime.

## Objective

Implementar y activar una herramienta estructurada `aether_observe` disponible sólo para Morfeo. Debe resolver un trace de Contract Observation, cargar su summary validado y devolver una proyección compacta, determinista y privacy-safe mediante las acciones `status`, `changes` y `diagnose`.

## Decisions and Assumptions

Decisiones: una herramienta, no tres; acciones `status|changes|diagnose`; toolset `aether_observation`; registro y handler restringidos a profile `morfeo` con setting explícito. Reutilizar `query.py`, summaries validados y `diff_summaries`; no capturar fuentes nuevas inicialmente. `unknown` es respuesta válida y nunca se infiere porcentaje. Supuesto: los campos normativos actuales bastan para #195; un dato ausente queda como coverage gap.

## In Scope

Crear proyección pura `aether.observation.brief.v1`; registrar tool condicional; inputs: `action`, `ref` opcional, `project` opcional y `since_summary_id` sólo para changes. `status` expone IDs, as_of, completion_state, seis ejes runtime, conteos work_graph y last_verified_progress_at. `changes` expone sólo comparación y change_classes. `diagnose` expone review_brief, coverage reason codes, bottleneck/defect codes y refs opacas, con listas acotadas.

## Out of Scope

Fuera: nueva plataforma de telemetría; nuevos hooks/eventos/checkpoints; dashboard; streaming o polling automático; logs/eventos/payloads crudos; prompts, respuestas, comandos, outputs, diffs o reasoning; porcentajes; recomendaciones automáticas; cambios de control Kanban; #220 CI protegido; #211; #242/#244/#240; publicación o push.

## Authority

Supervisor puede descomponer, revisar e integrar cambios locales reversibles. Implementer puede modificar worktrees aislados y pruebas. Activación: instalar bytes/config Aether en el runtime ya provisionado y probar procesos nuevos. Sin push, publish, deploy, credenciales, gasto nuevo, reinicio de servicios, cambios a Hermes core, schema de summaries v1 ni fuente autoritativa. Un reinicio requerido se devuelve a Christopher.

## Deliverables

Entregables: proyección curada y schema; tool `aether_observe`; config empaquetada Morfeo y runtime instalada; cero tool en Supervisor/Implementer; pruebas de mapping, role gate, privacy, bounded output, empty/unknown, changes y diagnose; prueba con PluginManager real; una invocación funcional desde proceso Morfeo nuevo sobre trace real; documentación breve e issue #195 actualizado/cerrado si acepta.

## Acceptance Criteria

Aceptación: status/changes serializados <=2048 bytes y diagnose <=4096; arrays diagnose máximo 5 por clase y sólo códigos/refs opacas. Nunca claves raw/log/output/prompt/response/command/diff/reasoning ni texto capturado. Ref ausente resuelve sólo un trace abierto; múltiple es error, cero es empty. Project exige marker válido explícito o del cwd. Summary validado requerido. Herramienta visible y usable sólo en Morfeo. Proceso nuevo devuelve JSON válido en las tres acciones sobre trace real sin mutar Kanban/sesiones.

## Testing Standard

Estándar de prueba resuelto por delegación técnica y requisito runtime del propietario: TDD para proyección y handler; unit tests exactos de cada campo/enums, errores y caps; adversarial privacy con payloads prohibidos; PluginManager/PluginContext real para exposición por rol; suites observation/plugin/packaging afectadas; wheel candidato; instalación en runtime Aether; proceso Morfeo nuevo que carga y ejecuta el tool contra fixture/trace real. Mock-only no acepta. Reinicio sólo si el proceso nuevo no basta y requiere autorización.

## Stop Conditions

Detener/bloquear si requiere nuevo dato no presente en summary, cambiar schema v1/captura, leer logs/eventos crudos, introducir modelo/red, inferir progreso sin evidencia, exponer tool a otros roles, superar caps sin schema válido, mutar autoridad, tocar Hermes core, conflicto Project/trace, credencial/gasto, o reinicio. Primer bug distinto: issue con reproducción y retorno a Morfeo; no rodeo. Output truncado nunca se acepta.
