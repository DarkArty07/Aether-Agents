# Authority

| Decision or effect | Authority |
|---|---|
| Product goal, priorities and material compromise | user/product owner |
| Intent interpretation, task contract, routing and synthesis | Hermes |
| Direct implementation inside an authorized local scope | Hermes |
| Project admission and typed operation validation | Aether MCP |
| Run/Task/Dispatch mechanics and owned resources | qualified provider |
| Specialist judgment | admitted profile inside its Task contract |
| Semantic acceptance proposal | Hermes from evidence |
| Final product acceptance | user/product owner |
| Push, release, activation, deployment, credentials or spending | explicit corresponding authority |

Tool availability, a profile file, a prior release, a test fixture or a provider response cannot expand authority. When identities or authority conflict, stop and resolve the conflict instead of guessing.

The current user instruction overrides standing repository workflow. In particular, this consolidation authorizes local source/filesystem changes and retirement of obsolete artifacts, but not push, publication or live provider mutation.
