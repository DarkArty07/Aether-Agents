## Outcome

M2.2 implements a provider-independent protocol package containing:

- deterministic canonical UTF-8 request encoding and SHA-256 identity;
- strict bounded request validation;
- immutable schemas for the exact 24-tool v1alpha1 surface;
- operation identity and exact idempotent-replay comparison;
- seven effect classes and bounded result/error envelopes;
- all 50 stable error codes from the canonical contract;
- static public error text that cannot include caller/provider values or tracebacks;
- one deterministic generated schema bundle.

The 24 schemas are exported but none is registered as callable in M2.2. This is
intentional: project admission and read-only provider projections belong to
M2.3/M2.6, while lifecycle, worker, learning and retention behavior belong to
later milestones. Registering stubs would make unimplemented behavior appear
available. The stdio server therefore remains default-off with exactly zero tools.

## Bounds and fail-closed behavior

- maximum canonical request: 65,536 bytes;
- maximum cursor: 1,024 UTF-8 bytes;
- maximum generic string: 8,192 UTF-8 bytes;
- maximum generic array/object members: 256;
- maximum nesting depth: 16;
- UUIDs must use canonical lower-case hyphenated form;
- digests must be 64 lower-case hexadecimal characters;
- floats, NaN and infinity are rejected;
- caller-asserted principal fields are rejected at every nesting level;
- unknown request fields are rejected where schemas are strict;
- dynamic Orca input accepts structured `command_id` and `arguments`, never a
  shell, argv, interpolation or arbitrary command string.
