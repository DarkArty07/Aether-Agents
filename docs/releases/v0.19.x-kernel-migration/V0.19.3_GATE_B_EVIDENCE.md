## Scope delivered

- Trusted v0.19.2 evidence is required before `close.requested`.
- `close.requested` projects only `CLEANUP_PENDING`.
- Cleanup is intent-before-effect and crosses only `OlympusRuntimeAdapter.cleanup_kernel()` into `ACPManager.cleanup_persisted()`.
- ACPManager returns inspected, project/session-bound survivor postconditions for the logical session, ACP mapping, prompt task, and PID/session mapping.
- A verifier-owned `cleanup.receipt.recorded` is bound to the exact run, task, attempt, contract generation, revocation epoch, dispatch message, logical/ACP session, evidence receipt, cleanup command, closure proposal, lease identity, and cleanup outcome.
- The dispatch lease is released only when owner, epoch, token and live identity match. A replacement lease blocks closure and survives.
- `task.closed` is accepted only after a valid zero-survivor cleanup receipt.
- Known cleanup failure projects `CLOSE_FAILED`.
- Ambiguous cleanup projects `RECONCILIATION_REQUIRED`; it never retries automatically and never projects `CLOSED`.
- Exact replay, restart after durable intent, crash between cleanup receipt and terminal event, competing cleanup consumers, and two independent SQLite finalizers converge without duplicate terminal success.

## Behavioral RED evidence

The implementation was driven in atomic increments. Observed RED failures included missing `request_close`, missing cleanup coordinator/outcomes, missing guarded lease release/finalizer/proof, forged receipt acceptance, and replacement-lease assumptions. The final negative matrix proves missing/stale/forged evidence, stale authority, mismatched sessions, malformed proof, direct completion, reordered/missing receipt, newer lease, failed cleanup and unknown cleanup cannot become `CLOSED`.
