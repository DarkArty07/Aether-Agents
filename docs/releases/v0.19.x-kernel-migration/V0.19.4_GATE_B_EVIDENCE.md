## 1. Scope proven

The deterministic path now supports one caller-fixed two-task contract:

```text
harmonia start with fixed A/B topology
  -> one immutable ExecutionContract
  -> A bound to worker A
  -> B bound to worker B
  -> only A admitted/staged initially
  -> verifier-owned A evidence receipt
  -> immutable canonical handoff snapshot
  -> atomic receipt + B release
  -> ACPManager-owned cleanup
  -> A CLOSED only after zero-survivor receipt
  -> kernel stages B from the exact snapshot
```

Harmonia submits and exposes the fixed topology. It does not choose B, infer a worker, inspect result contents, relay between agents or call ACP for the successor.

## 3. Authority and non-selection evidence

- One `ExecutionContract` owns both exact `task_worker_bindings`.
- Both workers must be explicitly named, distinct, discovered and contract-authorized before durable run creation.
- A has no prerequisite; B has exactly A as its sole prerequisite.
- Registry order, model capability, runtime availability and Harmonia judgment cannot select a worker or task.
- `KernelDispatcher.stage_successor()` derives B and its worker from persisted task topology and contract bindings.
- `ACPManager` remains the lifecycle authority for sessions, mappings, leases and process cleanup.
- `failed` and `unknown` cleanup states never release B.
- Public status exposes task IDs, states, prerequisites and worker bindings only; it omits result bodies, snapshot contents, lease tokens and cleanup internals.

## 4. Fail-closed and recovery matrix

The deterministic tests cover:

- malformed, extra and duplicate tasks;
- duplicate, unknown and restricted workers;
- omitted permissions and malformed prerequisite edge;
- exact request replay and conflicting request mutation;
- missing/foreign task binding and caller worker override rejection;
- snapshot conflict, source mutation, tamper, missing file and symlinked parent;
- receipt/release/snapshot identity mismatch;
- A not closed, cleanup failed and cleanup unknown;
- stale contract generation, epoch, attempt, receipt and lease identity;
- crash after B attempt creation but before `dispatch.staged`;
- same-process replay, runtime-registry restart and two independent SQLite consumers;
- one active B attempt, one durable B staged event and one outbox obligation.
