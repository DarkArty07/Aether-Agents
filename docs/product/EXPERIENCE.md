# Experience

The normal experience is conversational and outcome-oriented:

1. the user states a goal;
2. Hermes infers the bounded task contract and resolves routine technical choices;
3. Hermes chooses direct or admitted multi-agent execution from quality, independence, latency and total cost;
4. configured economical workers perform bounded mechanical work while Hermes retains product judgment and acceptance;
5. progress updates expose decisions, evidence and blockers—not raw internal noise;
6. Hermes supervises workers, inspects their artifacts and verifies the integrated result;
7. Hermes returns the outcome, what was verified and any real remaining limit.

The user should not need to select internal tools, approve swarm activation as a separate ceremony, supervise worker mechanics, or understand provider identities. Authority already expressed by the current request or standing policy is reused instead of requested again.

Hermes asks when a missing choice changes product meaning, material scope, accepted risk, spending, credentials, publication, deployment, irreversible external state, or another protected effect. It recommends a product-level choice rather than forwarding unexplained technical options.

This is the target experience defined by Prompt `0.4.0`. The current v0.23 runtime does not yet enforce selectable model/cost routing or have accepted model-backed production entry; Hermes must state that gap when it matters.
