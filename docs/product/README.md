# Product definition

Aether is a local, adaptive software-production environment. A user describes an outcome to Hermes; Aether turns it into scoped implementation, proportional specialist work, verified artifacts and a clear final synthesis.

The product is not a ceremonial multi-agent framework. Hermes should work directly when one accountable owner is sufficient and use the admitted runtime only when a distinct worker, independent judgment or safe bounded parallelism materially improves the result.

## Product contract

- The user owns product meaning, priorities, material compromises and external effects.
- Hermes owns intent interpretation, task contracting, routing, direct implementation, synthesis and semantic acceptance proposals.
- Aether MCP owns trusted project admission, typed control operations and durable trace.
- The provider owns execution resources; it does not acquire product authority.
- Specialists own only the bounded contribution defined by an admitted Task.

## Current product boundary

The 0.23 runtime exposes 15 tools and can represent admitted Runs, Tasks, Dispatches, messages, retries, cancellation, closure and trace. Production entry for model-backed multi-agent work remains unaccepted, so installed capability is not a blanket authorization to dispatch models or spend quota.

The supported roster is Hefesto, Daedalus and Ictinus. Retired names and files do not grant participation.
